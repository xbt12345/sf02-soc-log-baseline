## 1. 第一性原理：要优化的不是一个总分

目标按顺序是：

1. 从预测时实际可得、语义未被破坏的事实识别威胁，不能靠采集头、脱敏方式或上游意见假装掌握攻击规律。
2. 同时完成赛事三分类与风险报警。三分类报告 Macro-F1、逐类 P/R/F1；报警报告正常误报、两类威胁检出及人工复核负荷，两套决策分别计分。
3. 在已知不同来源和被完整留出的来源/模板上解释结果，不能让大量容易正常样本掩盖局部失败。
4. 前三项不被削弱的条件下减少数据传输、重复向量化与人工操作。

优先排除信息泄漏、确定的信息损坏和局部灾难性错误，再比较完整支持范围内的检出、分类和成本。没有业务损失权重时，不编造一个加权总分掩盖冲突。FPR=0.001 继续作为工程比较预算，另看 0.0001/0.01；它不是主办方评分公式，也不是已承诺的部署指标。三分类高分不能抵消报警失败，关掉报警或全部交给人工也不算解决。

“最佳”指在可信评价和已声明范围内得到最有依据的方案，不承诺全局最优或任意新环境的正确概率。全部官方训练数据及已用官方验证答案仍是已见材料；重划分不产生新的盲测。

## 3. 阶段 A：先修真实输入，成本低但不能省

### 3.1 ASA：按字段边界剥离采集头，保护事件事实

从原始记录确定 ASA 格式、头部和动作正文的边界；只剥离已确认的采集时间、采集器包装和无意义缺失槽位。保护可见事件码、严重度/结果字段的实际角色、动作、协议、接口方向、端口、ICMP 类型/码和 ACL 正文。不能全局删除 time/entity，也不能根据一行中首次出现 deny 就无条件截断。

现有四种头部表示是回归样例，不是四条硬编码模板的全部支持范围。增加头部字段顺序、日期表示、可选采集器、正文含时间或 deny 引文等反例；未知边界保留原文与诊断状态，不猜测其语义。

对 112,807 条 ASA 全量检查受影响范围、原文区间、被删字段和保留正文；将原来会翻转的真实样例加入固定反例。修复后的文本、向量及最终冻结模型应在可信头部变换下保持一致。不能把“不同语义必然翻转类别”作为要求。

### 3.2 Duo：既防上游捷径，又防损坏事实

先检查全部 337 条记录。已确认风险包括：

- adaptive_trust_assessments、trust_level、模型/特征版本等上游评估及实现元数据进入了当前主文本。
- 用户、设备、应用标识和事务标识在未知 JSON 包装中可能残留；按父路径和完整值处理，不能全局清理同名词。
- 正常 result 已被官方替换为 ORG-0893。必须保持“未知”，禁止恢复成 success、正常或任何猜测值。
- denied、no_response、invalid_passcode 等可见认证结果/原因需确认字段路径及生成时点，保留真实可观察事实；认证失败不自动等于恶意/可疑标签。

对可确认的对象边界进行字段级处理，主视图隔离上游判断及身份值，另存受限诊断视图。不盲目修复损坏 JSON 的引号、转义或缺失数字；无法可靠分离的片段标明范围，不将整行删掉或强制判正常。

缺失模式专项诊断：屏蔽 result 字段前后的差异只能称为“带信息损失的消融”；替换同一身份标记的编号才可作为保持身份角色的变换。不能把未知 result 改成 success 来制造语义保持样本，也不能把 denied→suspicious 写成规则。

这一步允许同时修复两处已经证实的输入问题；不宣称新旧总分差能被因果归因到其中某一项。如果需要逐项归因，另在同一新划分登记旧/新表示对照。

### 3.3 四类强线索的检查范围

| 线索 | 本轮明确检查 | 边界 |
|---|---|---|
| 时间 | ASA 包装、绝对时间、Duo 时间与实现版本字段 | 持续时长、可见事件顺序等有意义事实不盲删 |
| 缺失模式 | 空消息、Duo 未知结果、脱敏片段形状、未知格式 | 未知不补成正常；无证据和人工复核的数量单列 |
| 产品/管线来源 | 主模型不读裸来源列；完整留出与包装变换检查隐含来源依赖 | 来源仅用于可核实的解析和诊断；product 缺失桶不是独立环境 |
| 实体身份与重复模板 | 完整身份变换、同文组、近模板检查、模板族留出 | 实体关系、端口角色和动作结构保留；模板相同不等于同一真实事件 |

未知正文的风险仍可能存在。对高权重的剩余片段做字段/路径抽查，不把一次扫描结果为零称作完全无捷径。

### 3.4 原标签、日志内判断和事实分开处理

**要减少的是错误监督和标签捷径，不是把全部官方标签变弱。** 官方 label_binary 实际有三个类别。冻结训练代码只将准备后的 text 送入向量化，标签作为监督目标；但日志正文仍可能含上游风险评估、身份和来源痕迹。官方标签可以提供监督，不能拼入输入；日志内字段必须按事实来源审查。

本次全量实算发现：若把与旧模型 argmax 不同的标签自动降权，将影响正常 0 条、恶意 1,366 条、可疑 2,992 条。可疑样本中包括 Duo 12/12、WAF 2/2、AD 210/473、Falcon 26/35。即使要求预测最高分≥0.9，Duo 和 WAF 的上述全部可疑记录仍被选中。只降低这些样本权重，可能压制模型现有盲点。此处是筛选影响诊断，没有真的删除、降权或重训，也没有运行某种完整噪声学习算法。

按以下顺序执行：

1. **先隔离输入捷径。** 对确认与行为无关的采集头、身份编号和上游评估作字段级规范化。能得到完全相同主表示的合法变换，直接复用同一表示，通常无需为此增加一个训练损失。增加“更换 label_binary 不改变解析文本”的回归检查，避免后续解析器意外使用目标字段。
2. **再核对信息是否足够。** 当前原始 message 摘要中未见同文异标签；旧清洗文本有 49 组、2,423 行冲突。去除 ASA 头部后的诊断表示有 75 组、4,075 行冲突。逐组回到原文检查丢失的是合法行为事实、身份捷径，还是根本未提供的上下文。不能为了消除冲突恢复时间/IP 身份记忆。固定去头部正文、每种正文只能给一个类别时，对这些已见标签至少错 1,116 行；这是该表示上的经验限制，不是任务的理论上限或已证实的错标数量。
3. **模型不一致只建立复核队列。** 不自动删难例、改标签或按小损失保留“干净样本”。优先检查修复后的冲突组、Duo 全部 337 行、WAF 可疑及匹配正常对照、AD/Falcon 的不同错误模式，同时加入按来源/类别抽取的模型正确样本作对照。只看错误样本不能估计错标率。队列规则及抽样概率先记录。
4. **审查必须有标签之外的依据。** 核对赛事类别定义、原文可见动作/结果和可确认的事件上下文。逐条记录“事实支持 / 上下文不足 / 疑似标注不一致 / 已证实输入处理损坏”，这些不是新的攻击类别。首次判断隐藏原标签与模型分数；本次已经看过的记录只能称复核，不能重新声称盲审。不能把大模型意见、模型共识或认证 denied 直接升级成真实标签。
5. **没有可核实证据就不改监督。** 官方原标签不可覆盖；复核意见另列，未知保持未知。只有确认标注错误并留存证据，才登记一个独立纠错或可靠性权重候选。疑似、冲突、无上下文不自动降权，更不能只删掉评估中的困难记录。官方标签全量成绩继续报告；独立证据评价另报支持范围，二者不混成一个总分。

任何基于模型分数的候选权重或复核筛选，只能从当前训练职责内部的交叉拟合分数产生，不能用本轮外折/来源留出答案生成本轮训练权重。来源留出中的目标记录不能提前用于纠错规则学习；看过后修改规则，则该留出也成为后续开发资料。

**不默认加入标签平滑、旧模型软标签、自动纠错或无监督异常判攻击。** 标签平滑研究涉及过度自信与校准，不能据此推断它会消除本项目的采集头依赖；[原论文](https://arxiv.org/abs/1906.02629)。Confident Learning 提供标签问题估计方法，其理论包含类别条件噪声等假设；本项目当前模型有来源捷径，尚不能将其分数当成独立纠错依据；[原论文](https://arxiv.org/abs/1911.00068)。这是本项目的使用边界，不是断言这些方法普遍无效。

确有无法通过规范化消除、且经事实核对仍保持行为的变化时，再考虑一个成对一致性候选。先分组/分职责再生成变体；同一原记录及全部变体只在同一职责，总监督权重保持一条原记录的权重。屏蔽 result、删除动作、改变认证成功/失败不属于当然保持标签的变换。判所有样本相同也能满足一致性，所以一致性必须与真实分类、检出及误报一起验收。暂不为尚未出现的这种需要增加模型依赖。

## 4. 阶段 B：只重建必要内容，但完整重建评价职责

复用已核验的原始训练文件和旧准备缓存，缓存版本绑定规则与输入摘要；未受影响记录可直接复制，受影响格式按通用规则重做。对全部行做路由差异检查和结果汇总，不能只修发现的几个行号。

对新正文重新形成全量分组，再分配用途。ASA 仅去头部就有 183 个正文组跨旧外折、涉及 14,255 行；Duo 新处理可能带来更多合并，所以不能只修这 183 组。重新审查同文异标签、原文重复、规范化重复及可确认的事件关联；标签和每行权重保持原样，不按多数投票消除冲突。

仍用 3 个外层开发折，内层 fit/selection/calibration 为 60%/20%/20% 的软目标，seed=20260912。不可拆组及用途支持优先，继续检查每类非空组数、最大组占比和去最大组敏感性。总体用途的原 30 组工程线不应被错误推广到每个稀少来源：Duo/WAF 等可以作有明确小样本限制的压力案例，但不能靠拆组或复制凑够“可靠样本”。

同一新清单运行所有正式对照。词表、词频截选、DF、IDF、监督拟合及阈值只从各自允许的部分学习。[scikit-learn 的数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

## 5. 阶段 C：先运行修复词模型，再按失败原因升级

最先运行 C0、N 和修复后的词模型 R：

- C0 全正常；N 粗格式类别频率；R 为词 1–2 gram TF-IDF＋L2 多项逻辑回归。
- 维持 float32 稀疏输入、10 万词上限、saga、tol=0.001、max_iter=1000、C=0.1/1.0，选参平局差≤0.001 时选 0.1。
- 按拟合区原始行频率学习词表和 IDF；每行监督权重 1，无下采样、无类别权重。
- 每折两个选参拟合＋选定后一次 fit+selection 重拟合，三折共 9 次分类器拟合。校准和外折不能参与这两项参数选择。
- 每条外折输出三类原始分数、三分类结果、报警结果及无证据/复核标记，所有原始行都纳入评价。

不能用新的 R 分数直接减去旧 0.977761 来宣称清洗增益。首要比较是同一新协议下的 R 与 N，以及行为保持变换和切片结果；旧模型保留为历史与固定模型诊断基线。

效果优先意味着保留有依据的升级入口，而非强制永远停在线性词模型：

| 开发中实际发现 | 允许的下一项试验 |
|---|---|
| 输入已保留事实，但字段和值、源/目的角色在表示中混淆 | 一个有限的类型化字段表示候选；字段跨可核实格式共享，不放入产品名或未知真值 |
| 错误来自有意义词内片段、截断或未见组合 | 一个字符通道候选 |
| 输入与向量可区分、优化充分，但线性组合确实不够 | 一个受控的浅非线性候选 |
| 修复后少数类仍有跨独立组的系统性漏检，且有可观察的区分事实 | 一个有上限的类别权重候选；不使用逐条模型信心降权 |
| 只是少数来源标签不足、结果未知或缺正常反例 | 明确证据缺口；不靠调参、重采样或大模型填补 |

类别权重候选只改变监督拟合，保留 R 的同一训练行、词表与 IDF。若触发，固定试一个温和方案：按当前拟合部分计数 n_c，取 u_c=min(5, sqrt(max(n_c)/n_c))，再按拟合样本分布归一化到平均权重 1；每类必须有支持。上限 5 是预先选定的工程限制，不是已证实最优。各 C 的拟合权重由 fit 计数得到，按原规则只在 selection 比较 C；选定后以该 C 重拟合，并在 fit+selection 内重算权重。不同职责不得共用监督统计。与未加权 R 比较少数类检出、正常误报、各来源和组指标，在自然分布校准侧重新定阈值。它不能恢复未知事实，也不承诺改善 Duo。未经比较不替换 R；新增的完整候选验证计入额外预算。

每次只新增一个候选因素，复用可复用的拟合矩阵；不能同时加结构、字符、类别权重和校准。候选与触发规则在对应外折评价前登记；若看过该轮外折错误才改方案，另记开发迭代，不称作未见测试。新增候选需要完成匹配协议和同样的最终压力验证，不能因为单折提升就晋升。

## 6. 阶段 D：把域内、模板与来源验证作为同批交付

修复检查通过、候选冻结后，基础验证批次预留以下工作。无需用户每个实验单独运行命令。

| 验证 | 要回答的问题 | 基础拟合次数 |
|---|---|---:|
| 新分组域内 3 折 | 修复后是否仍超出粗格式对照，分类和报警权衡如何 | 9 |
| ASA 模板族 3 折 | 正文收益是否主要依赖熟悉的固定表达/命名 | 9 |
| 整体留出 Windows AD | 大来源改变时的可疑识别与正常误报 | 3 |
| 整体留出 Duo | 当前最突出的小来源排序与误报缺陷如何外推 | 3 |
| 整体留出 Barracuda WAF | 大量正常误报是否依赖来源接触 | 3 |
| 合计 | 不含条件新增候选 | 27 |

这是有必要证据时执行的基础预算，不要求为凑次数运行无支持的实验。输入、身份、角色或收敛失败立即停止依赖任务；不因看到较好/较差成绩就选择性跳过已登记折。新增模型候选可能增加拟合次数；不为省这部分成本牺牲必要的效果验证。

ASA 模板键先由已核实的动作、协议、接口角色与固定语句结构定义，参数值按字段角色处理，不能全局删数字或看标签/分数挑模板。模板只用于更严格的验证，不取代事件/同文约束。正式拟合前输出族清单、覆盖、支持、最大族占比；未知模板单列并报告未覆盖比例。若 3 折无法满足必要支持，预检阶段报告原因和可评价范围，不拆模板凑数。ASA 留出侧没有正常支持，报告恶意/可疑各自指标，不能编造三类 Macro-F1 或正常误报率。

整来源留出时，该来源及其确认关联组不能进入词表、IDF、选参、拟合、阈值或映射。AD、Duo、WAF 在当前旧组下分别留出后，其余数据仍保有三类；修复重组后须再核对。Duo 只有 12 个可疑组，WAF 可疑只有 1 个组，结果是压力案例和反例，不能声称稳定的异常检出率。

**零样本迁移与目标域适配分开：**零样本来源留出只能用非目标来源的校准数据和已冻结的通用策略。如果需要目标域正常样本校准，另建“适配”实验并把该来源按组拆为适配/确认部分；不能先用全部目标正常样本选阈值再称跨来源验证通过。任何 product 均不等同于独立组织。

## 7. 报警策略：先检查分数能否分开，再决定阈值

三分类保持完整三类 argmax；报警使用 1−P(benign)。两者不互相冒充，原始模型分数不称为正确概率。

1. 保留全局阈值作为对照，报告全体、非空、按来源和按组的误报与两类检出。
2. 先在拟合/选参/校准资料中审查分数重叠。Duo 已有证据说明只调阈值无法同时恢复检出与低误报，不能把这类问题交给概率校准掩盖。
3. 来源条件阈值仅作为已知来源的候选。路由必须在预测时可靠可得，不从真实标签决定来源；来源不明或支持不足不补成正常。最初的保守候选只允许相对通用阈值提高阈值，同时记下少报了哪些威胁，不能为了用满预算反而降低良好来源的阈值。
4. 选择阈值只用校准侧。需要选择阈值策略或拟合概率映射时，将校准资料按组再划为策略/映射和阈值两个职责；支持不足则不增加这层学习。
5. 最终外层/留出侧报告实际兑现情况；低误报不达标就标未满足。人工复核、拒识或无证据输出同时计覆盖率、复核数与留在自动通道的漏报，不能靠全部拒识“通过”。

少量正常样本不够支撑很低的误报承诺。即使固定阈值在一份独立、同分布的验证资料上零误报，要让单侧 95% 二项上界≤0.001，仍至少需 2,995 个独立正常试验；0.0001 对应 29,956。Duo 每折校准正常只有 37～45 条，ASA 产品桶为 4/2/0 条，远不足以作这种保证。该数值仅说明理想独立条件下的证据量：重复行、近似组、阈值选择资料和分布漂移均不能冒充满足条件。[SciPy 精确二项区间说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats._result_classes.BinomTestResult.proportion_ci.html)

无需在本轮一开始强制拟合温度缩放或等距回归。若分数可分但概率/阈值仍有明确问题，再登记一个简单映射对照；映射不能恢复未知结果，也不能保证新来源适用。

## 8. 提速必须保持同一统计问题

上一轮真正拟合约 20.25 分钟，其他环节约 81.28 分钟。这个差额不是完整性能剖析，不能宣称其中全是无效计算。本轮先增加阶段计时，再按收益实施以下优化：

- 原始数据、准备缓存、返回模型在平台已有；只上传小更新包，校验基包/原件摘要后在新目录执行，不重传大包。
- 规则未变的解析结果复用，修复格式按唯一原文计算一次再映射回全部行。规则/输入变动使对应缓存失效。
- 两个 C 共用允许拟合部分的矩阵；fit+selection 重拟合必须重新学习词表/IDF，不能误用旧拟合词表。
- 同一冻结模型下，对相同新正文只做一次 transform/predict，再还原到所有原始行；不同标签仍逐行计分。一次稀疏批次同时完成概率、零向量和碰撞诊断，避免再扫描同一外折文本。
- 允许缓存纯确定性分词；缓存里不能藏有全数据学习的词表、DF、IDF、类别频率或阈值。
- **本轮不以监督去重、类别抽样、自定义加权 IDF 或换求解器作为默认提速手段。** 这些会改变优化或引入额外等价性负担。若以后确需使用，先验证等价或登记为新候选。[TF-IDF 的频率与规范化定义](https://scikit-learn.org/stable/modules/feature_extraction.html#tfidf-term-weighting)
- 输出按实验职责绑定输入、源码、表示、词表、模型、阈值和行序摘要。已完成并核验的任务可恢复复用；失败或摘要不匹配的任务不能当完成。

先测一个正常任务的真实内存/CPU峰值，再判断最多并行两项独立折/留出任务。当前 CPU 配额历史记录为 40 核、内存上限 320 GiB，实际空闲资源必须在运行时检查。优先复用现有 CPU；不把昇腾 NPU 当作这套 sklearn 稀疏模型可直接使用的 GPU。无法安全并行就顺序跑，不能削减验证来追求耗时。

优化前后使用同一冻结模型核对全部预测：类别必须一致，数值差异及阈值附近的报警变化单列；有无法解释差异就撤回该优化。不能把本地约 60 秒推理复核与云端 101.5 分钟训练流程直接相除声称加速倍数。

## 10. 三轮对抗性自审后的通过条件

- **第一轮：用假高分反驳方案。** ASA 头部变化、Duo 脱敏结果模式、来源纯类和新同文跨折都能推翻“0.9778 即可靠”。已加入字段边界修复、缺失消融、重组与强制留出。
- **第二轮：用低误报换漏检反驳方案。** Duo 来源阈值把误报压低却丢掉检出；AD 来源阈值反而增加无必要报警。已加入同时计费误报、漏报和复核，不自动部署来源阈值，不以全部拒识通过。
- **第三轮：用省时导致目标变化反驳方案。** 去重改变 IDF、复用留出词表、减少关键折或只打补丁不重组都会破坏证据。提速限定在确定性计算、同职责缓存和可恢复调度；必要训练与外推验证优先保留。

允许继续投入：输入边界回归通过，同文不跨职责，拟合/选参支持合格且收敛，新同协议下的正文收益可解释。允许对某来源作更强主张：该来源拥有实际正常/异常支持、报告的报警预算兑现，且没有依赖目标数据的伪留出。无法满足的来源保留未验证范围；不外推为全环境能力。

官方数据足够推进本轮修复、开发比较和内部压力验证；不足以保证任意实际环境。暂不找外部训练数据，也不把字段未知、来源缺反例和缺独立环境的问题伪装成更多算力能够解决。若效果与便利冲突，优先做必要的重训与验证，并通过小包、单入口和恢复能力减少用户操作成本。

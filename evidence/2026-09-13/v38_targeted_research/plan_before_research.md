# v3.8 下一步方案：先修编码与决策，再验证有限分型

状态：2026-09-13，根据 [v3.7 实际结果](V37_CLOUD_RESULT_REVIEW.md)修订。当前完成的是回传审查和固定模型干预；以下新的表示、训练及选模流程尚未实施，不是可直接上传运行的新版执行包。

## 1. 目标与不能混淆的事实

模型需要根据能够观察和解释的行为事实区分正常、恶意、可疑，并在新来源上控制误报。禁止把采集包装、产品名、日历时刻、任意身份和上游判定当成攻击证据。允许有语义的协议、行为结果和关系信息，但必须追踪其来源、训练支持及缺失影响。

原数据和标签保持不变，不下载额外数据。既有五协议继续作为已查看的开发回归；不把它们重新称为盲测。v3.7 控制和修复模型冻结保存，不覆盖其代码、指标或失败回执。

本轮最关键的新约束：**若不同事件在实际编码向量上已经合并，先检查可识别性，不能把错误全部归因于分类头容量。** ASA hard 的编码总错误下界为 3,246，实际错误 3,473；原计划直接上条件分型不再作为第一步。

## 2. 第一步：兑现已证实的局部修复，不立即全量重训

冻结当前固定模型“屏蔽 authentication 类别独立特征”的诊断分支，保存独立名称、原模型摘要、特征索引、输出和旧门槛。当前五协议中它使 known_dev 正常误报 39→0、Duo 62→0，AD/Duo 可疑检出不变；WAF/ASA 不变。

这是开发证据下的候选修复，不直接覆盖正式预测入口。下一轮源特征修改必须同时检查结构化类别及正文中的同义字段名是否绕行，不能删除一个系数后让重训在另一个字段重新学到相同捷径。

修正下一版回放器的数值判断：身份、行号、标签和冻结主决策仍要求精确；概率按预注册容差，NP 尾概率等连续诊断量单独报告容差及差值。主阈值与非主阈值分开核验；浮点边界发生实际决策变化须记录，不能仅放宽数值比较后宣称决策一致。

验收：本次全部已证实包装变换继续通过；主评价输出逐条可回放；旧失败回执保留。此步不需要平台重训。

## 3. 第二步：把“保留字段”升级为“保留可用语义”

为正文→解析事实→编码列→模型输出建立最小追踪表，重点检查以下已出现的失败：

- Duo 的有效凭据事实被保留在准备文件，却因类别未见而被编码丢弃；泛化类别却继续加分。
- ASA 的 10,748 种目标表示编码后只剩 1,406 种；38,769 条已观察源端口、25,044 条已观察目的端口对应值未进入有效编码。
- native flow 只剩网络类别、协议、端口时，信息不足以直接宣称检测到了攻击行为。
- CEF `app=tlsv1.3` 属于应用／安全协议描述，不能与明确观察到的 TCP/UDP 传输协议无区别地共享“protocol”字段。没有传输层证据时保留未知，不能凭应用名补出事实。
- JSON 字段名、容器名称、脱敏占位及集合结构不应自己充当风险证据；保留它们用于追踪，不让缺少实际正文的容器凭样式得到高置信攻击结论。

采用有边界的共享事件事实：动作、对象、结果、传输／应用层协议和端点关系分开。认证成功、凭据有效、用户被允许、认证失败保持各自语义；不能为了压误报把 `valid_passcode` 一律等同于整个登录成功。跨格式同义映射须有文档／明确原文字段证据。

端口候选采用语义分层：传输协议＋已知服务／端点用途＋有依据的端口关系。精确值保留在审计原件；是否进入预测须独立验证，不能默认临时源端口是标签。词表只从允许拟合侧建立；预定义语义映射必须在评价前冻结，不能从目标端口清单补齐类别。未见值退化需要可见的支持标志，不能悄悄等同于缺失或正常。

重要限制：分层语义编码可能不能保留精确端口与官方标签间的全部相关性。这种情况下如实报告可识别性代价，不能为了降低本次冲突下界恢复无依据的身份记忆，也不能宣称信息已全部找回。

验收：在允许开发侧同时报告原始、解析、编码三层冲突下界，记录每种合并的原因；对同义包装要求不变，对真语义变化检查是否保留区分，对未知值报告降级行为。追加新格式变换回归时，也必须保留本次全部真实反例。此步不拟合大型模型。

## 4. 第三步：针对 WAF 的来源外决策失效做受控比较

固定 v3.7 修复模型及其门槛作为失败对照；类别干预分支作为已有开发对照。只引入一个主要训练候选：**在经过上一阶段审查的事实表示上直接训练 benign 与 non-benign 的风险模型**。不同时开启类重加权、重采样、重复降权和大网格，以免无法判断收益来源。

目的不是宣称二分类天然更好，而是将风险损失及选择标准与真实报警任务一致。当前 `1-P(benign)` 来自三分类联合拟合；它与直接优化二分类目标是两个不同方案。

每个外层协议内部，仅在其允许开发行上进行内层来源／行为家族留出，联合组不跨角色。来源信息只用于划分、支持检查和评价，不成为预测值或“缺产品名就选某门槛”的路由。拟合、概率校准（如使用）、门槛选择及内层评价分开；正常量或风险类别不足的折标记为不支持，不拆组凑数据。

选模比较实际最终规则：

1. 全行正常误报及每个受支持来源的误报；保留主工程目标 0.1%，不能用总体平均掩盖 WAF/Duo。
2. 在上述约束下比较风险类检出，之后检查最终三类召回与 Macro-F1。
3. 报告各来源的正常／风险行数、联合组数和错误集中度。小于所需支持时不能给出稳定低误报保证。
4. 若内层留出已经出现整来源全报警、单类零检出或事实不足的高置信预测，停止该候选；不进入全量平台轮次。

门槛必须由隔离的允许开发数据决定。不能使用现在已知的 WAF／Duo 评价分数间隙指定 0.01 等新常数，也不能假定未知来源绝大多数正常后强制只报固定比例。NP／概率校准仅作有明确假设的候选工具，本轮已证明直接套现 NP 门槛不能修复误报。

若直接风险模型仍在内层来源留出失败，先返回事实覆盖与类别支持检查，停止同类重训。只有明确证据指向非线性表达不足，才开启一个有界非线性候选；不因为结果差就默认上大模型或图网络。

## 5. 第四步：有足够输入信息时才执行条件分型

在风险方案固定后，在允许拟合侧的 malicious/suspicious 子集比较两个小候选：无交互与有限语义交互。原行权重不改；正常行仍参与风险学习及最终全行评价。

交互限定为预先声明且实际可观察的协议×端点角色、协议×目的服务类别等。先检查组成成分和必要类别在拟合侧是否有支持；目标独有组合不得通过查目标标签赋值，完整未见组合的 one-hot 特征也不能被当作已学会外推。

必须分开报告：原表示冲突、编码新增冲突、编码非冲突，以及关系已见／未见。对当前编码下不可分的 3,246 个总错误，不将“提高可疑召回但同时错更多恶意”冒充冲突解决。

停止条件：若改进只来自恢复原编号／临时端口记忆、牺牲另一类而隐藏混淆矩阵，或输入仍因缺策略而不可区分，停止扩展分类头。EBM、树模型或更大网络不能补出缺失上下文。

## 6. 全量执行、交付和最终门禁

以上局部阶段先在本地完成可归因实验，通过后沿用用户已选择的“单执行包＋命令，用户在平台运行”。不重新上传原训练集，不恢复两分片上传流程。代码、选择规则及最终包摘要在评价前冻结。

候选全量回归仍覆盖 known_dev、AD、Duo、WAF、ASA hard。它们是已经查看的开发回归，不是新盲测。若表示／分组变化影响职责，重新构建共同组，对所有需要比较的分支用相同职责拟合；不混用不同切分成绩。先跑与缺陷直接相关的小对照，失败即停止，避免又完成 30 次拟合后才发现同一个问题。

所有正式成绩来自统一的最终预测接口。三分类概率、原始 argmax、报警后分型分别明确命名；原始概率文件中的 `prediction` 不再模糊指代正式提交类别。主规则回归标志直接比较主混淆矩阵，同时保留 argmax 诊断，修复本轮选模目标与输出规则分离的问题。

反例门禁包括：等价包装不能改变预测；正常认证不能仅凭家族标志报警；完整 WAF 不能全量误报；ASA 的每一层信息损失可解释；所有未知、冲突和复核记录继续进入全行指标。复核不是第四个比赛标签，更不能自动写成 suspicious。

当前官方数据可继续支持这些步骤。判定细则、策略信息、可信实体／时间关系未得到确认前，不承诺解决所有 ASA 分型，也不承诺对任意外部日志维持高准确率。出现这类明确的信息障碍时停止无收益训练，记录需要确认的最小事实，而不是无限调参。

# 当前训练方案：先证明判断依据，再提高分数

版本：2026-09-11。本文替代散落的七份旧路线稿；历史事实可回查 [完整独立分析](历史分析_2026-09-11.md) 与 [审计证据](../evidence/README.md)。当前状态：v1.1 云端/本地切分内容和逐行预测类别已核对一致，原型可疑召回仍为 0。v2 有限行为解析、温和权重与来源留出已在本地执行，未通过检测或迁移验收。上下文方案开发分数提高，但 ASA/VPC 来源留出的可疑召回降至 0%；分组隔离后的开发区仅 1 条可疑，不能支撑可靠选型。最新实测与依据见 [v2 复核](BEHAVIOR_V2_REVIEW.md)，v1 表示损失诊断见 [历史试验复核](SIGNAL_PILOT_REVIEW.md)。

下一项优先工作是审计分组过度合并与遗漏，在全量官方训练集上确认每类独立组和用途覆盖，然后补同来源正常/攻击对照。当前不扩大已失败版本的训练，不以换种子修饰少数类支持。完整行为解析、自由文本支线、独立外部评价和最终提交仍未完成。

## 1. 第一性原理：要学的是行为与威胁的关系

任务的真实目标是：在输入包含足够证据、标签定义一致的目标环境里，以可接受的误报成本识别威胁。官方逐事件三分类是必须满足的输出契约；“换任意数据仍然正确”没有可验证的统一含义，应具体化为新时间、新实体、新采集器表示、新产品和新环境上的表现。

可以把日志生成过程简化为：

`真实行为 B + 环境 E + 采集/脱敏规则 C → 可见日志 X；行为及标注规范 L → 标签 Y`

训练集中若 E 或 C 恰好和 Y 绑定，模型能绕过 B 拿到高分。一旦部署环境改变，该关联可能消失。我们要保留“登录连续失败、执行动作、拒绝原因、访问序列”等有语义的证据，同时验证判断是否依赖“哪一年采集、是否缺字段、来自哪个产品、实体叫什么”。这是识别问题，不能只靠换算法解决。

还有两个不可忽略的限制：日志不一定记录足够上下文，单条事件可能无法区分合法管理与攻击；`suspicious` 的官方定义也不能自动等同于“模型不确定”。对这些情况应补证据或单独记录待复核状态，不能制造看似精确的标签。

## 2. 已经确认的数据问题

| 现象 | 实测事实 | 对方案的影响 |
|---|---|---|
| 类别失衡且比例变化 | 训练正常 92.36%，验证正常 97.30%；验证恶意约 0.70% | Accuracy 不作主决策指标；自然分布验证、分类别看误报漏报 |
| 时间与标签混淆 | 恶意最晚到 2024-07-18；正常/可疑从 2024-07-26 开始 | 单纯按时间切分无法从现有数据得到覆盖三类的独立未来测试 |
| 缺失与标签混淆 | 训练 `dst_host` 缺失的 111,728 行恰好全是恶意；验证 14,052 条恶意中 13,996 条缺失，其他类不缺失 | 缺失可能描述采集链路，必须规范化表示并检验依赖 |
| 产品与标签混淆 | ASA 几乎都是可疑；AWS VPC 在现有数据中全是可疑；Falcon 的类别比例在训练/验证改变 | 产品不能充当标签表；必须补同产品不同类别证据 |
| 实体、模板与重复 | 验证非空实体值与训练对应列不相交；去除时间等列后大量事件重复 | 新实体不等于新行为；应同时做模板/事件组隔离与来源隔离 |

训练输入真实只有 12 列；`label_binary` 是三类目标。任何更丰富的动作字段均须从 `message_sanitized` 解析得到，并保留抽取证据。`event_id` 只用于对应输出，跨训练/验证重新编号，不是跨集关联键。

“四类强线索”作为本项目的操作性分类是：**时间、缺失模式、产品/管线来源、实体身份与重复模板**。它们可能包含部分合理上下文，也可能编码采集差异；本地数据不能证明主办方是否故意设置陷阱。

全量官方验证的对照结果：

| 方法 | Macro-F1 | 说明 |
|---|---:|---|
| 全判正常 | 0.32876 | Accuracy 仍为 97.295% |
| 缺失规则 + 产品查表 | 0.99581 | 简单数据规则已可取得极高分 |
| 时间 + 产品的深度 4 决策树 | 0.99943 | 高分不足以证明理解攻击行为 |
| 冻结旧 CatBoost | 0.91668 | 恶意 Recall 1.0，但 Precision 只有 0.61661 |

这不是推荐部署上述规则，而是建立“能解释成绩”的负面对照。旧 CatBoost 在验证中将 8,737 条正常 WAF 事件判为恶意、801 条正常 Falcon 事件判为可疑，说明汇总 Accuracy 0.99524 掩盖了具体业务错误。

新增固定 100,000 条样本测试，无重训、无阈值调优：

| 变化 | 翻转数 | 恶意召回率 |
|---|---:|---:|
| 不变 | 0 | 100% |
| 所有类别字段 null → 空字符串 | 726 | 0% |
| 所有时间 +364 天 | 0 | 100% |
| 非空实体一致、一对一重命名 | 0 | 100% |
| 上述三种组合 | 726 | 0% |

基准样本含 726 条恶意、2,076 条可疑、97,198 条正常。null 测试说明旧模型对序列化表示极不稳定，尚不说明是哪一列单独造成，也不等于真实外部召回率已经测得为零。日期/实体测试通过只覆盖旧结构化模型这两种扰动；没有证明新的文本模型或任意身份变化都安全。

## 3. 训练集是否足够

**官方数据足够启动基线、开发解析器和验证流程；不足以证明用户要求的广泛迁移能力。需要补独立评价数据，并针对已知覆盖缺口补充训练证据。补充价值取决于缺失的行为/环境组合，而非行数。**

现有约 205 万行不能替代缺失的对照：同一产品、相近时段、相同字段完整度下，正常与攻击分别是什么样。重采样、日期平移、SMOTE 或改类别权重都不会创造这些真实信息。若一个来源只出现一种标签，该来源内部的行为判别能力暂时无法可靠识别。

补数据按以下顺序：

1. **优先同语义、同字段的互补样本。** 向主办方核对三类定义与允许外部数据的规则；争取同产品同时期的正常、攻击、可疑日志。重点覆盖正常 WAF 拦截、合法管理/扫描、正常 Falcon 活动，以及字段齐全的攻击和字段缺失的正常事件。标签应由事件事实、攻击记录或人工复核支撑，不能因日志里有 attack/error 就认定恶意。
2. **建立独立外部评价集。** 在看结果前确定环境/场景边界、标签映射和适用任务。需要正常与攻击同时存在；保留长尾、自然负样本比例和来源明细。外部集先用于测量缺口；用过的目标域诊断集不得再次称为未见测试。
3. **根据错误补训练数据。** 只有分来源错误证明某类行为、解析器或标签边界缺失时，才加入相应数据。目标域适配集、校准集与最终留出场景必须分开。比较官方源域训练、仅目标域训练、混合训练三者，确定迁移是否真的有帮助。

一个可用公开候选是 [AIT-LDS v2.1](https://zenodo.org/records/19483937)：包含 8 个模拟环境，提供逐行攻击步骤标注。官方已有不含 PCAP 的压缩包，例如 russellmitchell 约 522.1 MB，不必默认下载约 7.1 GB 完整包。先选一个场景做结构与标签审计，若匹配，再至少用三个互斥场景分别承担开发/适配、校准、最终留出；场景少时结论仍需限定范围。

AIT 不是官方三分类的直接替代品。应先按原始真值定义“标注攻击活动与正常”的独立任务；官方模型的 `P(malicious)+P(suspicious)` 只能作为非正常风险分数的迁移探针，不代表两个数据集正类语义完全相同。保留无法对齐的样本和覆盖率说明，不能为了算三分类 F1 强行把攻击步骤划成恶意/可疑。无标注行只有在官方规定的有效时间与标注范围内，才能按其约定理解为正常。

本次未下载或混入外部数据。是否允许外部数据进入最终参赛训练，需要以赛事规则/主办方答复为准；规则未明确前可以独立研究评价，不能宣称合规资格已经确认。

## 4. 验证设计：先冻结样本职责，再训练

一套分割无法同时代表所有迁移方向。建立以下互补验证，不把它们混成一个平均分：

| 验证层 | 样本与切分 | 回答的问题 |
|---|---|---|
| 开发验证 | 官方训练内部按事件/模板组隔离；训练、选型、校准各自独立 | 同来源新行为上的模型和阈值选择 |
| 官方诊断 | 已经查看过的完整 `valid_input` + 答案 | 是否满足赛事接口，错误集中在哪些来源；不是未见测试 |
| 表示稳定性 | 固定事件在语义不变时变更空值、脱敏名、全局日期及组合 | 是否把格式、编号或绝对日期当成威胁证据 |
| 来源留出 | 产品/采集环境完整留出；报告每类支持量 | 新来源是否仍可用，或者只是来源分类器 |
| 时间留出 | 在各有类别覆盖的来源内前训后测，窗口边界留间隔 | 真正未来数据表现；现有官方数据不足处明确 N/A |
| 外部环境留出 | 不同采集/攻击场景，标签可审查，预先锁定 | 对明确目标域的迁移能力 |

具体约束：

- 每条记录使用 `dataset_id + event_id` 作全局标识，保存原文件哈希。分割清单记录事件/模板组、来源、时间和用途，先写清单再拟合特征与词表。
- 去重先报告原始重复、规范化模板重复及可能的近重复。精确与近似规则分开审计，不能把所有相似登录行都当同一事件；重复行不能跨训练与评价。保留原始发生次数作为因果窗口计数或样本权重信息，避免删除真实爆破频率。
- 事件/模板分组与实体留出是两种测试。拼接 `src_host|src_ip|username|dst_ip` 只保证组合不重复，不保证任何单实体互斥。若做实体连通分组，先检查巨型连通分量，不能为了分层好看任意拆开。
- 不强行构造每折都有三类。来源与标签完全混淆时报告缺失支持，不能悄悄用随机切分修饰成绩。`StratifiedGroupKFold` 只能尽可能兼顾分组和比例。
- 词表、模板统计、归一化参数、插补值、特征选择和模型均只在该折训练数据拟合。插补参数随模型保存，预测批次大小不能改变结果。相同事件单独预测、不同批次顺序预测应一致。
- 所有行为窗口只看同一来源/采集会话中当前及过去事件；按时间因果回放，不使用未来日志或其他折的标签统计。不能把数年前恶意样本和集中一小时的正常数据拼成一条“攻击链”。
- 官方验证已经被查看，后续所有据此产生的选择都要承认适配了这个诊断集。真正的确认来自提前冻结的新环境或最终未见官方测试。

## 5. 指标和决策规则

准确率回答“多数事件判得是否相同”，业务还需要知道每次报警有多少可信、多少攻击被遗漏。若攻击基率为 π、召回为 r、正常误报率为 f，则：

`Precision = πr / [πr + (1−π)f]`

例如攻击只占 0.1%，召回 95%，正常误报率 1%，报警精确率约 8.7%。全判正常有 99.9% Accuracy，但毫无攻击检出能力。即使 ROC-AUC 很高，也要检查实际阈值下的这一组数字。

每次实验至少同时保存：

- 三类各自 Precision / Recall / F1，Macro-F1，完整混淆矩阵；Accuracy 仅作附项。
- malicious 与 suspicious 各自 one-vs-rest PR-AUC/AP、ROC-AUC；报告 AP 算法口径，勿混淆积分算法。正类缺失时标 N/A。
- 正常被报为 malicious 或 suspicious 的总比例，及每 10,000 条正常事件产生的误报数。
- 在固定误报预算下的恶意/非正常召回，以及每产品、来源、时段、模板、新旧实体的支持量与表现；额外报告有足够支持的最差来源表现。
- 按事件组/场景重采样的置信区间，避免将大量相关重复行当独立证据。类别极少时报告区间很宽，不用一个漂亮小数掩盖不确定性。

初始工程比较点设 `benign → 非正常 FPR ≤ 10^-3`（每万正常最多约 10 次误报），另画 `10^-4、10^-2` 对应曲线。这是可调整实验预算，**不是官方评分规则，也不是已获 SOC 业务认可的告警容量**。若校准集没有足够独立正常样本支持极低 FPR，就不能声称达到该水平。阈值仅由校准集选择，确认集只评价一次。

模型分数不是正确概率，尤其是采用类别权重后。用独立校准集评估可靠性曲线、Brier/log-loss；视样本量选择温度或简单校准映射，三类阈值需写清冲突与兜底规则，不直接套用二分类 API。未知来源与低信心可以产生内部 `needs_review` 标志，但官方 `pred_label` 仍须从三类中选一个；不能把“不确定”偷换成官方 `suspicious`。

## 6. 训练主线：优先行为证据，控制复杂度

### 6.1 固定预处理契约

- 所有空值表示（null/NaN/空串/约定空白）先按字段语义统一为一个缺失状态；合法值如数字 0 不当空值。纯表示变化应得到相同特征。保留缺失信息不代表允许它单独决定恶意，需要消融和补齐反例。
- `event_id`、原始绝对日期、原始 IP/主机/用户名不进入主模型。现有数据也暂不使用年/月/日/时段等时间派生量；未来有同源多时间覆盖后再通过独立验证决定。实体只用于关联和因果窗口计算。
- `product_name/vendor_name/pipeline` 可用于选择正确解析器和报告来源。主行为模型先不输入这些裸类别；需要协议/产品语义的字段可显式保留，并做来源留出。如果辅助来源分支有收益，必须证明收益不是标签查表再加入。
- 文本内的实体名、绝对日期、随机标识也做语义保持的规范化；保留动作、结果、错误码、端口角色、请求结构、进程/命令行为等证据。解析不足或失败必须可见，不能静默归正常。
- 解析器有版本和覆盖率；字段名及消息格式要以实际样例确定。规则直接给出的风险分数视为弱证据，不当真值。

### 6.2 从可解释的两条基线开始

第一版有限原型已提供 [可运行入口](../training/README.md)，仅提取 23 个固定词法信号，不能等同于本节要求的完整行为解析器。真实抽样发现 82.45% 日志没有命中信号，模型特征重要性主要集中在拒绝访问信号，可疑类召回为零。后续 v2 已增加有限的认证/网络/请求解析并执行来源留出，仍存在表示不足与来源迁移失败。已查看的内部评价区转为诊断材料；后续变更不能继续用其成绩证明未见表现。

该冲突诊断现已执行：训练区 56,536 行只形成 6 种输入，23 个特征仅 5 个非零；1,801 条可疑全部与其他类别共享向量。拒绝访问一组包含 2,698 条恶意和 1,522 条可疑，且来源/缺失仍与类别混淆。v2 已将认证动作/原因与协议/服务上下文分开，对可确认的结构片段和 syslog 日期补充处理；这不是完整恢复损坏原文。24 个行为字段在本轮 29,253 行可用范围形成 11 种向量，增加上下文为 17 种。更丰富的表示没有通过来源留出，温和权重也未改善本轮开发结果。分组、支持量和具体原文证据集中在 [v2 复核](BEHAVIOR_V2_REVIEW.md)，此处不维护另一份规则表。

现有脱敏可能破坏字段名、语义词和 JSON 数值，不得根据标签猜回原文，也不得把解析失败作为攻击特征。正常“拒绝/拦截”和恶意行为的同源对照是优先补充的证据。词法特征也会编码来源，去掉裸产品列不意味着来源捷径已经消除。

1. **解析行为字段 → CatBoost。** 先小规模但覆盖各类、来源与事件组地验证数据管道，再在冻结切分下训练。将动作、结果、协议语义和因果统计作为候选，而不是重用旧的实体/日期主线。
2. **规范化文本 → 稀疏 TF-IDF/字符 n-gram 线性模型。** 用训练折拟合受控词表/维数，按内存分块抽取；限制超长日志时先保留语义关键字段，记录截断覆盖率。约 205 万条长文本不宜无预算地全部稠密向量化。

只在两者的折外错误明显互补、在来源留出和固定误报率下都有收益时做简单融合。序列模型、图模型或大模型在能提出具体失败案例并获得可靠序列/关系与标签之后再考虑。解释先输出支持判断的原日志片段、解析字段和窗口事件；特征重要性/SHAP 只能解释模型依赖，不能证明因果正确。

### 6.3 不平衡处理

- 验证和确认保持目标自然分布，禁止为了好看改成三类各三分之一。
- 训练比较不加权与温和的平方根逆频率权重；再按来源与事件组限制重复样本的支配程度。权重上限和下采样率只在开发集选择，不直接默认完全逆频率。
- 少数类不因抽样丢失稀有模式；正常侧按来源/模板保留覆盖并挖掘高分误报样本。所有难例挖掘只来自训练/开发区，不能从确认集回流。
- 表示增强仅覆盖语义保持的空值、脱敏名、日期等变化，不能凭增强创造攻击真值。掩掉产品或消息属于信息消融，要另记；SMOTE 不用于构造虚假的 IP/产品/文本事件。
- 是否加权以固定误报预算下的召回和分域表现决定。旧模型恶意 Precision 0.61661 已说明“召回全对”不足以支持强类别权重。

## 7. 最小实验矩阵与验收

| 阶段 | 实验/产物 | 进入下一步的依据 |
|---|---|---|
| 已完成 | 全量审计、捷径对照、旧模型全量评估、10 万条表示压力测试 | 数字与脚本可回查，失败已明确 |
| 已执行、未验收 | v1 两端内容核对；v2 有限 A/B1/B2 与来源留出 | 核对通过；来源留出失败及类别支持不足，先修分组与对照数据 |
| A | 新预处理契约、切分清单、表示/批次一致性检查 | 语义等价输入的特征与输出一致；没有跨折拟合 |
| B1 | 行为 CatBoost，无权重 | 输出全部分类别/分域指标，展示代表性误报漏报 |
| B2 | 同一模型，温和权重 | 只因固定 FPR 下召回或稳定性改善而保留 |
| B3 | 规范化文本线性模型 | 检查文本词片是否仍泄漏来源/标签生成方式 |
| C | B1/B3 简单融合及来源/缺失/文本消融 | 折外互补，有可靠收益才融合；不过度扩大调参 |
| D | 互斥外部场景零样本评价 | 明确标签覆盖、解析覆盖、性能下降来自哪里 |
| E | 必要的目标域补数据/适配 | 在另一提前冻结场景上优于不适配，报告代价 |
| F | 最终推理、说明与展示 | 提交契约、算力/耗时、证据片段均通过实际回放 |

每次输出最少包含：数据/模型/配置哈希，划分清单，特征契约版本，训练与校准来源，指标及支持量，阈值，错误样本索引，耗时/峰值内存。保留失败实验，但不把运行记录当成通过验证。

升级模型的判断顺序是：数据与标签可比 → 切分可信 → 表示稳定 → 在既定误报预算下检出能力 → 最差支持来源 → 官方诊断分数。没有达标证据就不宣称“具备良好迁移性”。

最终 CSV 必须列名为 `event_id,pred_label`，输入每个 ID 恰好输出一次，集合完全一致，不重复、不漏行、不多行，预测仅为三类合法枚举。旧 `validate_submission` 尚缺完整集合与枚举校验；应在最终推理实现时补齐。异常/空消息要测试，未知产品不得静默失败。检测性能、提交格式与前端解释展示分别验收。

## 8. 平台和资源安排

先在赛事平台核对账户资源、CPU/内存/GPU、持久盘、断连恢复、数据位置、依赖和网络，再决定如何运行。第一轮以 CPU 的解析/CatBoost/稀疏线性模型为主；当前证据没有要求先使用 GPU 或训练大模型。平台若缺足够内存，采用 parquet 分列读取与分块特征缓存，不反复全量加载长文本。

后续核查已通过无登录凭据的 HTTP GET 读取平台公开资源，确认开发环境提供 Jupyter/VSCode/Shell 与独立训练任务入口。用户截图为 `Mindie` 环境、`Mindie12` 镜像、1 个运行实例和 2 张昇腾 910B；容器回传确认 40 核等效 CPU 配额、320 GiB 内存上限、cm-model 七个包及 `/root/work/sf02_data` 数据路径。v1 云端真实训练约 223.4 秒、进程峰值 RSS 1.1443 GiB；两端切分内容和预测类别已核对。全局昇腾工具依赖、NPU 功能、实际空闲资源和持久挂载仍未验收。v2 仅在本地运行，4 线程约 159.3 秒；当前结果不支持到云端扩大同版训练，资源不是这轮主要障碍。

浏览器工具仍连接失败，助手没有在云端启动/停止实例、上传或执行训练，也没有取得账单。用户已回传 cm-model 的 v1.1 真实训练成功结果，耗时 223.404 秒、进程峰值 RSS 1.1443 GiB。回传源码哈希与本地一致，其必经输入哈希检查先于训练，因此支持官方文件身份检查已通过；助手未独立重读云端数据，切分/逐行预测内容待只读核对。当前结果不具备迁移验收结论，已有运行实例的账户用量不能认定为零。具体操作见 [platform/PLATFORM_GUIDE.md](../platform/PLATFORM_GUIDE.md)，访问记录见 [platform/USAGE.md](../platform/USAGE.md)。

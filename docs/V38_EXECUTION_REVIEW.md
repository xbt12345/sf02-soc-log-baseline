# v3.8 本地分类器训练与停止依据

日期：2026-09-13。**已完成三个三分类候选、一个字段可用性对照，以及后续独立回放。质量未通过，按既定条件停止扩大训练。** 本轮未启动平台，没有生成比赛提交文件。

## 1. 实际执行的范围

本轮执行 [冻结前方案](../evidence/2026-09-13/v38_execution/training_plan_before_execution.md)中的表示修复、验证支持检查、A/B/C 三个输入对照及反证审查。阶段 D 的重加权／增加模型容量没有启动：结果首先暴露的是字段结构捷径与来源支持不足，尚不能把主要问题归因于类别先验或容量。

仅使用官方训练集；完整核对 2,056,871 行的原文件摘要、事件 ID、原标签与消息摘要。原标签和历史模型未修改。使用本地 CPU，线程上限 4；准备阶段约 147 秒，三个候选及负对照训练阶段约 171 秒，不包含前后代码实现和审查时间。

模型正式拟合共 **10 次**：三个输入分支各比较两个正则参数并按选择结果重拟合，共 9 次；字段可用性对照 1 次。软件测试中的合成拟合不算 SOC 训练。

采用既有 known_dev 的允许开发行，原外层评价行全部排除。内部把允许行中的 Duo 和 WAF 整来源及其关联组留给内部评价，联合组不拆分。角色如下：

| 角色 | 正常行 | 恶意行 | 可疑行 | 恶意联合组 |
|---|---:|---:|---:|---:|
| 初始拟合 | 927,552 | 62,946 | 32,785 | **2** |
| 参数选择 | 163,924 | 10,090 | 2,278 | 20 |
| 内部评价 | 167,222 | 10,090 | 1,763 | 20 |

最后使用拟合＋选择的 **1,199,575 行**重新拟合，评价 **179,075 行**。没有为凑类别拆开联合组，没有使用原外层评价行拟合、选择或调门槛。当前内部评价一经查看也成为开发资料；不称外部迁移验收。

初始恶意拟合只有两个联合组，这限制了可验证的变化范围。Duo 内部可疑 10 行仅两个组；WAF 可疑 2 行只有一个组。大量正常行不能补足这些证据。

## 2. 已落实的代码变化

- 主分类只有 benign、malicious、suspicious，参数选择和导出都用同一个三类最大分数规则，不再叠加报警门槛。
- 结构化事实中的泛化 category 被移除；由事实拼出的正文不再重复暴露类别、字段名和精确端口。认证结果、凭据检查仍各自保留，不把有效凭据自动当成整个事件成功。
- 传输协议与应用／安全协议分开，TLS 不自动补成观察到 TCP。
- 固定语义域和完整端口域不依赖拟合词表。未知值、缺失、非法值的状态进入审计；两端口精确值在不同分支中显式控制。
- 三个分支共享数据职责、文本统计方法、有限正则候选和原行等权。重复记录只合并计算相同损失的次数，没有降低重复样本权重。

保持信息可还原本身会暴露“是否观察到此事实”。本轮没有把这种可用性预先宣称为无害，而是训练了独立负对照，实际检查它能解释多少成绩。

## 4. 真正的内部分类结果

各分支先在选择侧选参数，再重新拟合，最后比较共同内部评价行：

| 分支 | Macro-F1 | 恶意召回 | 可疑召回 | 正常误报 |
|---|---:|---:|---:|---:|
| A：共享事实 | **0.82578** | 67.06% | **60.18%** | 0 / 167,222 |
| B：增加目的端口 | 0.82490 | 67.06% | 59.84% | 0 / 167,222 |
| C：增加两端口 | 0.82549 | **67.29%** | 59.84% | 0 / 167,222 |
| 只看字段是否存在的对照 | **0.83202** | 68.36% | 57.12% | 0 / 167,222 |

增加端口精确值没有带来明确的整体提升。这里改变的是输入信息，并不证明所有端口建模都无效；当前结果不支持为它扩大训练。

本轮分组、训练行和正式决策与 v3.7 不同，不能把该表与旧 0.97885 直接相减来宣称提升或退步。

必须单列的错误：

- **ASA 可疑：**内部评价 733 条，三个候选均只正确分型 48 条（6.55%）；其余 685 条判成恶意。检测到风险不等于分型正确。
- **Duo 可疑：**10 条全部判正常；23 条正常未误报。低误报伴随全部风险漏检，不能验收。
- **WAF 可疑：**2 条全部判恶意；3,302 条正常未误报。这是风险已识别、类别仍错误，不是两条风险都漏检。
- **缺产品名的切片：**仍有 3,158—3,182 条恶意判正常。模型不直接读取产品名，但来源差异仍能体现在可见事实结构中。

以 C 为例，完整混淆矩阵为：

| 实际类别／预测类别 | 正常 | 恶意 | 可疑 |
|---|---:|---:|---:|
| 正常 | 167,222 | 0 | 0 |
| 恶意 | 3,158 | 6,790 | 142 |
| 可疑 | 21 | 687 | 1,055 |

零误报只描述当前切片，不构成其他环境的误报保证。

## 5. 最关键的反证：字段结构仍能解释成绩

负对照只使用事实是否存在，例如是否有动作、结果、协议或端口观察，不读取这些事实的具体值，也不读取日志正文、产品名或日期。它使用同一拟合职责和同一评价行。

它的 Macro-F1 高于三个候选。进一步检查 C 与该对照的判断一致率：

- 正常记录：100%；
- 恶意记录：98.26%；
- 可疑记录：97.16%。

因此，一致性不只是正常记录过多造成的。当前不能把 0.825 左右的成绩主要归功于模型理解了行为内容。

另做十次固定随机种子的诊断：只在事实可用性模式相同的行之间打乱原模型预测，C 的 Macro-F1 均值约 0.83496，没有下降。这是检查预测与标签在该条件下关联的随机化诊断；它会改变真实语义关系，**不是保持标签不变的反事实测试，也不是新成绩**。它进一步削弱了“内容值已经贡献了可靠额外区分”的解释。

这些证据不能证明每个预测都只用了缺失模式，也不能证明所有内容特征毫无价值；但足以阻止把当前候选升级为可迁移模型。

## 6. 回放、真实变换及工程问题

三个候选的 179,075 条评价预测逐条重算，共 **537,225 条模型预测**，保存概率与独立矩阵计算一致，类别差异为 0。

在 **4,790 条真实日志**上进行直接推理与指定包装变换，包含全部 **4,130 条 WAF**、**337 条 Duo**；每个模型覆盖 **21,169 对变换**，概率变化为 0，类别翻转为 0。这是共享的一批反例在三个模型上的检查，不是三份独立数据。

因此不能将本轮错误直接归因于这些已经实测过的外层产品、采集时间和包装变化。它们的控制已有证据；字段可用性与来源支持是当前更明显的问题。未测试的其他变换不在此保证范围内。

工程审查纠正了两类问题：

1. 本地新版 pandas 不再接受列表作为部分 factorize 输入；改成显式数组后训练完成。
2. 初次准备审计误用了 Series.product 属性，它实际是方法，导致“全部 WAF/Duo”抽样分支未执行。完整训练数据和特征构建未受影响；本次补充审计按列名显式选择，完成了全部 WAF/Duo 回放，并为后续准备代码修复该问题、增加回归测试。原审计记录保留，没有覆盖成虚假的全覆盖记录。

当前 11 项针对性软件测试通过；另外在冻结运行源码下重新载入三个模型，检查原始消息到三类输出的完整入口。源码通过 Python 3.8 语法检查；**没有宣称已验证平台旧版依赖可直接加载本地模型**。

本地实测依赖：NumPy 2.5.0、SciPy 1.18.0、scikit-learn 1.9.0、PyArrow 24.0.0。平台历史依赖版本不同，本轮没有新平台运行或依赖升级。

## 7. 六轮第一性原理审查与决定

| 审查 | 实际证据 | 结论 |
|---|---|---|
| 数据真实性 | 官方文件摘要及全行 ID／标签／消息核对 | 本轮输入完整，标签未改 |
| 编码保值 | 实际 C 编码器恢复 10,748 种 ASA hard 向量 | 编码修复落实，不能等同于学会分类 |
| 目标一致性 | 选择、预测、导出均为三分类，无报警门槛 | 旧决策目标错位已移除 |
| 包装依赖 | 真实变换与逐条模型回放 | 指定变换通过，模型质量仍未通过 |
| 成绩解释 | 可用性对照更高、风险类判断高度一致 | 当前主要成绩解释仍受结构捷径挑战 |
| 是否扩大训练 | Duo 零检出、ASA 分型差、组支持有限 | 停止平台全量训练，未启动阶段 D |

本轮完成了分类器训练和后续审查，**不生成平台训练执行包、不生成比赛 res.csv、不选一个失败候选冒充最终模型**。三个候选及负对照全部保留，以便复核。

接下来最小有效工作是，在允许开发数据内核查“相同字段可用性、相近事件语义、不同标签”是否有足够独立组支持，检验具体行为值带来的额外区分。只看字段结构就能分类的单标签切片不能证明这种能力；它们仍保留在全行评价中。未先查清这一点，不继续叠加类别权重、模型容量或新门槛。

该检查仍可先使用官方数据，无需立即寻找外部数据；但若缺少可观察判定依据，必须记录信息边界，不能从未见标签或虚构的实体时间关系中补答案。

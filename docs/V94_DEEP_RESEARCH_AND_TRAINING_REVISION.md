# v9.4：从错误放大追到训练证据与更新目标

2026-09-28。最新实际训练仍为v9.2；v9.3和本轮均未新增分类器/校准拟合。本轮补做冻结检查点组合重放、续训错误流向和训练行为支持审计，并查阅一手论文及作者实现。未替换模型、未使用平台或外部训练数据。最近完整开发回放仍为v7.9的5,947错。

**进一步结论：分数放大是失效机制的一部分，更底层的缺口是没有用足够独立的行为对照约束“更新应该向哪里走”。已有更新多数只证明见过的点能分开；同一批训练点的正确性约束不能证明边界可迁移。v9.3的“正则＋扩大保护人口”保留为对照，不再作为未经条件核查的完整主方案。**

下一轮推荐检验的是：保留原频次监督和完整输入，在有真实M/S对照的组件上，加入“在一组组件学完后，另一组组件是否变好”的训练目标；把输出幅度控制作为单独因素。不先换更大网络、不按当前错误重写标签或删字段。

## 1. 本轮新增实证：放大、方向改变与共同适配都有

v9.2中U0为初始非线性分支，U0R为其充分续训状态。与旧教师比较，U0内层新增348条M错误，U0R新增500条。逐行追踪500条的来源：

| 500条退化的组成 | 原行数 | 解释 |
|---|---:|---|
| U0时已经判错 | 260 | 续训保留了不良改判 |
| U0仍判对，但残差已朝S方向推 | 192 | 原教师优势当时尚能抵挡，续训后越界 |
| U0残差不朝S，U0R变为朝S并越界 | 48 | 存在方向改变，不能归咎于统一放大 |

另有88条U0原先损坏的M在续训后恢复，因此不是所有记录单向恶化。相对U0本身，续训新增244条M错误、恢复88条，净少判对156条；244还包含U0曾修复的4条旧教师错误，故不能与“相对旧教师新增240条”混为一个口径。

U0R的58条S修复中，34条U0已修好、24条为续训新增；U0另有6条S收益在续训中丢失。只报告40→58会掩盖这6条损失。M/S末层方向余弦0.981，方向相近但非相同，范数约扩大8.28倍；它与编码器变化共同作用，不是一个全局偏置就能解释。

### 1.1 编码器与决策头交叉重放

不拟合任何参数，组合两个已保存编码器和两个已保存末层，重新推理所有角色：

| 冻结编码器／末层 | 训练总错 | 内层总错 | 内层新增M/S错 | 内层修复M/S |
|---|---:|---:|---:|---:|
| U0／U0 | 94 | 498 | 348 / 0 | 4 / 40 |
| U0／U0R | 9,538 | 5,608 | 5,556 / 20 | 0 / 162 |
| U0R／U0 | 403 | 210 | 0 / 28 | 10 / 2 |
| U0R／U0R | 24 | 636 | 500 / 0 | 0 / 58 |

这些组合离开了原训练路径，不能凭它们宣布哪层具有唯一因果责任。实际能排除的是“直接换回旧末层就保留已有收益”：虽消除了内层M新增错误，却损坏28条S，只保留2条S修复；C/H也没有合格。表征与读出是共同适配的，末层复用不是现成修复。

v9.3已证实当前固定U0R分数的统一缩放也无法保58减500。本轮因此将问题拆成三个需分别验证的假设：分数幅度失控、更新方向缺少跨组件约束、有效对照支持不足。没有将三者合并归因给某个端口。

## 2. 更底层的条件：能记住，不代表有证据识别稳定规律

ASA训练区38,771条记录、3,236个组件，**3,199个组件只有一种标签（98.86%）**；混合标签组件37个。组件由已有正文分组与来源符号连接产生，构造函数不读取标签；旧划分中单组件格式/类别另有fit-only安排。

单标签组件既可能是合理攻击活动，也可能承载来源/模板关联。该统计**不能证明模型读取了组件ID或标签泄漏**。它提示：拿一个组件当一个“域”直接套领域对齐，可能把类别差异错当来源差异；保持组件完整只是隔离的必要条件，还需要实际可比的行为。

沿用v9.3审计定义，以已知动作、结果、协议、源/目的角色、目的端口构成粗行为组；未知字段保持未知，不补猜端口。在同一ASA训练区：

| 条件 | 实际数量 |
|---|---:|
| 粗行为组 | 2,502组 |
| M/S各自至少来自3个组件 | **5组** |
| 仅按A/B训练区确定，两处均有M/S | **3组** |
| 固定A/B/V划分后三处均有M/S | **2组** |
| 前述5组覆盖训练S | 887/6,673（13.29%） |
| 实际三处都有对照的2组覆盖训练S | 865/6,673（12.96%） |

固定划分使用种子标识9301和组件哈希，未按成绩搜索划分。ASA原行A/B/V分别含M19,644/6,296/6,158，S4,823/526/1,324；**60/20/20是哈希桶比例，不保证类别行数比例**。同组件重复行没有拆开。

“每类至少3组件”是本次三角色局部行为对照的必要支持检查，不是所有泛化算法的普适定理；粗行为相同也不证明业务语义等价。以上结果不能推出“87%的S都无法学习”，这些S仍有主分类监督，也可能从共享表示受益。但不能声称三角色对照已经覆盖它们，更不能通过过采样增加独立组件数。

最接近根本的未决问题因此是：**哪些输入差异确实跨组件支持M/S，哪些只是本批样本的关联？** v9.3的558条没有已知解析遗漏或同输入冲突，只排除了两类错误，未回答这个问题。数据可分不等于正确规则可识别。[领域适配可识别性研究](https://proceedings.mlr.press/v162/gulrajani22a.html)也明确把这种推断依赖的分布假设作为研究对象；本文不将其理论条件直接宣称已在SOC上满足。

## 3. 深度调研：成功经验、前提和本项目决策

### 3.1 MLDG：检验“更新之后能否迁移”，最值得做一个受控试验

[AAAI原论文](https://ojs.aaai.org/index.php/AAAI/article/view/11596)在PACS跨域图像与强化学习任务验证了训练中模拟域变化的思路。[作者代码](https://github.com/HAHA-DL/MLDG)是基于提取特征的MLP示例，依赖Python2.7/PyTorch0.3.1，不直接安装。论文成功不代表SOC成功。

其核心是先在组件包A更新，再评价更新后的模型在不同组件包B上的损失。仅将A和B同时塞进普通CE，不等于这个目标。已检查[DomainBed的MLDG实现](https://github.com/facebookresearch/DomainBed/blob/main/domainbed/algorithms.py)：克隆网络、在一组数据上更新、在另一组求梯度、合并更新；该实现明确使用一阶近似而不求二阶导数。DomainBed仓库当前已归档，作为算法参考，不引入其整套依赖或默认大搜索。

**采纳范围：**只在具有真实双类支持的完整组件包上构造辅助训练任务，先验证更新对另一包的M/S是否有益；仍用全部A+B原行主损失。A/B都属于训练，V才是选择角色。组件包是隔离代理，不包装成经过认证的真实企业域。仅两组行为满足本次A/B/V局部对照，先把试验范围和覆盖率写清，不宣称全范围解决。

### 3.2 LogitNorm：解决高分失真，不能替代正确分类

[ICML论文](https://proceedings.mlr.press/v162/wei22d.html)和[作者实现](https://github.com/hongxin001/logitnorm_ood)在训练损失内约束logit范数。论文一个CIFAR10→SVHN的OOD检测设置将FPR95从50.33%降到8.03%，是42.30个百分点；这不是SOC三分类准确率收益。

**吸收：**幅度与方向分开控制，保存原始分数和逐类翻转。主对照保留v9.3输出变化正则，先不再增加LogitNorm参数臂。正温度缩放完整三类分数不改变argmax，故仅校准概率不能修好分类错误；在训练中改变损失则需实测，不能把二者混同。

### 3.3 DFR：冻结表示后重训末层有成功条件，但本项目不能直接复制

[DFR作者项目](https://github.com/PolinaKirichenko/deep_feature_reweighting)给出的检查点在Waterbirds最差组准确率约92.0±0.9、CelebA约88.02±1.6。关键条件是可用表示和打破伪相关的重训数据。

检查[实际重训代码](https://github.com/PolinaKirichenko/deep_feature_reweighting/blob/main/dfr_evaluate_spurious.py)：分组采样至最小组数、分开拟合/调参、按最差组选择；部分配置为二分类。不能把缺组补成空数据，也不能删掉多数M来冒充我们要求的全原行监督。v8.9已做冻结表示读出且留出退化，本轮末层交叉重放也未通过；保留为定位方法，不把同名方法再次设为默认路线。[后续研究](https://arxiv.org/abs/2308.00473)也指出末层重训仍可能依赖伪相关。

### 3.4 JTT与学习样本权重：不是“错得多就越重要”

[JTT，ICML2021](https://proceedings.mlr.press/v139/liu21f.html)在四个视觉/语言任务中，通过早期模型发现错例再训练，平均弥合ERM与Group DRO最差组差距的75%；仍依赖验证选择。[作者代码](https://github.com/anniesch/jtt)。本项目U0R后期训练只剩冲突错误，拿后期错例加权会强调完全不同的问题，不能照搬。

[Learning to Reweight，ICML2018](https://proceedings.mlr.press/v80/ren18a.html)根据梯度与干净无偏验证目标的一致性确定权重。[作者说明](https://mengyeren.com/research/2018/learning-to-reweight-examples-for-robust-deep-learning/)明确指出此验证集的作用。我们没有已认证无偏的M/S验证来源，不把当前B叫“无偏金标准”。当前不新增重复降权、错例无限加权或标签清洗。

### 3.5 DomainBed与安全任务评测：强基线与选模本身必须匹配

[DomainBed论文](https://arxiv.org/abs/2007.01434)表明，公平实现和选择规则能明显影响领域泛化算法比较；复杂方法不自动优于ERM。[实现区分](https://github.com/facebookresearch/DomainBed)训练域内、留一域和使用测试域的oracle选择。采纳相同输入、保存预算、调参次数及独立角色；不使用oracle成绩给新方法背书。

[TESSERACT，USENIX Security2019](https://www.usenix.org/conference/usenixsecurity19/presentation/pendlebury)在恶意软件任务审查空间/时间偏差。吸收评测必须对应部署条件的原则；当前SOC脱敏时间未被确认保留真实关联，不把日期直接当攻击规律，也不宣称已完成真实时间外推验证。

所有外部效果仅说明方法在其论文条件下有成功证据。本轮没有安装这些项目、下载其数据或运行其基准。

## 4. 对v9.3方案的实质修订

| v9.3未充分解决之处 | v9.4修改 | 验证依据 |
|---|---|---|
| 主要通过幅度正则＋更多保护点改善边界 | 幅度控制保留为因素；新增跨组件更新目标作另一因素 | 48条方向反转、固定α无解，不仅是幅度 |
| 教师未见B，但候选在B上直接训练 | 明确B属于训练；用A更新后在B评价的辅助目标，并以V独立选模 | 普通A+B拟合不等于学到了跨组件更新 |
| 默认三角色能支撑主要切片 | 先固定支持表；只有2组满足本次双类三角色局部对照 | 不靠重划种子或拆组件凑结果 |
| 每一步都严格保旧正确容易再次停滞 | 正式模型冻结；训练候选允许中间越界，用软兼容项引导，最终快照严格检查 | v9.2已有满足P的优秀训练终点，却被P0路径卡住 |
| 优化器收敛与模型可选性纠缠 | 固定保存预算、V选分类结果；记录早停而不声称最优 | 更接近CE下界并未带来留出改善 |

**允许候选中间越界，不是降低上线标准。** 本轮不改变旧模型和最终逐类/负翻转门槛；它解除的是实验优化路径限制。新模型只有最终快照满足保护、修复及独立开发检验才可能晋升。零变化不能算成功。

## 5. 下一轮执行顺序与停止条件

### 阶段0：先固定训练协议，不追加模型

1. 延用本轮组件哈希，固定原fit内A/B/V；原fold −1的单组件格式/类别仍固定A，不能失去唯一训练支持。进一步生成全格式清单并检查组件、正文组和来源符号不跨角色。当前保存的角色文件仅覆盖ASA，不能冒称全项目清单已完成。
2. **只按A/B训练区的双类支持确定辅助训练范围：当前为3个行为组。** 其中2组也在V中具有双类评测支持；这是评测覆盖说明，不能用V标签的存在性筛选那3个训练组。V标签不参与训练错例、方向、权重或配对。其他行为仍全部进入主损失，并单独统计效果。
3. 先建立A内新教师及其明确的数据来源；所有四臂共享。不能复用见过B/V的U0R编码器或教师来声称角色隔离。其他格式保持一致参考并逐类回归。
4. 以相同数据上的原频次ERM为匹配对照。新A教师可能弱于既有完整fit教师，报告两条基准：V与其角色内教师比；原inner/C/H同时与既有v8.5教师比。不能靠打败更弱的新教师报成功。

### 阶段1：一个教师＋四个小分支，变因清楚

| 臂 | 训练期输出变化正则 | 跨组件更新辅助目标 |
|---|---|---|
| E00 | 无 | 无，匹配ERM |
| E10 | 有 | 无 |
| E01 | 无 | 有，MLDG式一阶更新 |
| E11 | 有 | 有 |

四臂保持R0、64/16层、ASA修正范围、主CE原频次、初始化与评价角色一致。全部A+B M/S均进入主监督；原件和其他格式不删。重复只做保频次聚合，不能据此降低总权重。真正全量训练才使用全部官方M，包括32,596条native_flow M。

四臂采用相同软兼容项，作用于本角色训练标签确认旧正确的P_A∪P_B，旧错误不模仿教师。最终严格正间隔与负翻转检查也相同，不再把“扩大保护人口”与算法变因混在一起。

输出正则沿用v9.3待验证定义，注意ASA/全人口分母一致。跨组件目标的示意是 `L_A(θ)+β L_B(θ−η∇L_A)`，同时保留完整A+B主CE；实际采用一阶近似时明确记录，不冒称二阶精确目标优化。辅助项仅限登记的真实支持范围；A/B交替承担内更新和反馈，两边均属于训练。

组件包都要有M/S，不能将98.86%单标签组件逐个当完整多类域。主损失保持原行权重；辅助项若按类/组件均衡，其额外目标与权重须单独登记，不伪称未改变目标分布。未知端口不补猜，身份/时间不添加为模型特征。

先用真实训练子问题验证梯度符号、克隆更新没有写回教师、稀疏反传和各臂预算，再固定η、β、兼容系数、优化器、保存间隔和总步数。不得在读取inner/C/H成绩后追加参数网格。基础模型训练和每个分支计数分别保存；本轮尚未实施训练器，不虚构训练次数或完成时间。

MLDG每次更新需要更多梯度计算，因此既报告相同原行曝光的结果，也报告时间/梯度计算量，不称算力完全等价。先完成这一组最多5次拟合，失败臂不扩折。没有合格快照时保留旧模型，记清是求解失败、拟合缺口、改判排序失败还是支持外失效。

### 阶段2：用实际分类结果决定是否继续

- 按B/M/S分别报告支持、正确数、召回、精确率、F1、原错修复和原对改错；保留每个格式与组件统计，不能只看总准确率。
- 保存旧58条收益、500条退化的逐行回归，并另列所有新错误。额外保存“早期正确→后期错误”的流向，避免再次用净变化掩盖退化。
- V用于有限次数选择和停止点，配置冻结后检查旧inner/C/H；全部仍是开发，不称新盲测。支持内两组与支持外行为分开报告，不用局部成功替代全任务。
- 选择同时要求真实修复、最终训练P保护、开发各类指标不降及旧正确无新增错误；原全任务门槛不变。用组件重抽样估计差异，不把重复记录当独立证据。
- 通过首轮才轮换教师/候选角色、做至少两折收益检查以及完整任务推理。尚不全量训练，不下载外部数据，不向官方无标签验证文件猜标签。

### 阶段3：失败也必须改变决策

| 结果 | 下一步 |
|---|---|
| E10降低幅度但不改善改判排序 | 不继续搜索同类缩放；限制幅度仅留稳定性用途 |
| E01/E11仅在A/B变好、V不变 | 跨组件辅助目标未证实有效，停止扩训，不把元学习名称当突破 |
| 支持内改善、支持外退化 | 先查共享参数干扰与适用范围；不能按V标签直接训练“放行门” |
| 支持内各方向也失败 | 回查具体可读差异及语义，必要时一个冻结表征/读出诊断；不自动重新跑已失败DFR式大扫参 |
| 正确类别缺少独立样本/语义依据 | 保留监督和明确缺口；在“仅官方数据”约束下不能凭重复、伪标签或虚构反例宣称补齐 |
| 中间出现退化，最终恢复且全部门槛通过 | 认可最终结果，不能再用中间越界否定实际合格模型 |

## 6. 多轮对抗性审查

第一轮审查归因：交换编码器/头是离路径诊断，不能据此判某层唯一负责；模型分数高也不是真实正确概率。500条的三种流向都保留，不能全归“过拟合放大”。

第二轮审查研究迁移：DFR有平衡反例条件、JTT有早期错误与验证条件、LogitNorm主要验证OOD检测、MLDG不保证SOC有效。对已失败或前提不足的方法明确不照搬；“成功论文”不等于本任务已有成功。

第三轮审查数据角色：A/B参与梯度均属训练，V不参与；候选用过的标签不能再称独立泛化。两组有对照不等于全部行为有对照。98.86%纯组件不是标签泄漏证明。

第四轮审查保留收益：正式模型一直冻结；中间训练可改动，最终样本级/逐类保护仍严格。新教师弱化、旧收益流失、删字段后新增错都纳入检查，不只报告局部恢复。

第五轮审查可执行性：先做最多5次登记拟合，固定预算及停止条件；不把稀缺切片无支持解释成模型一定无能，也不把所有失败都推给官方数据。优化方案尚待训练结果证明。

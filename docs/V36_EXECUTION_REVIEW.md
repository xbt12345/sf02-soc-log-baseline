## 1. 最值得关注的实际结果

最终表示为 v36-representation-1.3。下表每格依次是“可疑类正确分类条数；正常被错分成恶意或可疑类别的条数”。三类按模型最大概率分类，不是独立阈值的报警结果。

| 场景 | 匹配 B0 基线 | B2 正文＋事实 | B2-W 有界权重 |
|---|---|---|---|
| AD 整来源 | 0/473；0/809860 | 473/473；1205/809860 | 473/473；892/809860 |
| Duo 整来源 | 0/12；0/325 | 2/12；0/325 | 12/12；0/325 |
| WAF 整来源 | 0/2；0/4128 | 0/2；0/4128 | 0/2；0/4128 |
| ASA 困难模板 | 0/3473；无正常支持 | 0/3473；无正常支持 | 0/3473；无正常支持 |

AD 的加权候选正常误判率约 0.1101%，可疑类召回 100%；但可疑精确率只有 473/(473+892)=34.65%。严重不平衡时，看“正常判断很准”和召回率仍会误导。Duo 结果改善只有 12 条、三个可疑输入组，不能据此承诺任意新来源。

ASA 的 3,473 条可疑都被判成恶意：属于三分类区分失败，不能写成未报警。WAF 的两条可疑只有一组，三分类仍全部判正常。全部旧失败都保留，未通过删样本掩盖。

来源覆盖开发抽组的 Macro-F1：B0 0.960525，B1/B2/B2-W 0.961136。这个小幅总体变化不能代表来源迁移成功。

模型输出的分数仍是针对官方标签的分数，没有完成真实攻击概率校准。下一步必须保留分类与报警两套验收，而不能用更换名称或事后目标阈值让一套问题消失。

## 3. 发现的问题怎样处理

| 问题 | 已落地的处理 | 当前边界 |
|---|---|---|
| 产品为空、来源名字直接提示类别 | 预测只接收消息；产品/缺失标志不进入模型或推理路由 | 正文隐含来源仍可能影响模型，不能只凭列删除宣布解决 |
| 时间段近乎决定类别 | 排除外层时间；处理有边界的采集头、损坏时间残片；保留确认为时长的字段 | 未确认的正文时间与真实跨事件时钟语义仍不作保证 |
| 标识符、包装、上游意见进入特征 | Windows ID 槽规范化；WAF 正文/分隔符分开；限定根级敏感性/标签元数据隔离 | 未支持布局保留诊断，不能泛化成所有字段已清干净 |
| 过度清洗也会丢失正常证据 | 核实提供程序和事件位置后保留 Windows 认证观察；补回 105,101 条成功事实 | 不恢复损坏字段名、不据事件码直接赋比赛标签 |
| 后部 Windows 容器损坏使完整正文被忽略 | 46,178 条恢复正文路径，含 24 条可疑；另 54 条清除根级意见/标签元数据 | 修复针对实际边界，不猜补残缺 JSON |
| 原 75 个同文异标签组 | 原标签、所有行及损失保留；同组不跨职责；同时输出冲突统计 | 不可观测差异不会靠算法消失，不能多数票改标或删难例 |
| 大量重复、空消息与类别不平衡 | 真实行频率的等价计算；一个有界权重对照；全行、类、来源、组与空记录分别计分 | 加权不是自动胜出，空事件编号不算独立检测证据 |
| 拟合/选参/校准/评价泄漏 | 每种学习统计只用允许职责，目标来源不进前三步；新分组下重训匹配 B0 | 已经看过的本项目评价仍是开发证据，未证明独立事件/外部泛化 |
| 字段依赖看起来像模型能力 | 实际元数据变换、单事实字段删除、N 格式对照、完整来源留出 | 删除真实事实未必保持标签；不翻转也不能证明没有捷径 |
| 全判正常也很高分 | 必报逐类、精确率、漏报、误报和全部正常对照，不以准确率放行 | WAF/ASA/阈值仍失败，未晋升最终模型 |

最终全量 2,056,871 行 ID/标签一致，联合组 494,116。旧文本混标 75 组/4,075 行，新抽象 215 组/23,220 行；全部在 ASA。新增冲突来自把具体 DMZ/ACL 环境差异抽象掉，并非证实“原标签错了”。经验最少错误从 1,116 到 2,510，是当前表示选择下的统计，不是现实安全任务的定理。

## 4. 多轮对抗审查怎样改变了实现

1. **输入与监督边界审查。** 针对日期、产品缺失、实体、未核实上游结论、载荷操作符、原始事件身份构造反例；第一次全量审计暴露 215 个新冲突组，逐组定位到 ASA 环境抽象。
2. **首轮真实配对试训。** 15 个模型/45 次拟合显示结构事实可恢复部分 AD/Duo 检出，同时正常误判恶化。没有把好看的域内分数当成通过；进一步修 Windows ID、系统日志时间头和渲染正文。
3. **正常反例与学习目标审查。** 区分“完整原生观察”与“脱敏标签猜测”，增加受文档约束的成功/失败语义。完成 20 个模型/60 次拟合及唯一有界重复权重对照，发现校准迁移仍失效。
4. **错误样本反查。** 在实际错误中找到损坏 Windows 容器导致的旧回退字段残留，修复 46,178 条正文路径和 54 条元数据；重新建立全部组与职责，再完成最终 20 个模型/60 次拟合。不是把所有问题归咎于标签或换个模型名字。
5. **还原、预测和评价复核。** 从最终单文件还原运行源码，38 项软件反例通过；重载最终 20 个模型逐条回放概率、复算选择和阈值，并检查实际元数据变换及单字段依赖。它证明本地结果可复核，不证明云端/真实环境验收。

这些是不同攻击面上的实现和证据检查，不能代替外部环境的质量验证。

## 5. 本地试训的局限与下一步决定

本地为控制内存，只在拟合/选择/校准职责中取固定组数并排除超过 1,000 行的大组；known_dev 评价也抽组。AD/Duo/WAF/ASA 的目标评价保留完整目标。该设计用于发现错误、比较方向，不代替全量拟合或自然总体比例验证；小样本校准的迁移问题必须在平台全量重新量化。

保留 B0 作为匹配基线，保留 B2 与唯一 B2-W 作为有局部证据的候选。纯 B1 的迁移收益不足，不继续扩大。平台执行五项任务、15 个最终模型、45 次拟合，重点是确认全量数据和重复权重的影响，继续完整报告 WAF/ASA 失败。没有增加更多 C、逐产品专用模型或目标标签调参。

当前官方数据足够继续做这种配对核验，**不足以证明任意新环境具有可靠的三分类和万分之一级误报**。本轮暂不添加数据。若全量后仍失败，应针对定位结果评估新的语义表示、参数关系或明确的目标适配条件；不能通过不断重跑、伪标签或目标阈值追分。对缺失的事件上下文和类别规则，保留“无法判定”，不谎称算法已经解决。

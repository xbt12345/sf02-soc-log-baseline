## 1. 第一性原理：四件事必须分开验证

可靠判断至少需要：原日志包含证据 → 解析保留该证据 → 编码器实际表达该证据 → 拟合数据支持学习其含义。

| 层次 | 这次实际发现 | 处理状态 |
|---|---|---|
| 原文到事实 | 3,188 条 native_flow 的厂商动作编码已被读取，却未转换为动作 | 已修复 |
| 事实到向量 | 全部允许开发记录的现有事实键和值均有编码位置，未发现额外未知键/枚举静默丢弃 | 已核查其边界，不能反推前面的解析完整 |
| 正文到向量 | 33 条认证记录有正文，但当前拟合词典将其全部编码为零文本向量 | 新确认的编码缺口，尚未更换词典 |
| 向量到学习 | 无响应、策略允许等部分事实有固定列，但拟合侧没有激活；压力协议没有任何认证路由拟合记录 | 新确认的支持不足，不能用扩大词典冒充已经学会 |

因此，“保留原文”“向量非零”和“能可靠区分攻击”不能相互替代。现场不存在的上下文，当前任务也不能通过猜测补成训练事实。

## 2. 已落地的输入修复

`training/v48_input.py` 是旧冻结解析器之上的新适配层，同一函数服务于训练准备和真实原文推理。旧运行依赖未修改，训练使用结果目录中的冻结副本。

- 在完整、已识别的旧式 Meraki 原生语法内，解释 `pattern: 1 all`、`pattern: 1 dst <有效 IP>` 等已观察形态；1 对应拒绝，0 对应允许，文字 allow/deny 使用对应语义。厂商明确给出了入站规则 1/0 的动作定义：[Cisco Meraki 官方说明](https://documentation.meraki.com/Platform_Management/Dashboard_Administration/Operate_and_Maintain/Monitoring_and_Reporting/Syslog_Server_Overview_and_Configuration)。`dst` 只界定规则匹配范围，地址不进入风险特征。
- 数值只在该动作槽位解释，不从任意文本找 1、不从设备名推断类别。未知数字、未支持的规则尾部及无效地址保持未解释。当前版本不扩大到新固件格式、任意地址前缀或其他规则表达式。
- 显式动作与规则动作冲突时，两项原始证据均保留，冲突的 action/outcome 不进入风险特征；不按有利标签挑选一个。未知规则也不会抹掉独立且明确的原生动作。
- 对 4,286 条 native_flow/native_firewall 记录保存原文 SHA、字段区间、解释依据及“进入模型 / 仅审计 / 未解决”的处理记录。原文仍在官方文件，记录通过原始行位置关联。
- 真实源/目的端口、协议、ICMP 参数保持原有观测精度；脱敏端口不补猜。产品、身份、绝对时间及外层标签不参与这次风险输入。

3,188 条修复包括 2,624 条 `all` 和 564 条 `dst` 形态，其中拟合侧 8 条、压力侧 3,180 条。新增 322 个修正后的投影，按原始行重新关联，避免直接修改共享旧投影时误伤其他记录。

原文扩查包括全部允许开发的 ASA、原生流/防火墙、VPC、聚合认证、audit_fields 和 CEF，以及此前保存的代表性案例。125,878 条均能重现旧准备事实。对其前后字段变化做了清单：例如协议改为 transport_protocol、真实端口转为固定整数编码属于转换，category 的主动排除属于既有边界，不能把字段改名算作丢失。

额外核查了 audit_fields 的 proctitle/argc/syscall 等可能遗漏点：本批该路由未捕获到这些可直接恢复的槽位；只发现 2,679 个 arch 槽位。不能把理论上可能有内容的字段宣布为本批已经发现的有效信息损失，也没有据此增加新特征。

## 4. 为什么没有继续扩训

拟合前冻结的要求包括：正常错误不增加、Macro-F1 上升、总错误下降、恶意判正常不增加、native_flow 之外错误不增加、各类召回下降不超过 0.02、优化器收敛。

**范围外错误 844→846，没有通过。因此只训练了 1 次，原三折 3 次拟合没有启动。** 没有在看到结果后放宽规则，也没有为了恢复两个旧答案按来源拼接模型。

退化两条均为不同正文组的 `invalid_passcode denied` 认证日志，原文事实与最终数值向量前后完全一致；词典、IDF 和事实缩放也相同。概率变化：

| 概率 | 原 B | 新模型 |
|---|---:|---:|
| 正常 | 0.497620 | 0.503869 |
| 恶意 | 0.002652 | 0.001974 |
| 可疑 | 0.499728 | 0.494157 |

原预测本来就在边界附近。可疑相对正常的对数分数差从 +0.004228 变为 −0.019465。截距变化贡献 −0.159568，特征权重变化合计抵消 +0.135875；两者之和精确重现翻转。这是共享权重变化与支持不足的具体表现，不是新解析器把两条原文删坏了。

其中，认证事件没有实际端口或 ICMP 槽位，却被旧通用编码器填入端口、ICMP、HTTP 状态等缺失位。缺失位参与了上述分数变化。这些位并不是实际观察到的网络行为；后续需要区分“不适用”和“本来有该槽位但已脱敏”。仅有这次分解，还不能声称删掉缺失位就一定提升分类。

## 5. 剩余错误和下一步唯一优先方向

| 路由 | 新错误 | 下一步需要区分的问题 |
|---|---:|---|
| ASA | 827 | 原始事实不足、同表示冲突和学习不足分别定位；动作修复未改变这些决策 |
| native_flow | 48 | 全部恶意被判可疑，已不存在该路由恶意判正常；继续查具体事实及拟合支持，不再当作动作丢失 |
| authentication | 10 | 正文全零、同路由拟合支持为零，且不适用字段缺失位干扰分数 |
| bounded_payload | 5 | 逐条核查必要正文与标签所需上下文 |
| CEF / Windows | 各 2 | 保留为小样本专项，禁止用全局分数掩盖 |

新的主方向是：**保留本次动作修复，先补编码覆盖与事件字段适用性，再验证跨来源语义共享。** 不重回 ASA 阈值扫描，不用增加模型规模代替输入审查。

执行顺序及停止条件：

1. **先做不训练分类器的编码修复验证。** 按事件实际证据区分“观察到值 / 槽位存在但不可读 / 该事件不适用”；明确事实的数值精度与观察到的零必须保留。不适用字段不再被伪装成一组网络缺失值。缺失状态仍留在审计记录，不使用产品名决定风险。
2. **修复正文覆盖时保留细节和关系。** 保留原技术词，同时增加有明确边界的词内分解候选；否定、动作对象、结果与原因不能被拆成无关系的普通关键词。只使用拟合侧词典。必要时再比较字符特征，但“能表示陌生词”不代表已学到其安全含义。scikit-learn 官方文档说明了词典和哈希编码的机制及哈希碰撞代价：[特征提取说明](https://scikit-learn.org/stable/modules/feature_extraction.html)。
3. **先看语义支持，再决定是否训练。** 对有效事实列列出拟合侧类数和独立正文支持。训练中从未激活的专属事实，不能因为评价时有列就宣称可识别；不把已看过的 Duo 评价标签搬进拟合侧修补留出成绩。
4. **各项改变单独对照，不一次叠加。** 先验证字段适用性修正，再按必要性比较词内/字符编码；每个候选先做一次固定旧压力训练。接受规则继续同时约束流日志收益、正常误报、认证退化及逐组结果，通过后才进入三折回归。尚未实施或执行这些新候选，不能把本报告当作它们已有效的结论。

本轮做了一个不训练的词内分解诊断：`invalid_passcode denied` 拆词后只有 invalid 与旧词典重叠；`no_response denied` 只有 no 和 response；`allow_unenrolled_user` 只有 user。向量可以非零，但残留的是局部词，尤其 user 缺少允许策略的含义。**因此否决“拆下划线后只要不为零就算问题解决”的简化验收。**

ASA 压力评价中的同输入标签冲突至少要求 204 条错误，而模型错 827 条。这是当前表示、当前已看数据的有限计数；其余 623 条差额不是可保证获得的收益，也不能把 204 条直接宣布为原始错标或不可约噪声。普通三折的历史上界与当前压力协议不能混算。

继续只用官方数据。现有数据足够做上述表示和有限模型对照；没有同族正常样本的路由，不能独立证明未知环境迁移可靠。暂不寻找外部数据，不需要用户操作平台。

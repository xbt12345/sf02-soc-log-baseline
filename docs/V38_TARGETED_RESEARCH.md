# v3.8 专项复审：ASA 编码、报警决策与来源迁移

日期：2026-09-13。对象：SF-2026-02、v3.7 回传修复模型及固定预测。依据官方题目、冻结源码、实际开发诊断和一手文献。本次未训练新 SOC 分类器，未启动平台任务。

## 1. 方向修正

**取消“比赛类别必须先通过报警门槛”的前提；先修 ASA 编码损失，再在共同输入和切分上验证三分类学习。** 报警保留为可选业务输出及误报诊断。

重新阅读题目原件后确认：提交类别为 benign、malicious、suspicious；没有第四个“报警”类别，没有要求两阶段模型，也没有规定 0.1% 误报门槛。题目列出准确率、召回、F1、AUC 等评价方向，未给出唯一排名公式。0.1% 是我们自行引入的工程目标，不能凌驾于题目目标之上。证据：[原件核查](../evidence/2026-09-13/v38_targeted_research/official_contract_review.json)。

旧方案“先二分类风险，再条件分型”尚未实施，本次撤回其主候选地位。两阶段结构本身并非必然无效，但当前没有证据支持将其设为必经步骤。[修订前快照](../evidence/2026-09-13/v38_targeted_research/plan_before_research.md)保留历史，当前计划见 [V38_NEXT_PLAN.md](V38_NEXT_PLAN.md)。

第一性原理检查顺序：可观察事实 → 解析表示 → 编码向量 → 学习分数 → 最终类别。输入合并的信息不能靠分类头恢复；表示可区分不等于模型已学会关系；排序良好也不保证门槛适用于新来源。

## 2. ASA 的损失及实际编码实验

ASA hard 共 66,269 行，恶意 62,796、可疑 3,473。v3.7 编码前正文与事实有 10,748 种表示，进入实际模型后只剩 1,406 种向量。38,769 行已观察源端口、25,044 行已观察目的端口的类别不在拟合词表。

实际 DictVectorizer 为字符串事实建立词表，变换时忽略未见类别；正文词表也不能表达未见词。已检查项目所用 1.3.2 源码并核对[官方文档](https://scikit-learn.org/1.5/modules/generated/sklearn.feature_extraction.DictVectorizer.html)。这不是上传或模型文件损坏。

对于相同向量组，计算“行数减最多标签行数”并求和，得到固定表示的经验最少总错误。它只约束**这批数据上、仅根据该向量做固定类别判断的分类器**，不是外部错误率预测，也不是可疑召回上限。

本次定义固定整数域编码：端口 0—65535，缺失哨兵 65536，每端口 17 位，两端口 34 维。映射不依赖标签或目标类别清单，65,537 种单端口状态全部往返还原通过。它编码实际整数，不是给训练中出现的类别先编号。

| 表示 | 不同向量数 | 相同向量下的最少总错误 |
|---|---:|---:|
| v3.7 冻结编码 | 1,406 | 3,246 |
| 追加源端口固定编码 | 8,382 | 2,683 |
| 追加目的端口固定编码 | 4,992 | 2,558 |
| 追加两端口固定编码 | **10,748** | **1,776** |
| 只追加端口三大范围及缺失 | 1,973 | 3,118 |
| 追加 2²⁰ 维带符号事实哈希 | 10,746 | 1,782 |
| 编码前完整准备表示 | 10,748 | 1,776 |

证据：[编码实测](../evidence/2026-09-13/v38_targeted_research/asa_codec_probe.json)。

**本次恢复了这批 ASA hard 在编码阶段额外损失的区分信息，消除了 1,470 个编码新增的错误下界；没有证明纠正了 1,470 条预测。** 哈希仍发生合并，额外增加 6 个最少错误。

位编码只负责保值，不赋予安全语义。端口数值接近、二进制位相似，不能推出攻击相似。完整预留 one-hot 列也不能使训练从未观察的列获得有效权重。精确源端口可能反映环境或生成方式，故固定编码先作为损失诊断和有界候选，必须比较无精确端口、仅目的端口、两端口三个同条件分支。

协议、端点角色、明确动作和结果继续保留；传输协议与应用协议分开。[IANA](https://www.iana.org/assignments/service-names-port-numbers)提醒，已登记端口不保证流量安全，也不保证实际使用对应服务。高端口不能自动判正常，443 不能自动等同于正常 HTTPS。

编码前仍有 1,776 个经验不可分错误。先前核查的原始 ASA 同文没有异标签，规范化后的冲突不能直接等同于原始错标。ASA 106023 在 [Cisco 原厂说明](https://www.cisco.com/c/en/us/td/docs/security/asa/syslog/asa-syslog/syslog-messages-101001-to-199021.html)中表示 ACL 拒绝流量，持续同源事件才可能提示扫描；单条拒绝不足以补全 malicious/suspicious 的判定依据。未确认时间和实体关联可信度前，不能拼造攻击链。

## 3. 门槛失效的具体原因

v3.7 正式规则为 r = 1 − P(benign)；r ≥ τ 时，在 malicious/suspicious 中取较大分数，否则输出 benign。τ 来自校准正常分数经验分位数，再取各校准来源门槛最大值。该规则解决校准侧预设误报预算，没有直接优化完整三分类。

| WAF 项目 | 风险分数 |
|---|---:|
| 最终门槛 | 0.00016709326500186086 |
| 校准正常最大值 | 0.00016709326500186084 |
| 留出 WAF 正常最小值 | 0.00021950923326796712 |
| 留出 WAF 正常最大值 | 0.0008106052330629776 |
| 两条 WAF 可疑记录 | 0.19010966511008953 |

4,128 条正常 WAF 因而全部超过门槛。此门槛等价于要求正常记录的模型正常分数超过约 99.98329%；这些分数不能直接视为可信的真实概率。

三个已证实问题：

1. **跨来源分布改变。** 留出 WAF 的正常分数全部超出校准正常范围。校准来源中的最坏情况不覆盖未进入校准的来源。
2. **选择与输出不一致。** 正则参数选择用三分类 argmax 的 Macro-F1，最终却使用报警后分型，未完整评价最终规则。
3. **单一约束代替完整目标。** 满足正常误报上限的门槛往往不唯一；现规则没有同时解决风险漏检、分型和来源失配。

微小浮点差异解释不了整来源误报。旧数值回放中的诊断尾概率问题须单列。现有 NP 诊断门槛仍使 WAF 4,128 条、Duo 62 条正常报警，换统计门槛名称没有修复它。

不能看过当前 WAF 分数后挑一个恰好分开的常数再报成绩。[Ovadia 等的 NeurIPS 研究](https://proceedings.neurips.cc/paper_files/paper/2019/hash/8558cb408c1d76621371888657d2eb1d-Abstract.html)表明，分布变化下常用后校准方法仍会失效；该文支持风险判断，不替代本项目验证。

## 4. 去掉报警之后是否已经有可用规则

**没有。** 本次完成五个修复模型的决策对照，没有重新拟合分类器。

比较原始三类最大分数与简单联合决策：对 log 概率加两个类别常数后取最大值。常数仅在原校准侧，从预定义 81 组组合中选择；载入对应评价分数前保存。评价集此前已看过，因此是开发诊断。校准成绩参与选择，不是独立验证。

| 开发切片 | 原报警规则 | 取消门槛直接 argmax | 校准侧选择类别偏置 |
|---|---|---|---|
| known_dev | Macro-F1 0.97885 | 0.65926；恶意正确识别 0 | 0.79700；5,848 条可疑被判恶意 |
| AD | 可疑 473/473 | 可疑 0/473 | 可疑 0/473 |
| Duo | 正常误报 62；可疑 12/12 | 正常误报 0；可疑 2/12 | 同左 |
| WAF | 正常误报 4,128；可疑 2/2 | 正常误报 0；可疑 0/2 | 同左 |
| ASA hard | 可疑 0/3,473 | 可疑 0/3,473 | 同左 |

来源切片缺部分标签，故不填伪完整三类 Macro-F1。[实测及全混淆矩阵](../evidence/2026-09-13/v38_targeted_research/decision_probe_results.json)。

这否定两个具体候选：“只删门槛”“在当前校准集加两个常数”。没有否定所有三分类、类别平衡学习或层次分类方法。下一步须修输入，使训练、内层选模和最终输出针对同一三分类规则。

## 5. 一手资料和开源方法的取舍

优先读取原厂定义、对应版本源码、原作者项目和正式论文。没有已被本项目证实的“市面最好模型”；以下按失败机制筛选。访问日期为 2026-09-13。

| 渠道／方法 | 吸收与边界 |
|---|---|
| [DictVectorizer](https://scikit-learn.org/1.5/modules/generated/sklearn.feature_extraction.DictVectorizer.html) | 已定位静默丢失；固定值域事实不能依赖训练词表才存在 |
| [FeatureHasher](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.FeatureHasher.html) | 无词表但有碰撞，未见桶无自动语义；本次实测不作为无损主修复 |
| [Category Encoders BaseN 源码](https://contrib.scikit-learn.org/category_encoders/_modules/category_encoders/basen.html) | 先拟合类别序号，再编码；默认未见类别共享处理，不等于固定端口整数编码，不能直接安装替换 |
| [rtdl-num-embeddings 原作者项目](https://github.com/yandex-research/rtdl-num-embeddings) | 连续数值表示可供有依据的时长、字节数后续参考；端口不是天然连续安全量，本轮不引入深度网络 |
| [Google Research Logit Adjustment](https://github.com/google-research/google-research/tree/master/logit_adjustment)、[论文](https://arxiv.org/abs/2007.07314) | 吸收显式处理类频率的思想；原实现主要展示长尾图像实验，不能称 SOC 或 Macro-F1 最优。本次常数偏置探针不是论文完整复现 |
| [ICML 多分类复杂指标优化](https://proceedings.mlr.press/v37/narasimhanb15.html) | 区分概率学习与混淆矩阵目标；用最终类别选择模型，不能认为 argmax 自动优化 Macro-F1 |
| [scikit-learn 决策门槛](https://scikit-learn.org/1.5/modules/classification_threshold.html) | 吸收预测与业务决策分离、隔离数据调门槛原则；文档二分类工具不是当前环境直接可用的三分类修复 |
| [ICML Temperature Scaling](https://proceedings.mlr.press/v70/guo17a.html) | 正温度缩放不改变 argmax，不能修复向量合并或直接纠正分类错误 |
| [NeurIPS Dataset Shift 不确定性研究](https://proceedings.neurips.cc/paper_files/paper/2019/hash/8558cb408c1d76621371888657d2eb1d-Abstract.html) | 校准侧误报率不能继承为新来源保证 |
| [ICML 不变表示的域适应限制](https://proceedings.mlr.press/v97/zhao19a.html) | 不变性不足以保证目标正确；包装压力测试之外还需类别条件分布和行为覆盖检查 |

六份源码／README 快照及 SHA 见 [sources/receipts.json](../evidence/2026-09-13/v38_targeted_research/sources/receipts.json)。scikit-learn 固定 1.3.2 标签；其他仓库是当时分支文件快照，没有宣称固定到未核验提交。未安装这些新包，未执行项目演示训练或下载外部训练数据。

## 6. 六轮反证与修订

这是本会话的六轮假设检查，不是六次独立训练或六位独立评审。

| 轮次 | 假设与反例 | 修订 |
|---|---|---|
| 1：目标 | 报警必为主分类步骤？题目只要求三类 | 撤回二分类优先；0.1% 改为历史参考，正常误报仍完整报告 |
| 2：实现 | 事实保留在 JSON 就能用？未见端口被忽略 | 检查实际向量；固定域编码已有局部保值实证 |
| 3：新捷径 | 精确端口找回就学会攻击？位相似无安全含义 | 精确端口分支必须接受来源、未见组合与有效反事实检查 |
| 4：开源适配 | BinaryEncoder／Hashing 能否直接无损？序号词表、哈希碰撞反例 | 不按名称套工具；冻结值域映射，明确未知和缺失 |
| 5：决策 | 去门槛／调偏置能否解决？实测漏检与类别互换 | 不发布旧模型简易新规则；修输入后再联合三分类训练 |
| 6：验证 | 校准 F1 近 1、大量行是否证明迁移？来源失效、ASA hard 仅一联合组 | 报告组支持；已看结果只作开发回归，不构造伪独立置信区间 |

保留之前屏蔽 authentication 类别独立特征的局部证据：known_dev 正常误报 39→0，Duo 62→0，可疑检出不变；WAF 和 ASA 未改善。下一版要在源特征中移除泛化类别独立证据，检查正文绕行，并重训复验。

官方数据足以继续查编码、特征绕行与开发侧学习；仅靠这些数据尚不能证明任意新 SOC 环境的准确率，也不能补出缺失的策略与类别定义。具体顺序和停止条件见 [修订训练方案](V38_NEXT_PLAN.md)。

# v3.9 执行结果：协议已修正，局部改善有效，迁移问题仍未通过

更新：2026-09-13。按用户授权完成 v3.9 计划的本地执行与逐阶段反证检查，只使用官方训练集。**本轮有真实训练结果，但整体质量未通过，不扩大平台训练，不生成比赛提交文件。**

最重要的结论是：新分组下约 0.959 的 Macro-F1，主要反映评价问题的改变；相同新协议下语义修复的真实增益只有约 0.000214。换回旧模板/来源压力协议，主要问题仍然暴露。没有证据支持“已经解决字段捷径、具备普遍迁移能力”。

## 1. 实际做了什么

- 原始训练集 2,056,871 行逐行核对事件 ID、标签与消息摘要；原文件及原标签未改。
- 允许开发池保持 1,378,650 行，新建 508,823 个完整正文/原文身份键；原外层评价行未进入拟合。空消息不假定共享同一个事件身份。
- 拆开正文重复与粗模板分组，保存固定三折。已核对非空原文重复及完整正文键跨折重合为零。3,257 个旧联合组被拆成多个正文键；没有新正文键跨越多个旧联合组。
- ASA code 13 的 865 行保持两个正文键；WAF 两条同原文可疑保持同组。正文键仍不等于已验证的独立事件。
- 同协议完成旧 C、语义修复、字段可用性对照，各三折，保留九个比较模型。每次拟合使用原行次数，不做重复降权、类别重采样或报警门槛。
- 追加时间变换检查发现一个部分脱敏的时钟残留，修复后替换三折语义模型；旧 C 和可用性模型经输入、行、分组完全一致检查后复用。
- 主开发结果满足预先声明的有限推进条件后，额外做一次旧模板/来源压力协议拟合。

**实际总拟合次数为 13：九次首批拟合、三次缺陷修复后的替代拟合、一次压力拟合。** 当前比较使用九个模型，另有一个压力模型；三个旧语义模型保留为失败证据，不按成绩挑选。没有辅助配对训练，没有启动大模型或非线性扩展。

准备与角色证据：[最终全量准备](../artifacts/v39_local_r2_20260913/prepared/audit.json)、[逐行分组与角色](../artifacts/v39_local_r2_20260913/prepared/rows.parquet)、[训练前方案快照](../artifacts/v39_local_r2_20260913/prepared/approved_plan.md)。

一个有跨正文组支持的 Windows 正常/可疑切片三折都降低错误，其条件排序 AUC 没有提升。因此证据更接近“已有信息的表示/决策得到小幅改善”，不能说新增了攻击真相。父类语义是对已有事实的重表达，也会改变线性模型的几何与正则化效果。

新开发的 6,153 条错误中，ASA 占 6,018 条，约 97.81%，是当前主要瓶颈。但**不能把全部错误都归为信息不可恢复**：按各折实际编码计算，同输入异标签的经验最少错误分别为 662、634、674 条，合计 1,970 条，低于实际错误数。这个后见统计既不是可部署规则，也没有证明剩余错误都能迁移解决。下一阶段仍须分别识别可学习的拟合不足与缺上下文；不能因某个冲突簇不可分，就宣称整个任务换模型也无益。本轮没有取得在合格行为对照上增加浅层非线性模型的充分依据，因此未自动启动该条件分支。

这次修复 20 条，没有新增错误：流量 12 条、Windows 可疑 6 条、Duo 可疑 2 条。其余关键问题仍然存在：

| 问题 | 新开发三折 | 旧模板/来源压力评价 | 当前判断 |
|---|---|---|---|
| Duo 可疑 | 10/10 正确 | 2/10 正确；8 条未响应仍判正常 | 同来源可学习不等于新来源迁移；未响应的跨来源支持仍不足 |

新开发分数与旧压力分数对应不同记录划分、拟合支持，不能直接相减解释为算法增益。旧压力评价此前也被查看过，仍不能称独立外部测试。压力结果见[完整报告](../artifacts/v39_local_r2_20260913/old_protocol_stress/report.json)。

### ASA 两正文的反例尤其重要

865 行 code 13 在新三折中**全部分错**：180 条恶意被判可疑，685 条可疑被判恶意。两种正文位于不同折；相同模型表示在拟合侧看到的标签会随被留出正文而改变。新表示仍不能辨别两组记录所对应的资产上下文。

这是对“细分组以后效果高就算解决”的直接反例。恢复 `dmz-1/2` 可以把这批数据的身份关联带回来，但仍无资料证明编号的业务含义能迁移。code→语义名称是确定性变换，不能给同输入增加新信息。原先 180 条的经验最少错误描述一个统一输入映射在该组上的信息限制；它不是多个折模型实际错误必须达到的上限，也不是当前训练程序必定能达到的成绩。

## 4. 本轮实际修复的缺陷

### 时间残留：修复并重新拟合，没有拿失败模型当成果

第一版发现并处理 210 行残留的完整绝对日期时间；追加原始日志时间替换时，row_position 811245 的任务计划正文仍留下 `entity:04:44z` 一类部分脱敏片段，替换时间后变成另一片段。

修复采用明确字段边界：将任务计划 `StartBoundary/EndBoundary` 的绝对时间内容统一处理，保留间隔、持续时长与其他行为参数。微软把这两个字段定义为触发器的激活/失效日期时间，见 [StartBoundary](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-startboundary-triggerbasetype-element)、[EndBoundary](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-endboundary-triggerbasetype-element)。没有把所有数字或所有时长删除。

修复改变了 59 个语义投影、86 行记录的正文表示。最终对全部 241 条相关真实记录做 482 次时间替换，零失败。旧表示、语义事实值、全部记录和角色均一致，所以只替换三折语义模型。[失败与修复凭据](../evidence/2026-09-13/v39_execution/clock_and_reuse.json)保留了原失败位置与原因。

### 认证语义：策略允许、完整结果与交互响应分开

旧解析路径将 `allow/allowed` 当作完整认证成功，新路径改为政策允许；只有明确结果才记录认证成功或失败。未响应与无效口令继续区分，不猜测被脱敏结果。依据 [Duo 的认证日志字段说明](https://duo.com/docs/adminapi#authentication-logs)。这修正了代码中的潜在混淆，但不能把本轮全部指标改善都归因于这个分支；报告另以真实预测变更计数。

ICMP 则保留 type/code，并增加已知消息类型与不可达原因，区分“设备拒绝所观测报文”和“报文携带的错误”。没有增加资产身份、产品名、时间段标签规则或第四个报警类别。

### 辅助配对：按约定跳过

三折拟合侧分别有 14,642、14,927、14,870 行落在同实际输入异标签的键中。这些键全部排除出辅助配对，但原行仍参加普通分类损失和完整评价。

在不同正文组、可核查行为值差异、相同其余上下文和最低独立正文支持条件下，三折合格配对组均为零。因此辅助候选未训练，没有造假标签、重复复制或放宽条件来凑训练任务。没有删除原冲突标签。

## 5. 执行中的七轮反证检查

以下为基于实际结果的顺序自审，不是七位独立评审。

| 轮次 | 反例/检查 | 实际处置 |
|---|---|---|
| 1：新分组是否泄漏或加入旧评价 | 全量逐行核对、正文/原文跨折重合、旧外层身份检查 | 允许池不变，零已知重复跨折；保留近重复疑点而不声称事件隔离完毕 |
| 2：时间删干净了吗 | 原始日志的完整时间替换发现一个部分脱敏残留 | 按任务边界字段修复，替换三折语义模型，再检查 241 条/482 次变换 |
| 3：高分是算法的功劳吗 | 旧表示在新协议已经达到 0.95850 | 只认可相同协议下 38 条净改善，不把约 0.959 当新发现的迁移能力 |
| 4：同来源能识别就能迁移吗 | Duo 开发 10/10，来源留出只有 2/10 | 保留已识别的凭据问题，未响应迁移列为未解决 |
| 5：语义名称能解开 ASA 冲突吗 | code 13 两正文三折 865 行全部分错 | 不恢复身份答案，不把经验下界当已取得效果；ASA 优化未通过 |
| 6：还可以用对比学习加码吗 | 三折严格配对支持均为零 | 跳过候选，保留普通损失与全部错误；不自动换大模型 |
| 7：执行检查通过是否等于模型可用 | 源码、序列化和指定不变性通过，但压力错误仍有 3,988 条 | 记录执行完成、质量未通过；停止扩大训练和比赛提交 |

近重复候选仍有 4,823 个模型投影跨多个正文键。这个数字是进一步检查的范围，不是已经确认的 4,823 个泄漏组；正文重复隔离不能自动保证真实事件独立。

# v4.9：两项编码优化实测与训练方向修正

日期：2026-09-14。当前审查入口：`evidence/2026-09-14/v49_review/`。

**两项针对性优化均已执行，但都没有减少分类错误，因此不晋升、不继续扩训。保留 v4.8 有效的原生动作修复。新证据把下一步重点指向：如何让模型在训练时使用跨来源的共同事实，而非继续重编码或增加字符覆盖。**

本轮总计 2 次新分类器拟合，各在独立目录、各自拟合前冻结配置。两者分别与同一个 v4.8 对照，不叠加改动；没有调阈值、搜索 C、修改标签、重复降权或下载其他数据。两者都触发预设停止条件，合计 0 次后续正文三折拟合，公共 B 未替换。本地 CPU 完成，无平台操作。

## 1. 实际执行结果

三者使用相同的 1,199,575 条拟合记录和 179,075 条旧压力记录，C=0.1、原始行等权和三类 argmax。

| 指标 | v4.8 对照 | O：观察值编码 | T：原词＋字符 |
|---|---:|---:|---:|
| 总错误 | 894 | 894 | 894 |
| Macro-F1 | 0.887161 | 0.887161 | 0.887161 |
| 正常误报 | 0 | 0 | 0 |
| native_flow 错误 | 48 | 48 | 48 |
| authentication 错误 | 10 | 10 | 10 |
| 相对 v4.8 修复 / 新增错误 | — | 0 / 0 | 0 / 0 |
| 正文组改善 / 退化 | — | 0 / 0 | 0 / 0 |

不是总数恰好抵消：两个新模型在这批压力记录上的最终分类都与 v4.8 逐条一致。概率有所变化，不能把这种变化当作准确率收益。

预设接受条件要求：总错误严格少于 894、Macro-F1 不下降、正常误报不增加、认证错误最多 8 条、流日志错误最多 48 条且无恶意判正常、各路由错误和各类召回不退化、优化器收敛。两者都因“总错误未减少”和“认证未恢复”失败，未放宽标准。

O 收敛于 138 次迭代，拟合阶段约 27.8 秒；T 收敛于 348 次迭代，拟合阶段约 86.3 秒。这些时长不包含准备、核验与分析。

## 2. 为什么观察值编码没有解决问题

O 将八类有限取值字段的默认缺失数值清零，真实取值及明确观察到的零均可区分。编码检查覆盖所有允许开发记录对应的 79,900 种输入：189,210 个已观察有限值保持精度，其他原有事实特征也不变。

但“是否观察到”的标记仍携带可用性信息。这不是消除了字段缺失机制。原始缓存也不总能区分“原文有槽位但脱敏”与“没有该槽位”；本轮没有把两者冒称为已经识别出的不适用状态。

更关键的是，本轮在不训练分类器的情况下，通过代数变换便能在新编码下重现旧模型：最大概率差仅 **9.44×10⁻¹⁶**。

```text
旧缺失编码 = 观察到的取值位 + 缺失哨兵 × (1 − 是否观察到)
```

相应改变权重与截距即可重现原决策函数。它没有增加可观察信息；在固定 C 下重新拟合，主要是在比较正则化对不同参数表示的偏好。特征表示/缩放会影响逻辑回归的正则化选择，官方示例也说明这一点：[scikit-learn 特征缩放示例](https://scikit-learn.org/stable/auto_examples/preprocessing/plot_scaling_importance.html)。本项目的等价结论来自上述实际代数回放，不是从该示例推断得出。

**决定：停止把这种重编码作为性能提升主方案。** 它可提供更清楚的审计表达，但本轮没有分类收益；也不能据此否定所有缺失数据方法。历史 v4.5 只在 ASA 的两个端口组做过不同实验，本轮不是把那次结果换名复述。

## 3. 为什么字符补充仍没有解决问题

T 保持 v4.8 的结构化事实编码和原词通道不变，额外加入固定的局部字符通道：字符片段长度 3–5、最多 10,000 个特征、通道权重 0.5。词典与 IDF 只使用拟合侧记录；原有词、原有运算符关系及其向量没有被替换。

这种现成机制可对拼写片段编码，工具定义见 [CountVectorizer 官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.CountVectorizer.html)。本轮没有把拼写相似解释成安全语义等价。

| 认证正文 | 原词通道非零数 | 新字符通道非零数 | 分类结果 |
|---|---:|---:|---|
| allow_unenrolled_user | 0 | 23 | 23 条正常仍全部判对 |
| no_response denied | 0 | 21 | 8 条可疑仍全部判正常 |
| invalid_passcode denied | 0 | 23 | 2 条可疑仍全部判正常 |

文本全零问题在这 33 条记录的联合向量中消失，但分类没有改善。invalid_passcode 两条的可疑概率由 0.494157 变为 0.491914，no_response 八条由 0.418087 变为 0.411960，仍在正常一侧。

**决定：停止这个固定字符通道候选，不继续扩大字符词典或扫描权重。** 原文可表示是必要检查，不足以证明模型会根据这些文字可靠判断；本轮也没有证明所有字符模型或语义模型均无效。

## 4. 新确认的核心问题：有共同事实，但模型没有稳定使用它们

本轮将单列支持核查细化到拟合侧原始行和正文组：

| 共享事实 | 拟合侧记录 | 来源与原标签 |
|---|---:|---|
| 凭据无效 | 314 条 / 314 正文组 | Windows；全部可疑 |
| 认证失败 | 484 条 / 484 正文组 | Windows 331、syslog 153；全部可疑 |
| 认证成功 | 77,714 条 / 13,385 正文组 | Windows 两类原生呈现；全部正常 |
| 凭据有效 | 0 | 无直接支持 |
| 无响应 | 0 | 无直接支持 |
| 该认证策略“允许” | 0 | 无直接支持 |

“没有 Duo 拟合记录”不等于“没有任何共享认证事实”。同时，单个事实只出现一个标签，不能证明它在现实中必然对应该类别；正常认证失败等外部对照仍缺乏。

对 314 条拟合侧“凭据无效且认证失败”记录做了不重训的诊断：保留三个既有字段 outcome=failure、credential_check=invalid、auth_result=failure，移除正文与其余配套字段。

| 模型 | 完整输入判为可疑 | 简化输入判为正常 |
|---|---:|---:|
| v4.8 | 314 / 314 | 314 / 314 |
| O | 314 / 314 | 314 / 314 |
| T | 314 / 314 | 314 / 314 |

v4.8 简化输入的概率与那两条真实跨来源错例的概率完全相同。这是可复现的输入依赖证据：模型拟合了完整组合，却没有让相同的共同事实在缺少配套信息时产生同样的判断。

这是**拟合侧删减信息诊断**，不是新的未见测试成绩，也不证明删掉的所有字段都是噪声；真实状态码、正文等可能包含额外有效证据。仅凭该诊断还不能宣称“只保留三字段”就是充分表示或新模型。

## 5. 下一步方案：先验证共同事实视图的训练，而非继续换编码

建议下一轮只验证一个有限候选：**原始完整输入与经过语义核对的共同事实视图共同学习。** 目标是检验模型能否减少对配套字段组合的依赖，同时保持完整输入的辨别能力。该候选尚未训练，不能称为已有收益。

执行范围与判据：

1. **仅从原拟合侧构建候选视图。** 以有文档和解析依据的认证成功/失败、凭据状态作为逻辑事实；先核对原文出处，以及哪些被移除字段表达的是重复事实、哪些携带新的必要语义。outcome 与 auth_result 的同义内容不能在解释中当成两份独立证据。
2. **保留完整输入。** 共同事实视图是辅助训练视图，不替代原文和真实参数，不删原数据，不自动修正或合并标签。如果同一共同视图对应多个原标签，保留其真实分布，不投票改成一个标签。
3. **每条官方记录总权重仍为 1。** 只有通过上述语义检查的记录，拟议将完整视图和共同视图各分配 0.5；不合格记录仍只用完整视图、权重 1。这一比例在训练前固定，先做一次 C=0.1 对照，不额外提升小类或重复组权重，也不从压力错例生成训练记录。
4. **无直接支持的概念不强行对齐。** no_response 的含义没有直接拟合支持，不能将它改写为 invalid_passcode，也不能设置“无响应必为可疑”的标签规则。已有失败事实可参与学习，专有原因的无支持状态仍需披露。
5. **首先重复原压力比较。** 继续约束总错误、认证恢复、正常误报、流日志漏判、各路由及正文组退化；另报告真实认证成功/失败反例与固定不必要字段变化。只有过关才进行原正文三折，不根据结果放宽条件。

这个候选改变的是训练时可依赖的证据组合，因而与本轮仅换参数表示的 O 不同；它也没有通过固定来源路由拼接两条旧正确答案。辅助视图可能丢掉与标签相关的必要信息，这是首要否决条件。如果原文语义审查不能支持这些视图，就不训练这个候选，转而保留信息不足的范围。

ASA 仍占当前压力错误的 827/894。不能因为认证诊断更容易解释，就把它当作全部项目问题已经解决。完成这项有限的迁移机制验证后，应把同样的“完整输入、共同事实、原标签冲突”核查用于 ASA；不直接沿用未验证的认证简化规则，也不继续普遍删真实目的端口。

## 6. 已新增的实际能力与证据边界

- `v49_encoding.py` 的推理接口能随原三类概率返回“正文编码全零”和“事实列在拟合侧未激活”的覆盖说明。说明作为独立审计结果返回，三类 argmax 仍可能给出正常；这不能视为有充分依据的确认。说明未用于修改标签或设置第四种竞赛类别。
- O 的真实原文核验返回 33 条文本全零说明；T 对这些记录不再返回文本全零，但无响应、策略允许的无拟合支持说明仍然存在。覆盖说明不是经过校准的错误概率，也不能独立保证安全。
- 两个新模型各完整回放 179,075 行概率；各自另验证 4,319 条真实原文及同量指定变换。native 路由变换身份/时间包装，认证记录检查外部字段变化；不夸大成全部日志的全变换验收。
- 五项编码测试覆盖所有有限值位的代表性边界、已知零、未知/缺失、非法事实以及来源外字段；全量缓存观测值也已核查。软件验证和分类质量分别报告，两个分类器质量均未通过。

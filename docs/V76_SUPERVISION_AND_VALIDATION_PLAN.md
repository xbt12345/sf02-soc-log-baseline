# v7.6：补齐监督诊断与内部验证，先证实瓶颈再扩训

日期：2026-09-22。状态：**本轮新增 0 次拟合；完成既有结果复算和三个保存模型的全量优化状态诊断，尚无新模型成绩。** 最近真实训练仍为 v7.5，质量未通过，不替换保留模型及正式提交入口。仅使用官方数据。

## 1. 判断：保留有效改动，但不能据此认可整个分类器

原件保留、补齐原先漏用的训练记录、逐切片检查，已经带来真实局部收益，应继续。下一阶段的主问题是：**内部收益是否落在真实难点上，以及模型究竟缺少区分证据、可学习表示，还是有效优化。** 更大权重并不等于更多监督信息。

本轮没有重新训练，也没有重新选择检查点。`training/v76_review_audit.py` 核验 v7.5 交付绑定文件并复算支持；`training/v76_optimizer_state_audit.py` 在每个已保存 D/E/F 模型上处理全部 2,056,871 条训练文件记录，核对平均参数预测与原记录完全一致，再诊断最后一步参数的预测。输入、原标签、模型文件均未修改。

## 2. 由实际结果确认的四个卡点

### P0：内部收益集中在当前回放不覆盖的格式

四臂 A→D 内部净少错 2,406 条，其中 native_flow 贡献 2,320 条，占 96.43%。它在内部恶意样本中占 29.91%，当前完整开发回放却没有该格式。保留这项能力有价值，但不能把它当作解决完整任务的主要证据。

相反，完整开发回放的恶意类中，unsupported 6,226 条与 VPC 2,664 条合计占 63.27%。官方训练里前者只有 30 条恶意，后者为 0；内部验证对应恶意只有 8 条与 0 条。内部高分因此没有充分检验最薄弱的能力。

这里的 63.27% 使用了已查看的私有答案，仅用于回顾诊断，不用于推算训练权重、选择阈值或构造所谓新盲测。17 个解析路由也不等于已经覆盖全部语义格式，尤其 unsupported 是混合容器。

最小修正：保留逐记录任务分数，新增“格式×类别缺支持迁移”验证，明确未测单元为 NA。验收必须同时看到覆盖状态和逐类别结果，不能把没测到写成通过。

### P0：同一格式内仍存在失败，不能全部归因于格式比例

ASA 恶意召回：内部 D 为 97.89%，全量重训 D 在完整开发回放为 48.69%。两者模型拟合状态不同，因此这不是严格控制其他变量后的分布漂移因果估计；但足以反驳“只是 native_flow 占比变化”的解释。

D→F 全量回放，ASA 修复 6 条却新增 681 条错误；其他格式的局部收益被反向取舍吞掉。后续必须同时记录“修复谁、伤害谁”，不能只报告稀缺召回上涨。

最小修正：ASA 的 M/S 任务单列同协议、动作、方向、参数及可用上下文的对照表；区分近似行为异标签、缺类别支持、未见组合和有支持但学错。原始端口、计数、单位和缺失状态全部保留；不把 deny/reject 直接当成恶意或可疑真值。

### P1：六轮训练不构成收敛证据，关闭平均参数也不是解法

v7.5 仅固定运行六轮 `partial_fit`，未保存足够的目标函数、梯度或收敛证据。官方 API 明确每次 `partial_fit` 只执行一轮，收敛、早停及学习率管理由调用者负责。[scikit-learn 文档](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.SGDClassifier.html)

本轮零拟合诊断：

| 已保存模型 | 内部验证：平均参数错误 | 最后一步参数错误 |
|---|---:|---:|
| D | 1,044 | 3,704 |
| E | 1,273 | 3,888 |
| F | 887 | 3,648 |

F 的 Windows S 错误 10→0、bounded_payload S 5→0，但 ASA M 错误 640→3,630。unsupported 的 22 条拟合恶意和 8 条验证恶意，两种状态仍全部错误。

这说明优化状态显著影响边界，不能把当前训练错误直接判成容量不足；也不能通过关闭平均参数解决整体问题。最后一步参数不是已证明的最优解，这次比较不是新模型选型。

最小修正：先做相同表示、损失、正则化、权重的收敛线性参考。不能把更换 OVR/softmax、截距正则或权重归一化产生的收益冒称“仅优化器改进”。

### P1：记录数不等于独立监督，保留信息不等于表示充分

unsupported M 的 30 条只有 4 个正文/划分组件，拟合 22 条来自 3 个组件、验证 8 条来自 1 个组件；观察到的源符号只有 1 个。这不是四个独立真实组织。Windows S 的 473 条分成拟合 38、验证 435，独立组件分别只有 7、6。Windows M 共 2 条、无独立验证恶意。

当前字节 1/2-gram 保留短局部组合，**并不保留完整顺序与长距离语义关系**。原文哈希无混标仅说明字符串不同，身份和时间就可以制造不同；不能据此证明行为足以决定标签。设备判断片段已保留，但其独立模型分支尚未训练。

最小修正：先按训练侧可观察语法细分未知载体，逐条追踪“原文跨度→结构事实→实际特征→模型判定”。记录不足靠共享表示和真实跨格式对照验证迁移，不靠复制样本或自动改标补造证据。

## 3. 下一轮严格执行顺序

### 第一步：冻结验证契约与监督缺口表，不启动全量模型搜索

1. 保留既有源/正文隔离回归，增加在官方训练内构造的格式×类别支持撤除实验：选择确有独立组件与真实类别样本的载体，将该载体目标类及其关联组件整体留出，检验其他载体的行为证据能否迁移。禁止只抽走单行却把同事件、近正文或主体关联行留在拟合侧。
2. 先列支持表，再决定可执行对照。仅一组的类别不能伪造多折；没有某类别的验证折记 NA；格式只有单类时，明确缺少同格式反例。unsupported 的正文组件留出只能声称正文迁移，不能声称跨组织泛化。
3. 17 路由逐类列出记录数、独立组件数、实际拟合曝光、标签冲突、解析覆盖和错误。细分 unsupported 使用训练侧可观察语法，规则冻结后应用到验证侧；不能按验证标签挑拆分规则。稀缺切片提高诊断优先级，仍保留正常反例和全局对照。
4. 每个协议内部单独拟合词典、标准化、采样权重、基础模型和局部头。旧 v5.1 或 v7.5 模型可能见过新验证行，不能直接作为无泄漏教师或基线。历史模型只用于历史回归。
5. 内层选择超参数，外层只评价固定候选；已查看的完整开发回放仅在候选冻结后作一次回归。重划分旧数据不会恢复真正的盲测地位。只有时间语义和关联可靠性已确认，才把时间切分作为真实性能验证。

### 第二步：先回答“有监督且可分的样本，为什么仍学不会”

首个诊断对象为原角色中 unsupported 的 22 条拟合恶意，以及拟合侧同载体正常/可疑反例、ASA 保护对照。原验证 8 条不进入拟合。逐条检查原始字段、转义、顺序、参数、设备断言及真实特征冲突；不只拿正样本做记忆试验。训练侧困难负例挖掘和选样过程保存清单。

先跑两个同任务小规模对照：现有六轮 SGD 复现与收敛线性参考。损失、正则、权重、截距处理必须匹配，并记录目标函数、梯度范数、停止原因；必要时用数值梯度验证实现。有限预算内未收敛应写“未收敛”，不能当作模型表达上限。

若相同表示的收敛参考已解决拟合与留出问题，不扩容量。若仍有缺口，再做以下 2×2；收敛参考直接复用，整个诊断最多五个不同拟合配置，不自动全量扩训：

| 表示 / 学习器 | 收敛线性参考 | 一个有限规模交互网络 |
|---|---|---|
| R0：纠正身份后原字节 1/2-gram＋行为事实 | 基准 | 只测非线性组合 |
| R1：R0＋训练侧字符 3–5-gram＋结构参数片段 | 只测表示 | 测二者交互 |

网络先采用一个 64/32 隐层配置，固定输入和任务目标，不同时扫模型库、权重及阈值。训练前固定种子和资源预算；词表仅来自拟合侧，保留 R0 回退，统计未知片段，不截断正文前缀、不统一抹掉所有数值。字符 n-gram 也不代表保留完整长序列。

判读：R1 线性改善而 R0 网络不改善，支持表示缺口；同表示网络改善，支持交互能力缺口；两者拟合都改善却留出不改善，转查支持/条件变化，停止以拟合分数证明泛化。单个种子差异只作筛选，晋升前再做独立组复验和固定种子稳定性检查。

这些是**诊断子集实验**，不能声称已经完成全量训练。进入最终候选训练时必须使用全部官方记录，包括全部 32,596 条 native_flow M；该数字不是全数据恶意总数，官方训练恶意总数为 111,728。继续保留重复记录的原监督频率，缓存复用不等于样本去重或降权。

### 第三步：将局部改进的影响限制在有事实支持的范围

若诊断产生有效稀缺修复，采用“稳定基础模型＋独立局部修正”的受控实验。启用依据必须是日志中可观察的行为事实，例如认证动作或请求载荷；不以产品名、来源编号、时间、格式名称、空字段或预期标签作为判定捷径。对无法可靠识别的行为回退基础模型。

非适用记录的输出概率应逐条完全不变；适用记录同时接受正常反例、M/S 及未见主体检查。独立头训练前冻结基础参数，每个验证协议内重新拟合基础模型，禁止历史权重泄漏。

本项目 v5.1 已证实这种参数隔离能保留认证局部收益并避免其他记录退化，优先复用这个有本地证据的思路；这不代表它能自动解决 ASA 内部 M/S。若局部修复必须大范围改变共享参数，先证明其行为适用范围与全局净收益，否则不晋升。

### 第四步：零支持迁移单独验收；通过后才全量候选

VPC 的官方训练没有 M，权重、更多轮数或更大分类器都不会新增这个监督单元。先用第二步之前冻结的“撤除格式×类别支持”真实标签对照，检验共享协议、方向、动作、端口、计数等事实能否迁移；统一单位和角色，同时保留原值及缺失标记。不能把 VPC 拒绝事件自动改成 M。

只有模拟缺支持迁移对照有收益，并通过真实反例与类别保护条件，才值得将该机制用于 VPC。否则明确“当前官方监督不足以验证此区分”，保留不确定性和证据缺口，不伪造正样本或承诺靠模型规模解决。

设备断言分支若要启用，须先确认推理时可用、字段含义及其与真实行为的边界，然后单独消融。若依赖可靠事件上下文或长序列，先验证时间、实体、邻居真实性；没有这些前提，不引入大模型序列训练。

## 4. 更强内部验证的交付标准

主结果同时报告比赛规则下的原记录准确率/错误数及官方评分指标（若题面另有定义，严格按题面实现），Macro-F1、M/S 召回和正常误报为必要保护项。不能用全正常高准确率、格式等权平均分或稀缺切片分数替代完整任务质量。

每个候选必须提交：同记录配对修复/新增错误表；逐格式逐类结果与支持状态；拟合目标及停止证据；预测重载一致性；原件和实际输入对应关系；模型与输入哈希；记录曝光计数。独立组足够时做配对组 bootstrap，少量组直接列出各组结果，不能把重复行当独立样本制造窄置信区间。

保护条件：不放宽 v7.5 已有 M/S 及误报门槛，不允许用 Windows 提升抵消 ASA 大幅退化。新增条件是适用范围外输出不变、缺支持单元不能默认为通过，以及在预先指定的支持撤除对照上报告类别级迁移结果。候选总错改善但关键类/安全保护项失败仍不晋升。

行为反事实测试分开两类：身份重命名、合法日期/UUID保持等语义不变操作检验稳定性；端口、方向、动作及参数变更可能改变真实语义，不能强制预测不变，必须检验合理敏感性或标注为未知。引用、否定、转义和载荷截断作为专项检查，不用人工编造标签替代真实结果。

大模型不是本轮首选：尚未证明长序列上下文真实可用，也未证明当前监督足以支持目标区别。先把同一信息下的收敛、表示和容量区分清楚；结果支持后再设计有数据依据的序列模型对照。方法的公开成绩不直接迁移为本项目收益承诺。

## 6. 逐项验收与对抗性审查

第一轮反证——“已有收益，所以原方案整体正确”：不成立。96.43% 的内部净收益来自回放无该格式的 native_flow；只能保留已证实有效的组件。

第二轮反证——“提高稀缺权重就补齐监督”：不成立。F 局部收益伴随 ASA 新错，零支持没有新增事实；先诊断独立支持和影响范围，不恢复无依据重复降权。

第三轮反证——“最后一步或更强模型能记住，所以已解决”：不成立。末步参数让 F 验证总错 887→3,648；记住训练正例不能证明跨组 M/S。

第四轮反证——“重新分折就有可靠测试”：不成立。历史权重可能见过新留出行，旧私有答案也已被反复查看。所有拟合对象按协议重建，旧回放只作开发回归；真正外部泛化仍未验证。

下一次执行的第一交付限定为：冻结的验证清单、unsupported 逐条监督/表示缺口表、两个优化器对照及相应停止判据；有证据才进入剩余表示×容量对照和局部修正。首先可在本地 CPU 完成；本轮无需用户平台操作。若后续确有序列模型需求，再依据实测资源与可用训练支持提供平台执行包。

# V160 原型中有效小方向被截断的独立审查

V159 的实际问题是固定更新方向被分类保护阻挡。V160 是尚未训练的新方向原型；下面发现不能倒推为 V159 已发生同一种 Gram 截断故障。本轮新增官方前向、特征、梯度和拟合均为零。

已绑定并保留原型首失败源码 SHA-256 `ce0e2d773110ab106237cd01275c484b5a60a2f2436d1fb0361d8cbb90f4aa60`，独立运行复现两项问题：

| 合成问题 | 数学可行性与实测 | 原型结果 |
|---|---|---|
| 同一保护法向只改变正单位尺度 | 法向乘 1、1e-12、1e12，可行锥完全相同；两类有相同安全共同下降方向 | 1 倍通过，另外两倍截断数值秩并拒绝 |
| 保留有用小梯度分量 | 分量 1e-11；显式安全方向在有限步 0.5 下，两类风险各降 3.43747e-12，超过原 16eps 风险分辨率约 968 倍，线性分类保护完全保持 | Gram 子问题秩从 2 变 1，丢掉有用方向并拒绝 |

第二个反例的梯度为 `gM=[-1,epsilon,0]`、`gS=[-1,0,2*epsilon]`，保护法向为 `[-1,0,0]`。已知安全方向是 `[0,-1,-0.5]`。风险是显式光滑二次函数，实际浮点重算有限步下降，不仅是局部梯度为负。epsilon=1e-4 和 1e-8 时原型通过；1e-11 时拒绝。这些函数不是 SOC 模型，证明的是数值算法会遗漏有效方向，不能证明真实模型已有这种可行方向。

直接缺陷位于对基向量先构造 Gram 矩阵，再用默认 `lstsq(rcond=None)` 解自由变量。Gram 放大条件数差异；数值秩截断丢掉小分量。记录中的 `condition=1` 只计算保留的奇异值，不能说明完整问题条件良好。当前末端原向量证书正确阻止了误用，但拒绝结果不能被称为模型无解或分类已收敛。

针对性修复要求：

1. 对保护法向做正尺度处理并检验单位不变性；两个类别梯度保持同一个公共尺度，不能改变类别目标权衡。
2. 优先直接求解基矩阵最小二乘，核验数值秩、全部奇异值和原问题残差；避免 Gram 平方条件数后默认截断。NumPy 的默认秩阈值与矩阵维度有关，不能不经验证直接换成高维默认 SVD 后追认问题解决。
3. 保留小的有效分量，不用绝对梯度地板、阻尼或放宽保护条件来让资格变绿。
4. 无法分辨的零重构残差必须标记数值停止；局部数值失败、固定切空间无共同下降和全模型不可分类分别记录。
5. 修复后重新跑原正例、反例、完整参数数量及相同几何的不同尺度；仍须官方合法训练角色的实际有限步和完整保护才能允许下一训练。

原型失败源码与原日志已独立保存在 `artifacts/v160_independent_first_solver_failure_source_snapshot_20261002/`，与首执行绑定逐项匹配。数值反例见 `artifacts/v160_independent_normal_units_counterexample_20261002/review.json` 和 `artifacts/v160_independent_small_useful_component_counterexample_20261002/review.json`。

独立保存向量检查器已通过 6 组尺度/维度对照，并使用三个角色此前保存的真实初始类梯度核验下降符号，最大与原记录斜率差 1.38778e-17。实际保护法向尚未测量，这些检查不证明官方有限步安全或分类收益。

原理参考：[NumPy 2.2 lstsq 的数值秩阈值](https://numpy.org/doc/2.2/reference/generated/numpy.linalg.lstsq.html)、[SciPy 1.15.3 lstsq 的 cond 和奇异值说明](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.linalg.lstsq.html)。具体故障和处置以本项目上述实际反例为依据。

实际执行跨越北京时间 2026-09-13—14。**已完成 12 次主/诊断拟合、全部保存模型核验；没有候选满足冻结验收条件，旧压力拟合为 0 次。** 本轮使用本地 CPU 和官方数据，无需用户操作平台。

最重要的结果是：直接删重复事实重现了上一轮认证退化；参数增强在已有支持区域有效，却继续损伤未见输入；Windows 输入修复解决了目标漏判，却通过全局重训影响了另一个认证来源。继续把这些改动整体拼装、重训和比较总分，不能解决当前问题。

### 2.1 直接去副本的退化已得到单因素复现

| 切片错误 | B | F：仅换码 | D：仅删别名 | 旧 N：两项合并 |
|---|---:|---:|---:|---:|
| Duo 33 条记录 | 0 | 0 | 10 | 10 |
| Windows 已知 18 条退化记录 | 0 | 0 | 18 | 18 |
| 全部允许开发记录 | 6,153 | 6,041 | 6,191 | 6,071 |

D 还使一个 CEF 恶意小切片的 12 条记录、2 个正文全部判错。D 合计修好 2 条、退化 40 条，净增加 38 条错误。单看 ASA 少错 2 条会掩盖这类破坏。

结合 [前轮尺度等价性检查](V41_REASSESSMENT.md)，证据与“删去相同列改变有效特征尺度和 L2 惩罚”一致。**应舍弃当前直接删列方式；不把保留两个相同特征解释成拥有两份独立安全证据。** 目前也没有证据支持无限更换全局 C 来补救。

F 没有这 28 条认证退化，故不能把上一轮这些退化单独归因于 n+1 换码。但 F 的 ASA 三折错误变化为 `+2 / -48 / +4`，总体 log loss 从 B 的 0.01610449 略升到 0.01612434，不能仅凭少错 112 条认定表示整体更可靠。

### 2.2 参数分支的优势主要发生在已有支持区域

P 的 ASA 三折均改善，变化为 `-195 / -192 / -182`。按原 B 固定分区重数：

| ASA 固定分区 | 行数 | B 错误 | P 错误 |
|---|---:|---:|---:|
| 拟合侧同输入单一标签、且与评价标签相同 | 12,901 | 1,522 | 892 |
| 拟合侧同输入单一标签、但与评价标签相反 | 1,311 | 921 | 1,013 |
| 拟合侧同输入标签冲突 | 21,233 | 2,479 | 2,428 |
| 拟合侧未见实际输入 | 71,508 | 1,096 | 1,116 |

P 总体修好 889 条、退化 258 条。ASA 恶意判为可疑从 618 增至 768，增加 150 条；可疑判为恶意从 5,400 降至 4,681。两种分型错误应分别报告，不能把它们全部称为“漏报”或都包装成召回改善。

未见参数错误 `652→664`，未见联合值错误 `740→752`；这两个切片重叠，不能相加成 24 条。新增 12 条错误集中于两个投影。

对保存模型做精确线性分数核算发现：一个未见目的端口的 UDP 投影，虽然没有对应端口项，仍受到公共 `deny×udp` 项影响；这个项贡献 -3.1949 的“恶意减可疑”分数，把原先正确的恶意判断推过分界。另一投影受到已见源端口主项和协议×源端口项影响，即使目的端口组合未知也继续修正预测。

**“某个局部交互见过三个正文”不等于完整待判上下文有足够支持。** 当前参数分支的激活范围过宽，应停止将它作为整体替换模型。证据：[实际分数贡献](../artifacts/v41_local_r1_20260913/failure_mechanism_review.json)。

### 2.3 Windows 事实修好了，但公共分类器仍发生跨类别干扰

扫描全部允许开发的 962,244 条 Windows 记录，并解析全部 95,278 条已识别认证记录：378 条失败认证可确认状态来源；其中 357 条原来已有结构化状态，21 条需要从完整正文补入。94,900 条成功认证标题被脱敏，保持 B 的原处理；这属于边界未知，不是已证实的语义冲突。

A 对 378 条记录统一状态表示，替换正文中的对应数字载体，按拟合侧重新建立词表；原标签与三折不变。目标错误 `3→0`，全部 18 条已知 Windows 退化记录也保住了。

但 `invalid_passcode denied` 的两条 Duo 记录变成正常，概率分别从：

- 可疑 57.03%、正常 41.64%，变为可疑 38.63%、正常 60.08%；
- 可疑 56.16%、正常 42.54%，变为可疑 36.82%、正常 61.94%。

两条输入按实际特征名对齐后，B/A 非零特征值差异均为 **0**。这证明本次回退可以由公共参数重新拟合解释，不能归咎于 Duo 输入被解析器改坏。A 合计修好 5 条、退化 2 条；小切片保护正确阻止了它晋升。

证据：[全量原生状态审计](../evidence/2026-09-13/v41_native_preflight_r2/audit.json)、[原生范围支持分布](../artifacts/v41_local_r1_20260913/native_support_review.json)、[A 分支复核](../artifacts/v41_local_r1_20260913/primary_review/candidate_A.json)。

## 5. 第一性原理下，应继续保留和改变什么

**保留事实层和可解释的验证体系；停止把局部修改交给公共分类器整体吸收。** 当前证据支持以下次序，后续模型尚未训练：

1. 以冻结 B 作为比较基准，下一次只检验一个局部增量方法。原参数和截距都冻结，明确证明不属于适用范围的输入概率与 B 完全相同；不能按产品名或绝对时间分流。
2. 对网络参数增强，先做覆盖核查，再训练。适用性取决于完整可用语义上下文的拟合侧支持；目的端口或组合未见时，不能因为公共 `deny×udp` 或某个源端口项已见就自动修正。未知范围回到 B 是保护措施，不算新增能力。
3. 对 Windows，保留带来源位置的解析修复作为事实输出；当前不根据 378 条同类标签训练一个强制判可疑的补丁。先解决公共参数干扰，再决定这些事实如何参与分类。
4. 在全体指标之外，继续冻结少数类别、未见上下文和每类分型退化限制。ASA 恶意→可疑的新增错误也要单列；不以少量可疑类增益掩盖它。

**官方数据足以继续做表示诊断和同协议模型比较，但不足以证明现实迁移可靠性。** 本次允许开发的 ASA 106,953 行只有恶意 78,746、可疑 28,207，正常为 0；可确认状态的 378 条 Windows 失败认证也全部为可疑。这两处都不能估计同类正常行为的误报率。遵循当前只用官方数据的约束，不能以改标签、造正常伪样本或换一个随机划分补出这项证据。

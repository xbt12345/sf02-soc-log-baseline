## 2. 发现并定位的解析缺口

502 行原文出现源接口名 `Outside-3620`，现有 facts 和坐标缺少 `src_role`。按现有 known-interface-name-family 规则做大小写一致化应映射为 `outside`；不能据接口名称独立断言真实网络信任区。

|原行|来源根|local 输入条目|M/S|A0、V142、V146 A/B 错误|
|---:|---:|---:|---|---|
|502|105|139|502 M / 0 S|全部为 0|

从逐行审计与原始账本交叉重算。这里的 139 是 local 条目数，不宣称等于 canonical 不同输入数。

[Cisco 官方 ASA 接口文档](https://www.cisco.com/c/en/us/td/docs/security/asa/asa92/configuration/general/asa-general-cli/interface-routed.html)说明 `nameif` 名称不区分大小写；名称和 `security-level` 分别配置。因此可借鉴其大小写规则，不能把名称前缀或文档示例自动当安全等级、攻击身份或 M/S 规则。

这是输入解析一致性问题，当前这些行分类全正确。后续需要版本化大小写一致性候选与回归保护，但不为了凑收益把这 502 条 M 设为特供监督，也不把修解析说成修复了 502 个分类错误。原历史 trace、旧输入和模型不修改；若新表示采用该修补，重新封存、检查分组/来源角色并用实际模型验证旧正确记录，不能直接复用旧输入的能力证据。

## 3. 下一步范围与分流

当前继续第二问题，不直接正式训练整个分类表示的 facts-distance。当前证据支持的下一项是**模型表示对已保留行为字段的读取诊断**，由训练执行会话独占模型计算，父会话只做数据与结果复核：

1. 检查固定第一层、当前第二层是否能读出关键可观察事实，保持原行频次、同类/反类支持和正确稀缺对照；来源闭合与初始模型已见标签的边界明确。
2. 原端口能从坐标精确解码但不能从隐藏表示读出，才有针对表示补监督的机制依据；读取结果应区分拟合区与来源外、已见值与未见组合。仅隐藏状态不同、不存在同值冲突不等于可以准确读取。
3. 如果关键行为能读取而 M/S 仍错，不以更低事实重建损失继续同方向，转查这些成分与类别的对应、合法 TRAIN 支持及未提供的判定上下文。已有事实分类依据能否迁移仍须实际匹配试验。
4. 502 行源角色缺口记录为独立解析反例；其正确对照保留。它不覆盖原 578 困难 S，不替代第二问题主目标，也不直接产生新拟合资格。

# v3.5 整体方向复审：先确认可学的任务，再选择模型

日期：2026-09-12。**此前整体方向存在偏差，需要调整目标假设、信息处理和验证设计，不能只继续清洗后重训。** 这不意味着两轮所有结果无效：v3.3.1 确实学到了当前分布中的可预测模式，严格留出也有效揭露了失效；问题是这些证据不能支撑“单条清洗日志即可对任意新来源可靠三分类”的目标。

本轮使用架构审查方法，重读官方题目原件、当前解析源码和回传审计，另对全部 2,056,871 行重新进行任务支持与上下文审查，查阅论文、作者代码及实际 IDS 架构。未重训模型、修改官方标签或增加外部数据。用户已确认：**只有题目与现有数据，没有额外类别定义或脱敏关联说明。** 本文是评审依据；唯一当前执行方案见 [TRAINING_PLAN.md](TRAINING_PLAN.md)。此前 v3.4 已[按原始字节保留](../evidence/2026-09-12/v35_direction_review/training_plan_v34_before_reassessment.md)。

v3.2 与 v3.3.1 主模型都沿用词 TF-IDF 与线性分类器，主要改变输入及验证协议；它们不是两条完全不同模型路线的独立失败。现有证据足以停止同路线的盲目扩大，也不足以证明所有机器学习模型都无法解决这个任务。

## 1. 从第一性原理看，先前哪里走偏

一次安全判断至少涉及三个层次：记录实际表达的事件、该事件所处的可用上下文、把事件归入某种安全类别的判定规则。机器学习只能从给定信息和监督中学习；不能恢复被脱敏掉的事实，也不能自动知道一个新组织没有提供的判定规则。

因此，需要减少的是对无关采集特征的依赖，而不是对“原始信息”的依赖。原始信息中的动作、结果、角色、合法上下文恰恰是判断依据。高相关字段不自动等于泄漏；删掉高相关字段也不自动产生因果知识。

以下是会改变实施选择的主要发现。

| 严重度、源位置与短原文 | 已观察事实或待证假设 | 对方向的修改 |
|---|---|---|
| P1，官方题目 §4/5：“事件数据和日志”“事件时间…源/目的 IP…动作…”；v3.3.1 prepare_record 只传 message_sanitized | 实际主路线收缩为单条文本；题目没有要求只使用文本。单事件已见类别分类、未知来源分类和攻击链分析是不同问题 | 保留预测时可用且经核实的事实与关系；先审查数据能支持什么。攻击链不得仅凭列存在就声称已支持 |
| P1，v3.4 §2/3：“共享事实短文本…沿用…TF-IDF” | 字段统一有价值，但继续把全部信息压成一个文本视图，尚未证明会保留充分区分力 | 最小规范化正文保留为独立对照；结构事实是补充视图，不再预先认定它能替代全文 |
| P1，v331_prepare.py 的 AUTH_FACTS 白名单及 “upstream_or_post_event” 原因标签 | 上游意见、真实设备处置、预测前已有状态、事后标签是不同事物。当前记录的隔离理由不等于已核实每个字段的生成时点 | 字段逐项记录含义、可得时点与使用范围。目标标签禁止进入输入；原生事件码、结果等不能仅因与标签相关就删掉 |
| P1，来源/标签完整统计；此前只检查全局三类支持 | 全部恶意落在产品为空字符串的桶；17 个有名产品中 13 个只有一个观察类别 | 来源偏差属于数据支持问题，删除一列不能消除。先检查同事件族内的异类对照，禁止用产品名恢复类别查表 |
| P1，v3.4 阶段 B 把若干整来源失败作为统一升级门槛 | 完整来源留出可能同时移除事件格式、语义或类别支持；这是有效极限压力测试，但不同于同来源新实体/新模板泛化 | 保留所有失败并继续优化；把迁移类型标清，增加共享事实支持诊断，不能用一种验证代替另一种 |
| P1，原行频率优化与少数来源的实际组数 | 重复很多次的模式不提供等量独立知识；全局类不平衡与来源内类别缺失是两种问题 | 基线保持原行频率；信息稳定后才比较有界组权重，评价仍全量。没有正例时不靠加权假装解决 |

不回退到 v2 曾排除大量恶意记录的验证，也不恢复“产品/日期决定标签”的旧捷径。需要舍弃的是过强的任务假设和单一压缩视图作为唯一主路线，而不是删除真实失败证据。

## 2. 本轮新增的全量证据

[完整计算](../evidence/2026-09-12/v35_direction_review/task_assumptions_audit.json)；[从官方 DOCX 原件重新提取的题目](../evidence/2026-09-12/v35_direction_review/official_task2_verified.txt)。

### 2.1 来源与标签高度绑定

- 111,728 条恶意的 product_name 全部为空字符串。17 个有名产品中，没有一个含恶意标签，13 个仅有一个观察类别。
- 按当前已冻结格式路由看，32,596 条 network_kv 全是恶意，10,620 条 vpc14 全是可疑；356,315 条原消息为空的记录全是正常。
- 上述是实际数据构成，不证明这些格式本身有风险，更不能据此推断主办方故意设置陷阱。

这也解释为什么“删除产品名后照样能猜来源”很容易发生：结构、词汇、缺失状态和采集行为仍相互关联。另一方面，若一个来源没有某类独立例子，就缺少学习该来源类间差异的直接监督。强行使各来源的特征分布完全一样，可能连真实事件类别差异也抹掉。

### 2.2 外层时间并不构成已经可信的连续行为轨迹

下列为原 timestamp 按 Unix 秒转换的 UTC 范围：

| 标签 | 最早时间 | 最晚时间 |
|---|---|---|
| malicious | 2022-06-13 07:32:15 | 2024-07-18 16:32:25 |
| benign | 2024-07-26 11:10:20 | 2024-08-22 20:11:27 |
| suspicious | 2024-07-26 11:10:26 | 2024-07-26 12:00:07 |

恶意时间与另两类完全分离；45,420 条可疑挤在约 49.68 分钟内。这是明显的类别/时间混杂证据，不能当作真实威胁随日历变化的规律。没有额外说明，不能把全部记录简单按时间排序，再做跨产品攻击链或宣称现实时间外推。

但也不能因此丢掉全部上下文：111,702 条恶意同时有非空 src_ip 与 timestamp；45184 条可疑也有这两个字段。**值存在不等于关联可靠，关联未证实也不等于永远没价值。** 源地址有 157 个值跨产品桶复用，用户名有 7 个；既不能据此认定是同一真实实体，也不能自行断言一定冲突。需要角色、命名空间和时间语义核查后，只对支持片段测试因果历史特征。

### 2.3 当前表示本身有信息限制

再次全量重算确认，75 个非空相同文本组包含多种标签，共 4,075 行。如果每种当前文本只能输出同一个类别，至少会错 1,116 行。这是该固定表示在现有样本上的经验限制，**不是任务理论上限，也不是确认有 1,116 个错标**。

Duo 的 263 行无可观察认证事实也再次确认。字面短语探测找到 473 条 Windows 登录失败、219 条 Precinct 认证失败、2 条 Duo 无效口令，均为可疑；原文抽查确认存在这些可见表达。但“本数据中出现这些词的记录都是可疑”仍不证明所有真实登录失败都应归可疑。没有主办方判定规则，暂时无法独立验证三类标签的完整安全语义。

此前确认的运算符依赖、Duo 支持缺口和来源留出失败继续成立，见 [v3.3.1 结果审查](V331_CLOUD_RESULT_REVIEW.md)。本轮没有用新的统计覆盖那些失败。

## 3. 从别人的真实经验中吸收什么

调研范围是论文方法、作者实现和实际安全系统；不是比较各自榜单 F1。项目未在本地安装或在官方 SOC 数据上复现。

| 一手资料 | 对本项目有用的经验 | 本次采纳与反驳 |
|---|---|---|
| [安全机器学习研究的常见陷阱，USENIX 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/arp) | 数据采样、标签、特征相关性、指标和部署条件可共同制造乐观结论 | 先审任务/数据/验证，不再把不断换模型作为首要动作；保留困难评价记录 |
| [Sommer / Paxson，IEEE S&P 2010](https://www.icir.org/robin/papers/oakland10-ml.pdf) | 异常分数与安全事件解释存在差距，安全策略具有环境条件 | 先声明能从哪些信息判断什么；新颖、认证失败、设备拒绝均不自动等于攻击 |
| [日志解析影响实证研究，2024](https://arxiv.org/abs/2305.15897) | 13 种解析、7 种检测方法的比较表明，解析准确率与检测准确率没有强对应关系；保留区分信息很重要 | 建立最小规范化正文与结构事实的成对对照，不以“格式统一”作为成功。论文也没有找到处处最优方法 |
| [DomainBed 作者代码](https://github.com/facebookresearch/DomainBed)、[论文](https://arxiv.org/abs/2007.01434) | 模型选择策略是域泛化算法的一部分；统一比较中简单 ERM 有竞争力 | 选参时说明用了哪些域；外层目标答案不参与选参。该论文不是“2026 年任何任务线性模型都最好”的证明 |
| [不变表示的条件限制，ICML 2019](https://proceedings.mlr.press/v97/zhao19a.html) | 标签分布/条件差异存在时，对齐边缘表示不足以保证迁移 | 不把所有来源完全对齐作为硬目标；本项目有明显混杂，但尚未独立证实具体因果机制 |
| [Group DRO 作者实现](https://github.com/kohpangwei/group_DRO)、[实际损失代码](https://github.com/kohpangwei/group_DRO/blob/master/loss.py) | 强调最差组表现，同时显示正则化/早停的重要性 | 借鉴组级评价和受控优化。小组、单类别来源与可能有噪声的标签不适合直接追最大组损失；不默认套原神经训练栈 |
| [TESSERACT 作者代码](https://github.com/s2labres/tesseract-ml-release) | 按时间组织训练、评估和更新，分开控制比例与时间偏差 | 借鉴时间一致性，先检查本题时间是否支持；不能把明显类别分离的时钟排序当作现实部署证明 |
| [Slips 实际项目](https://github.com/stratosphereips/StratosphereLinuxIPS)、[2026-08 作者预印本](https://arxiv.org/html/2608.11979v1) | 将模块证据、实体时间窗口和最终告警分开，保留支持记录 | 借鉴“事实—证据—决策”的层次；不照搬其 PCAP/Zeek/Redis 系统、不启用阻断或外部威胁情报。作者也明确指出实体合并、窗口切割、相关证据重复计分等限制 |
| [EvLog 论文](https://arxiv.org/abs/2306.01509)、[作者仓库](https://github.com/YintongHuo/EvLog) | 对软件演化使用多层表示，而不只记固定模板 | 借鉴多表示思路。当前公开默认分支仅见 README/数据链接，未核实可运行训练代码；不当成即用执行包 |
| [K4 论文](https://arxiv.org/abs/2507.20051)、[项目页](https://github.com/zazmir/K4-log-anomaly-detection-) | 解耦表示与检测、用正常参照分布识别不典型样本 | 可以参考低成本新颖性诊断；不把新颖分数当攻击三分类。当前默认分支仅见 README，不把论文中的几秒训练当完整 SOC 成本 |

此前的 OCSF/LogLead 调研继续可参考，但它们分别解决结构和工程比较，不能证明标签语义正确或未知来源可识别。

若需要语义先验，可将 [all-MiniLM-L6-v2 官方模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)作为一个明确、轻量的后续候选：384 维，面向短句/段落，相似度模型不是威胁检测器，默认超过 256 word pieces 会截断。必须检查日志字段、否定和载荷是否被截掉。**本阶段仍只使用官方数据训练，不下载该权重；预训练外部先验与新增 SOC 数据应分别披露。**

## 4. 修正后的架构方向

采用一个有明确输入支持范围的三分类器，加可审查的风险/证据输出。事实提取与必要正文并存，校准按声明场景验证；可靠关系数据出现时才加历史上下文。不是立即搭一套大型多模型平台。

1. 原件保留，生成最小规范化正文：移除已证实无关的采集身份/包装，保留真实动作、结果、否定、参数角色与完整载荷。未知边界不擅自解释，记录覆盖限制。
2. 从完整字段/原文区间抽取结构事实，与正文并存。认证失败、阻断和风险意见保持不同角色；没有证据时不补值。结构视图不能以牺牲关键事实为代价追求整齐。
3. 同一职责下比较旧表示、最小正文、正文加结构。先固定学习器，判断增益来自哪里。若线性表示仍不能对齐已核实的等价表达，再单独比较一个冻结语义候选。
4. 已知来源新组、来源完全未见、允许目标正常适配分开报告，所有原失败来源继续保留。支持不足的部分不伪造可靠性，也不从全量评分中移除。
5. 不立即建每产品一个分类器。来源只用于解释格式、监督覆盖、明确的阈值适配及审查；小来源没有可靠独立数据，单独模型只会放大记忆。
6. 最终输出仍覆盖所有 event_id 的三类标签。证据不足另附标志及复核量，不用“全部未知/全部人工”制造好成绩。事件置信度、独立攻击真值与人工确认不可混称。

## 5. 六轮对抗性自审

这是六轮围绕不同反例的主 Agent 审查，不是六个独立专家结论或六次新模型训练。

| 轮次 | 对新方向的攻击 | 处理 |
|---|---|---|
| 1：任务可识别性 | 同一个失败事件是否必然有唯一安全标签？ | 缺少规则或上下文时不能保证；保留官方评分，独立安全真值保持未验证 |
| 2：信息保留 | 保留更多原文，会不会把旧捷径带回来？ | 正文/结构成对比较，做包装与身份扰动；不能因正文分高就直接采用 |
| 3：结构泛化 | 统一字段会不会再次合并真正不同的事件？ | 全量碰撞检查与原文证据，保留参数角色；类间冲突不能靠改标签清除 |
| 4：上下文 | IP 相同、时间接近就能连成攻击链？ | 已发现时间与类别混杂；关联未证实前不生成跨产品链、不使用未来记录 |
| 5：训练目标 | 最差组优化、类权重是否一定能救小来源？ | 没有正例和独立组时无解；有界权重仅作匹配候选，真实比例全量评价 |
| 6：开源与验收 | 前沿模型、目标适配或大量复核是否能包装成成功？ | 核实仓库实际文件，分开目标接触权限；复核也计成本，保留失败与未支持项 |

本次审查后的选择不是马上再跑同类完整批次。先完成信息保留与同类异标签对照的短验证，让下一次训练回答一个能判定对错的问题：**在不恢复旧捷径的前提下，保留的正文与事实是否增加了已知困难来源的区分力，并改善严格来源外推？**

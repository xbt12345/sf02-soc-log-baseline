# v5.0：编码无收益的原因、实际训练尝试与方向修正

2026-09-14。**本轮完成 7 次拟合及独立回放。共同事实辅助训练修复了旧压力测试的 10 条认证错误，但三折新增 54 条净错误，因此当前候选不晋升。** 保留 v4.8 的原生动作解析修复；公共基准 B 未替换。官方标签、原行次数及所有划分均保持原样，未使用平台或外部训练数据。

## 1. 先纠正“之前所有方法都没效果”的判断

| 实际试验 | 观察到的结果 | 当前判断 |
|---|---|---|
| v4.4 ASA LR / CatBoost | 原三折 ASA 错误 6,018→5,131 / 4,763，同时出现分型或缺失压力退化 | 有局部收益，未满足完整要求；不能说所有非线性方法无效 |
| v4.6 协议×区域方向交互 | 相对当轮对照净减少 170 条，148 条净收益集中于一个正文组 | 不足以证明广泛迁移；不继续堆组合 |
| v4.8 原生动作解析修复 | 旧压力错误 3,988→894，实际恢复 3,188 条记录中原本存在的动作 | 修复真实信息丢失最有效，保留 |
| v4.9 观察值重编码 O | 179,075 条逐条分类不变 | 没有新增信息，停止该候选 |
| v4.9 词＋字符 T | 同一批逐条分类不变；33 条认证文本可编码，但 10 条可疑仍漏判 | 字符可表示不等于安全含义已学会，停止该候选 |

不同协议、不同对照的数字不能直接相减。O 的新旧表示可通过权重与截距变换复现同一函数，最大概率差仅 9.44e-16；改变的是固定正则化下的参数表达。T 增加拼写片段，却没有补充跨来源的标签对照。它们均没有改变“模型只在完整配套特征下使用共同事实”的学习问题。

## 2. 本次实际尝试：完整输入与部分上下文共同训练

目标对象是 v4.8 修复后的数据及三类线性分类器。新增 `v50_views.py` 和调度代码；历史模型及冻结源码不覆盖。

本轮借鉴 [Learning with Marginalized Corrupted Features](https://proceedings.mlr.press/v28/vandermaaten13.html) 的特征缺失鲁棒训练思想：改变训练时的损失条件，不能只在推理时删字段。作者也提供了 [参考实现](https://lvdmaaten.github.io/mcf/Marginalized_Corrupted_Features.html)。我们实现的是一个有限、确定性的部分上下文训练对照，**没有复现论文的解析边缘化算法，也没有把论文成绩当成本项目效果**。

训练前核实了 332 条真实原文，包括全部 314 条拟合侧凭据无效记录；原文与冻结解析一致。构造条件只看原有认证事实，不读取来源、产品、时间、标签或评估答案：

- 有相互一致的认证结果和 outcome 才生成辅助输入；明显冲突、未知结果及单纯策略允许不生成。
- 完整文本及全部原有事实保留在完整输入中。辅助输入去掉文本和配套状态码等上下文，保留认证结果、凭据状态、已观察的次数/持续时间及其他认证事实。
- 每条适用记录的完整输入、辅助输入各权重 0.5；其他记录权重 1。每个原始行总权重严格为 1，保留所有原标签；同辅助输入若对应不同标签，也不合并或改标。
- 旧压力拟合侧共 78,198 条适用记录，产生 155 种辅助输入；只由拟合侧生成。词典、IDF、事实编码与尺度直接复用对应 v4.8 对照，固定 C=0.1，无调参、阈值搜索、标签规则或新类别。

这是“缺少上下文时如何使用仍可观察事实”的统计假设，**不是证明剩余信息足以确定威胁类别**。Microsoft 对 [4625 认证失败](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625) 的说明明确区分原因，并建议结合连续事件和账号环境分析；失败不能直接等于攻击。Duo [官方日志说明](https://duo.com/docs/administration-reporting) 同样区分认证结果、拒绝原因及策略。

## 3. 结果：局部机制有效，全局候选失败

| 预先固定的比较 | v4.8 对照 | v5.0 辅助训练 | 实际影响 |
|---|---:|---:|---|
| 旧压力：总错误 / 179,075 | 894 | **884** | 修复 10、新增 0 |
| 旧压力：Macro-F1 | 0.887161 | **0.888599** | 小幅改善 |
| 旧压力：认证错误 / 33 | 10 | **0** | 9 个正文组获益，不等于 9 个独立事件 |
| 旧压力：ASA 错误 | 827 | 827 | 无改善 |
| 原正文三折：总错误 / 1,378,650 | **6,022** | 6,076 | 修复 4、新增 58，净增加 54 |
| 原正文三折：Macro-F1 | **0.959184** | 0.958839 | 退化 |
| 原正文三折：正常误报 | 16 | 16 | 原有问题仍在 |

第一次旧压力对照通过后，才按预先约定执行三折。v4.8 以前没有跑这三折，因此额外训练了三折 v4.8 对照，再各训练一次新候选，共 **1＋3＋3＝7 次新拟合**，没有重复那次成功的压力拟合。模型拟合与保存阶段合计约 106 秒；准备、读取、核验另计。

三折逐折错误：1,888→1,888；2,444→2,498；1,690→1,690。所有 58 条新增错误和 4 条修复都来自第二折 ASA；恶意→可疑增加 58，可疑→恶意减少 4。这是分型退化，不是恶意被判正常。

公共 B 的三折错误为 6,153，新候选为 6,076，表面上少 77；但同样输入修复的 v4.8 对照已降至 6,022。**不能把此前解析修复的贡献记到本次辅助训练上。** 当前候选未通过总错误、Macro-F1、ASA 和恶意召回条件，不能以旧压力局部成功替代完整验收。

## 4. 为什么认证改善了，ASA 却退化

认证侧，314 条拟合记录仅保留共同事实时，旧模型全部判正常，新模型全部判对。这是拟合侧诊断，只解释机制，不作为未见成绩。真实旧压力中：

| 认证输入 | 可疑概率，旧→新 | 结果 |
|---|---:|---|
| invalid_passcode denied，2 条 | 0.4942→0.9422 | 恢复可疑分类 |
| no_response denied，8 条 | 0.4181→0.6944 | 恢复可疑分类 |
| allow_unenrolled_user，23 条正常 | 正常概率均约 0.9998 | 保持正常 |

无响应专有原因在压力拟合侧仍无直接支持。改善来自已有“认证失败”等共同事实，不是模型已经学会 no_response 的全部含义。拟合侧 484 条失败全为可疑、77,714 条成功全为正常，正常失败及恶意成功反例仍缺失，不能据此宣称现实认证安全判断已可靠。

ASA 退化已逐条做加性分数分解，全部 58 条都能用**输入不变、共享系数改变**解释。典型记录的恶意概率从 0.500113 降到 0.499081，刚好跨过三类最大概率边界。贡献较大的项包括“不存在的 Windows status/substatus”缺失位、共享截距、action=deny 和 outcome=blocked。局部训练变化经共享参数影响了别的行为类别。

这不证明每个缺失字段都无用，也不证明 O 重编码加辅助训练一定能修好。O 已经证明仅换表达不足；本次进一步定位到了**任务之间共享参数的连带作用**。继续全局重训或扫描权重会把这个问题掩盖成调参问题。

## 5. ASA 的真正瓶颈：冷门语义与输入冲突集中

旧压力中全部 7,571 条 ASA，在拟合侧都没有完全相同的编码组合。更具体地，827 条错误的 791 条（95.65%）集中在两个输入：

| 可观察事实概要 | 该输入的原标签 | 当前错误 | 拟合支持 |
|---|---|---:|---|
| ICMP Type 3 / Code 13，outside→dmz，deny | 685 可疑＋180 恶意，共 865 条、2 个正文组 | 685 | Code 13 及 administratively_prohibited 在整个压力拟合侧均为 0 条 |
| ICMP Type 3 / Code 3，dmz→outside，deny | 106 恶意＋22 可疑，共 128 条、38 个正文组 | 106 | 该完整组合未见；Code 3 在其他方向存在 |

两种输入在当前表示下各自对应多个标签。即使事后知道其标签比例，只给每种输入一个固定类别，至少也分别错 180、22 条；ASA 全部输入的同表示有限样本最低错误数为 204。这个数不是原始数据不可约噪声的证明，更不是保证剩余 623 条能被训练消除。

RFC 1812 将 [ICMP Code 13](https://www.rfc-editor.org/info/rfc1812/) 定义为由于管理过滤不能转发。协议定义能说明发生了什么，不能据此直接把它指定为 malicious 或 suspicious。将压力评价里的多数标签硬写成规则，会制造新的答案捷径。

另有 16 条真实 ASA ACL 正常反例，本轮仍全部判错；它们在旧压力的拟合侧，所以“压力正常误报为零”没有覆盖这个缺陷。

本轮进一步完整拆读了上述 **993 条原始 ICMP 日志**，全部匹配明确的日志语法。每个输入组的动作、类型、代码及 ACL 尾部完全一致，没有发现被遗漏的原始报文载荷。Code 13 的 180 条恶意使用 dmz-1、685 条可疑使用 dmz-2；但主办方没有提供区域拓扑或风险定义，因此区域编号与标签的吻合不能证明可迁移的安全语义。Code 3 的两种标签则连 dmz-1 区域名也相同。剩余地址、日期和身份差异不重新加入分类器。

## 6. 下一步只保留两条有证据的方向

**第一优先：把已有效的认证学习限制在适用的参数范围。** 使用有原文依据的认证事实判断适用性，研究共享基线加认证专用修正的参数分离；完整输入仍可用，不以产品名、route 名、空值或预测为正常作为开关。这样才能验证“认证改善而非认证分数不随之漂移”。这一思路可参考 [Frustratingly Easy Domain Adaptation](https://aclanthology.org/P07-1033/) 的共享与专用特征分解，但原论文需要目标域监督，不能直接当作本题零目标样本迁移保证。该新结构本轮尚未训练。

下轮验收应明确区分“目标压力改善”和“原三折不退化”：局部修复不必让已经正确的正文折再次提高，但必须保持其他路由及各类安全指标。本轮三折确有 54 条净退化，因此改变未来判据也不会使本候选通过。任何新约定都需在新拟合前固定，不改写本轮结论。

**第二优先：将 ASA 的行为含义与威胁分型能力分开验收。** 本轮 993 条原文审查尚未找到足以区分冲突标签的可迁移新增事实，暂停针对这两组的编码试训。保留完整原文和现有协议含义，逐个报告“事实未见、组合未见、同输入混标”，不要把它们统称为模型不会。只有后续找到可由原文验证且在拟合侧有支持的额外差异，才修解析并做一次一致对照；原文没有提供的上下文不恢复、不猜测。真实端口只有适用时才使用；这两个 ICMP 问题不能靠统一删 TCP/UDP 端口解决。

对 Code 13 这种未见概念，下一轮同时报告单个事实支持、组合支持及概率变化；原有三分类输出继续完整提供，但不能把一个最高概率类别解释成经过校准的安全确定性。继续只使用官方数据；用现有数据可以进行受控优化，**目前没有证据说它足以支撑对任意新环境的高准确率承诺**。

暂不继续字符词典扩容、等价重编码、重复降权、评价答案阈值扫描或无目标的大模型替换。DomainBed 的 [研究](https://arxiv.org/abs/2007.01434) 与 [开源评测项目](https://github.com/facebookresearch/DomainBed) 强调统一实验条件和明确模型选择方式；本轮采用的是这种比较纪律，没有移植其图像模型或引入其数据。

## 7. 对抗性审查与复现边界

| 反证问题 | 本轮实际检查 | 结论 |
|---|---|---|
| 是不是多算了训练样本权重？ | 每个原始行的视图总权重重算为 1，标签逐行比对 | 通过 |
| 是否从压力错例制造训练答案？ | 视图由拟合侧重建，行与正文组隔离，原文支持复查 | 通过；已见开发评价仍不是盲测 |
| 是否只是编码变了？ | 对应新旧模型词典、IDF、事实矩阵一致 | 训练损失变化产生效果 |
| 局部改善是否伤害别处？ | 原三折配对比较、逐条增损、58 条分数分解 | 失败，停止晋升 |
| 未见语义是否有直接支持？ | 全拟合侧 Code 13 与无响应事实计数 | 均无直接支持，不能伪造规则 |
| 是否足以证明迁移？ | 原标签冲突、正常失败缺席、16 条 ACL 正常反例及来源限制 | 不足 |

实际回放 7 个模型，共 2,936,375 行保存概率，最大差为 0；每个模型还核验 4,319 条真实原文和等量指定包装/外层字段变换。原文种类仍只有 4,319 条，不能把跨模型重复核验计成更多独立样本。4 项测试覆盖原标签冲突、单行权重、语义矛盾和评价专属视图不入训练。

执行过程两处软件问题均已明确处理：原三折误套宽模板隔离检查，在任何折拟合前中断，续跑只修检查、不改划分、不重复压力训练；旧 v4.9 推理包装因版本号拒绝 v5.0，改用独立 v5.0 核验器完成全部回放。训练模型、原始冻结代码和中断前结果保留。

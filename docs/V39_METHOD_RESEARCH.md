# v3.9 专项研究：先检验方法的成立条件

更新：2026-09-13。此次审查对象是 v3.8 冻结 C 模型、已有官方数据与待执行 v3.9 方案。完成了原始正文核查、固定预测的决策试验、一手论文与开源实现核对，并据此修订 [当前训练方案](V39_NEXT_PLAN.md)。**没有训练新模型，没有新增平台任务，没有使用外部训练数据。**

结论：目前最值得投入的是“完整正文去重复、保留细节的共享语义、同协议受控比较”。对比学习降为有条件候选；统一抬高可疑分数、恢复接口编号、直接套用领域对抗或自动清洗标签，都不作为下一轮默认修复。尚无证据支持某个开源模型是本题的最佳解。

## 1. 新证据改变了哪些判断

### P0：865 行 ICMP 冲突，完整正文实际上只有两种

位置：旧组 2054164；[逐行摘要](../evidence/2026-09-13/v39_methods/asa_code13_audit.parquet)、[核查结果](../evidence/2026-09-13/v39_methods/assumption_probes.json)。从官方原文的 `Deny icmp` 开始截取到结尾，保留正文里的地址、接口及其他值：

| 比较层次 | 不同键数 | 是否有同键异标签 |
|---|---:|---|
| 原始完整消息，包括外层包装 | 386 | 无 |
| 去掉前缀包装后的完整事件正文 | 2 | 无 |
| 再去掉 IP、脱敏实体身份与 DMZ 数字后缀 | 1 | 有：M 180 / S 685 |

其中 180 条恶意都出现 `dst dmz-1`，685 条可疑都出现 `dst dmz-2`。**接口后缀足以解释本组标签划分，却没有资料证明其安全语义能跨环境成立。** 它可能对应真实资产角色，也可能只是样本生成关联；目前无法区分。不能据此认定原标签错误，更不能把接口编号恢复为类别规则。

这同时修正分组方案：用于去重复的正文签名必须保留这些字面值；不能先抹掉身份再拿分类向量当事件身份。但即使拆为两组，也只有两个完整正文键，不能把 386 个不同包装当作 386 个独立事件，更不能拆重复行凑三折。

对同一个保留事实向量，只增加由其确定生成的代码名称，不会创造区分这 865 行的新信息。该表示在这组已查看数据上的经验最少错误仍为 180，当前错 685。语义共享可能改善学习与多数类决策，**不能保证修复缺失上下文，更不能直接使用评价多数标签拟合规则。**

### P1：统一提高可疑分数，局部漏检减少，但整体三分类变差

位置：v3.8 C 的固定评价概率；[试验记录](../evidence/2026-09-13/v39_methods/decision_tradeoff.json)。保持所有模型参数不变，对全部记录的 suspicious 对数分数加同一个常数，再三类取最大。常数故意用已查看错例计算，只检验修补的代价，不是合格的校准或新模型成绩。

| 已查看开发数据上的诊断 | 总错误 | Macro-F1 | 可疑精确率 | 原先正确恶意改判可疑 |
|---|---:|---:|---:|---:|
| 原冻结 C | 4,008 | 0.82549 | 88.14% | — |
| 刚好修复 6 条 Windows 可疑漏检 | 4,068 | 0.81400 | 78.88% | 66 |
| 刚好修复 10 条 Duo 可疑漏检 | 4,142 | 0.79356 | 64.60% | 152 |

两次试验新增正常误报均为 0。失败原因是恶意/可疑分型与精确率恶化，不能误写成“抬阈值必然增加正常误报”。判断也没有依赖正常占多数的准确率：Macro-F1 和少数类精确率同样下降。因此舍弃这两个整体平移修补；这不证明所有经过独立验证的决策重训都无效。

### P1：有不同标签的组合，不等于有可学习的行为对照

原拟合侧进一步固定协议、动作、可观察方向和 ICMP 代码后，找到 12 个同时有 M/S 的 ASA 组合。部分组合每类只剩一个投影，不能只看数百上千行便启动对比学习。比如 ICMP type 8/code 0 的 M 798 / S 6，以及 type 3/code 3 的 M 152 / S 6，每类均只有一个投影。此统计本身不代替逐个投影冲突核对。

对照候选必须先检查：每个实际输入键是否在拟合侧冲突；两个样本是否来自不同正文重复组；除了待比较的行为值，关键语义上下文是否可比；差异是否仅为端口号、身份或脱敏编号。**类别不同不等于机制不同；分数排序更好也不等于学到了攻击因果。**

## 2. 他人的方法，具体借鉴什么

下列资料均为原作者论文、原项目或标准文本。研究结论是方法选择依据，公开成绩不作为本项目的验收线。

| 方法及已读证据 | 可借鉴的机制 | 本项目取舍及验证条件 |
|---|---|---|
| [Drain3](https://github.com/logpai/Drain3)，核对 `template_miner.py` 的聚类与 `extract_parameters` 实现 | 模板与参数分开保存；参数提取可用完整匹配，失败显式返回 | 借鉴分离方式。模板相同不代表重复事件；已知格式先用小范围、可审计解析，不默认引入完整在线挖掘器 |
| [OCSF](https://github.com/ocsf/ocsf-schema)，已读认证与网络事件定义 | 区分活动、结果、端点、协议和认证细节；来源/目的端点不总等于原连接发起者/响应者 | 借鉴最小共享事实结构；不伪称完成 OCSF 合规转换，不填造缺失身份和发起者。来源标识只服务解析与审计 |
| [TESSERACT，USENIX Security 2019](https://www.usenix.org/conference/usenixsecurity19/presentation/pendlebury) | 检查评价样本分布与时间关系是否符合部署任务，避免时空偏差 | 拆开开发插值、模板外推、来源迁移。当前时间脱敏关系未证实，不能机械采用时间顺序并宣称真实未来测试 |
| [Dos and Don'ts of ML in Computer Security，USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/arp) | 系统讨论标签、数据窥探、虚假相关和评价指标等安全 ML 陷阱 | 保留全行少数类指标、负对照、已查看数据说明。修复某项检查不等于获得部署保证 |
| [Correct-N-Contrast，ICML 2022](https://proceedings.mlr.press/v162/zhang22z.html)及[原实现](https://github.com/HazyResearch/correct-n-contrast) | 从 ERM 预测出发构造群体，再拉近同类、干扰特征不同的表示 | 仅借鉴控制配对的思路。原计划的“同上下文、不同标签”分数对照不是 CNC 复现。不能随意把不同恶意行为当同语义正对，也不能把重复采样当新增独立样本 |
| [DFR 原论文](https://arxiv.org/abs/2204.02937)及[原实现](https://github.com/PolinaKirichenko/deep_feature_reweighting) | 当已有表示保留有效信息时，最后分类层的训练分布也可能是问题所在 | 保留为后续有条件方向。原代码依赖分组平衡数据、独立调参和再拟合；当前已有线性分类器，且多来源缺对照，不能直接搬二分类代码或仅改一个偏置就称 DFR |
| [On Learning Invariant Representations for Domain Adaptation，ICML 2019](https://proceedings.mlr.press/v97/zhao19a.html) | 说明领域边缘分布对齐加源域低误差，并不足以保证目标域正确 | 暂不采用全来源对抗对齐。我们的某类流量全部为 M，强制其与以 B 为主的来源表示对齐可能混淆类别；这是一项风险推断，尚未在本项目训练验证 |
| [nnPU，NeurIPS 2017](https://proceedings.neurips.cc/paper/2017/file/7cce53cf90577442771720a370c3c723-Paper.pdf) | 二分类风险估计需要正例及来自目标总体的未标注混合样本，并处理类别先验 | 不把“某格式全为恶意”直接变成 PU 学习任务。现有其他来源正常样本不是已证实同分布的未标注混合池；本轮不引入官方验证数据来填这个条件 |

实现核查有三处直接影响方案：

- [DFR 固定版本实现](https://github.com/PolinaKirichenko/deep_feature_reweighting/blob/9d8d5de78feafb0ba99878b8a1f91c5cd942e62a/dfr_evaluate_spurious.py)把验证数据再分拟合与调参部分，按组取样并比较最差组表现；它的 `class_weight` 候选是二分类写法。当前小样本尾部无法直接满足这种选择条件。
- [CNC 固定版本采样器](https://github.com/HazyResearch/correct-n-contrast/blob/eaa1c664fd2002ed4dd45344353583dbce31fac0/contrastive_supervised_loader.py)部分不足样本场景允许有放回采样。计算上可训练，不表示获得了新的独立证据。本项目 WAF 唯一可疑正文不能因此获得独立验证。
- [OCSF 固定版本网络事件](https://github.com/ocsf/ocsf-schema/blob/c1ab05a382ffc97250997ffe010f3f715a097c2a/events/network/network_activity.json)明确提醒双向或非对称流中的端点角色歧义。因此 ASA ICMP 的 source/destination 仅保留观测方向，不推导谁是攻击者。

三个项目的 13 个文件已保留版本与摘要，包括许可证，见[源码读取凭据](../evidence/2026-09-13/v39_methods/source_receipts_git.json)。Drain3 使用网页读取，未取得本地固定提交快照。没有安装或执行这些开源项目，没有下载其训练集。

## 3. 下一轮具体怎样改，怎样判断是否有用

### 3.1 先完成两项必做改动

**第一项：重复身份与分类内容分开。** 去重复签名保留完整事件正文的字面参数，只去掉已核实的包装。协议、字段可用性、模板或删身份后的模型向量不得直接充当重复组。空正文也不能共用一个“全部相同事件”键。输出新旧合组差异、正文键数量、跨折重复及近重复疑点；旧联合组继续作为模板压力测试。此项解决评价问题，不计作算法收益。

**第二项：细节与共享语义同时保存。** 使用少量有标准或厂商定义支持的父子事实，不依赖语言模型猜标签：

| 原文事实 | 建议的最小共享表达 | 必须保持未知的部分 |
|---|---|---|
| ASA `Deny icmp … type 3, code 13` | 观测设备动作：拒绝；被观测报文：ICMP；其携带的错误类别：目的不可达；具体原因：管理策略禁止；保留 type/code | 不认定该报文就是攻击；不认定报文源是原连接发起者；不把两层“拒绝”合成攻击结果 |
| `invalid_passcode` 且日志明确认证失败 | 凭据检查：无效；认证结果：失败；保留具体原因 | 不扩展为所有失败都是恶意，也不补造凭据泄漏或暴力破解 |
| `no_response` | 所要求交互：未收到响应；只有明确结果字段才记录完整认证失败 | 不等同错误口令，不猜超时原因；政策允许不等于认证成功 |
| 新的协议或状态码 | 原码与未知语义并存；仅在标准定义范围增加父类事实 | 未见代码没有训练支持时不承诺正确分型 |

ICMP 的解释依据是 [RFC 792](https://www.rfc-editor.org/rfc/rfc792.html)和 [RFC 1812 §5.2.7.1](https://www.rfc-editor.org/rfc/rfc1812.html#section-5.2.7.1)。这里分开“观测设备拒绝”和“报文携带错误”的做法是结合原文作出的建模判断，标准没有给本竞赛的三分类答案。

共享父类让不同格式可以共用已学到的事实参数；细粒度原值避免再次扩大碰撞。但若新类别及其父类均缺拟合支持，仍无法从名称推导标签。语义修复必须另报碰撞变化，不能只报新增特征数量。

### 3.2 先比较输入修复，再决定是否增加损失

首批必做：同一新协议上，旧 C 表示三折、语义修复三折、可用性对照三折，共 9 次拟合。用原行等权、相同正则化定义和固定选择规则，避免损失缩放变化被误当输入改进。复用每折矩阵，先本地 CPU。

仅当拟合侧支持审计通过，才额外做三折行为对照候选，总量上限 12 次。对照项纳入前须满足：

1. 只用该折拟合标签构建冲突表，任何拟合侧同实际输入异标签的键，全部排除出辅助配对；普通分类损失及全行评价照常保留，标签不改。
2. 两端来自不同完整正文重复组；协议、观测方向和事件阶段等上下文可比。待比较的事实值预先指定，不能先看评价错例再挑变量。
3. 差异可回溯原文。只有数值/端口不同而缺少行为含义时，最多支持“内容关联对照”，不能作为“真实攻击行为对照”通过条件。
4. 用已有真实记录，每个正文键至多 4 个不同组对照，不用合成标签、有放回重复或全量笛卡尔积制造支持。完整损失保留原行交叉熵；辅助项按合格对均值乘固定 0.1。

若不满足，就跳过此候选，不为凑满三个方法扩大任务或自动改用复杂模型。这个辅助损失是否改善三分类仍待实测。CNC、DFR、JTT 的公开结果不能代替此处验收。

### 3.3 训练前就定义“仍未解决”

- 主要指标同时保留 Macro-F1、M/S 精确率与召回率、正常误报和全行错误账；不能以总体准确率或唯一分数决定改进。
- 同协议比较旧/新表示；对支持充分且跨正文组的任务，检查三折至少两折是否降低错误，另报模板与来源留出。原已查看评价重新分配仍是开发，不是新盲测。
- ASA ICMP 的新输入若仍冲突，明确报告冲突键、原文组和该表示经验最少错误；若只是学会两种正文的身份，不称迁移改善。
- 对无同类正常对照的流量、唯一 WAF 可疑正文等，保留所有错误，但标明缺少相应能力证据。诊断标记不进入比赛第四类，不拿来删样本提高成绩。
- 保留产品/时间/身份包装不变性。真实行为改变则检查响应合理性，不能把所有字段影响都当坏事。

| 轮次与攻击方案的问题 | 用到的反例或证据 | 修订与剩余限制 |
|---|---|---|

| 6：全来源对抗或 PU 可以填补流量正常反例吧 | 来源类别分布严重不同，缺同分布未标注混合池 | 不做缺前提的领域对齐或 PU；格式高分不能证明行为区分 |
| 7：新开发分数更高就完成了吗 | 协议改变、旧评价已查看、同文可被重复利用 | 冻结协议并同协议比较，分层报告证据；不把新开发成绩包装为外部泛化 |

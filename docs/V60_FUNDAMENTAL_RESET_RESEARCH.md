# SOC 威胁分类的路线重建与训练设计

**结论：停止 v5.5—v5.7 的共享残差、缺失分支和同表示扩训路线，重新设计学习输入、主模型与验证目标。** 新主候选为“预训练安全文本编码器＋明确的事件事实＋经核查的局部关系”，通过一个四组对照实验检验。这里的 v6.0 是研究与执行设计版本，尚未训练出 v6.0 模型。

需要推翻的是已经限制探索的前提：13 个字段足够表达所有 ASA 判定信息、屏蔽字段后每个类别都必须逐项不退化、单条日志应该支持所有真实安全结论。需要保留的是原数据、可复现基线、已有效的信息解码和暴露失败的评价记录。不能因多轮失败就删除反证，也不能把“换成大模型”当成解决问题的证据。

本报告重新核对 SF-2026-02 官方原题、v3.5 至 v5.7 的关键设计与实际结果，复算当前允许开发的 99,382 条 ASA 输入，并查阅安全运营实证、日志语言模型、预训练适配、图检测及评估研究。当前约束仍是仅使用官方 SOC 数据；研究公开方法不等于引入其训练集。全部新统计属于已观察资料上的开发诊断，不是新的盲测。

## 1. 先把真正的问题说清楚

### 1.1 官方任务与额外期望不能混成一个目标

官方题目要求输出 benign、malicious、suspicious 三类，允许传统机器学习、深度学习、图神经网络、异常检测和大语言模型辅助分析，也允许对原始脱敏消息、日志字段等建模。原题列出准确率、召回率、F1、AUC、少数类识别、速度、鲁棒性和解释性，**没有给出唯一排名公式，也没有要求采用“所有切片、所有类别错误同时不增加”的验收规则**。提交契约是完整覆盖 event_id 的 res.csv。[1]

本项目同时追求赛事分类和新环境中的可靠安全判断。两者相关，但证据要求不同：官方标签可以监督赛事分类；新环境可靠性还需要目标环境的覆盖、标签定义与可用上下文。当前没有 malicious/suspicious 的操作性定义，也没有脱敏关联保真说明。不能默认“拒绝＝可疑”“成功＝恶意”，更不能将模型的不确定性改名为 suspicious。

从第一性原理看，安全判断依赖事件、上下文和判定规则。ASA 拒绝报文说明策略匹配及处置，不能单独证明主体意图、资产是否被攻陷或业务是否允许。Cisco 对 ACL 拒绝日志的说明支持这一边界；真实 SOC 实证也区分真正攻击、攻击尝试和有业务理由的规则触发。[2][3] 这不是放弃分类，而是明确哪些区分需要新增观察，哪些可以通过更好的函数学习。

### 1.2 多轮失败暴露的不只是模型问题

| 设计问题 | 实际证据 | 新处理方式 |
|---|---|---|
| 把筛选后的字段当成充分输入 | ASA 最近数轮基本都在同一组 13 字段上训练；正文信息不直接进入主网络 | 结构字段不再拥有排除全文与关系的优先权；保留可核查的正文和候选关系对照 |
| 方法名称变化大于学习任务变化 | MLP、组合修正、共享偏移、缺失头持续围绕相同表示；v5.7 的 22 次拟合含 16 个残差头 | 终止该系列扩展；下一批只比较两个真正不同的轴：预训练能力与关系信息 |
| 验收成为没有明确业务代价的严格全项保护 | v5.7 缺目的角色：M 少错 270，S 多错 30，整体少错 240，但被直接否决 | 新实验事先定义主目标和有限退化预算，完整报告代价；不追认旧失败为通过 |
| 把极限外推和常规泛化合成唯一门槛 | 部分分折让拟合只剩 3 个行为组，校准含 15 组；有的相关供体完全移出训练 | 覆盖审查前置；同类新主体、未见目的主体、未见行为分别评价 |
| 反复提出新输入方向，却继续局部补丁 | v3.5 已建议最小正文＋事实、候选语义编码器；后续长期停留在解析及压缩表示 | 预训练编码器进入实际核心对照，不再无限延期到局部修补成功之后 |
| 核验投入被误认为研究进展 | v5.7 有大量概率回放，仍无质量晋升 | 必要核验保留，但主要产出必须是可区分假设的效果实验，而非核验次数 |

以上不意味着全部旧工作无效。原生动作恢复曾取得显著收益；这说明信息处理确实影响分类。另一方面，当前全局 Macro-F1 约 0.959 的开发结果，也不能抵消 ASA 在困难条件下对 suspicious 的严重漏识别。下一阶段仍以 ASA 为主要缺口，避免用大量容易的正常样本稀释失败。[4]

身份无关候选包括源目的区域是否相同、地址是否相同、端口是数值／不透明符号／没有提供、非空端口符号是否相同、syslog severity 与 ACL 语法。该有限补充没有减少冲突下限；这不证明所有安全信息均已穷尽，但足以停止“再加几个同类字段就会解决”的无依据期待。

这些是**未按旧外折分开的有限样本计数**，不能直接与历史按折得到的 1,970 相减，更不是模型成绩或真实 Bayes 错误。原文恢复后冲突为零，只说明原文可区分这些样本，不说明区分依据有安全意义、训练能学到，或能迁移。

### 2.2 原文直接入模同样有很大风险

本子集 7,933 个源地址和 142 个目的地址，各地址都只对应一种观察标签。区域名称也有明显混杂：源区域 `dmz-2` 有 108 条 M、22,741 条 S；目的区域 `dmz` 有 57,718 条 M、0 条 S。具体名称与标签高度相关，不能因它能降低冲突就直接恢复为分类特征。

相反，也不能据此删掉一切地址相关信息。记录“主体 A 是否访问多个目标、端点间是否互相连接、同一符号端口是否重复出现”不需要记住 A 的实际字符串。**全局一致地重命名地址，关系应保持不变。** 这种关系表示值得单独实测，但统计关联本身还不能证明它来自真实攻击行为。

### 2.3 上下文存在候选支持，但尚未证明是真实行为轨迹

7,933 个源地址中，2,829 个关联多条不同原始消息，2,795 个关联多个不同正文，2,602 个关联多个不同目的地址。99,382 行只有 29,031 种整条消息，因此直接把重复行次数当成扫描频率十分危险：它可能反映重复采样或数据构造。

使用明确的保守语法，只有 7,118 行能读出完整年月日时分秒；但 98,808 行仍能读出月、日和时分秒。**完整年份经常不可读，不等于所有相对时间都已消失。** 当前统计也不证明能够跨日、跨年份、跨设备建立真实顺序；其他日期格式尚未包含在该语法中。

所以，新路线的前置工作应是核查同命名空间中的关系、重复来源和局部顺序，而不是根据外层时间直接串攻击链，也不是继续把“时间不可信”扩展成“永远不能研究上下文”。对无法确认顺序的记录，只允许作为无序事件集合的研究对照，并明确其批处理条件。

## 3. 新调研的解决方法及适用边界

没有检索到已经在本题官方数据和上述迁移条件下证明最优的现成模型。可借鉴的是成熟训练与研究方法；下表中的公开成绩不与本项目 F1 横向排名。

| 方法与一手资料 | 解决什么问题 | 本项目采用什么 | 不采用什么／尚缺什么 |
|---|---|---|---|
| **NeuralLog**，ASE 2021 作者实现 [5] | 通过日志语义表示与序列分类，避免完全依赖模板 ID | 保留最小规范化正文，比较文本表示的实际收益 | 它的系统异常任务不能直接映射为本题三分类 |
| **LogLLM**，2024 提出、2025 修订，作者论文与代码 [6] | BERT 编码每条日志，投影至 Llama 的序列表示，分阶段训练 | 将单事件编码与上下文融合分开检验；先简单融合，再考虑大解码器 | 不直接照搬 Llama-3-8B＋4bit 脚本；原始实现默认 CUDA，处理的是序列异常 |
| **SecureBERT 2.0**，Cisco 官方模型与实现 [7] | 安全领域预训练，产生文本／代码上下文表示 | 选为主要可微调文本编码器；输出三类分类分数 | 不是现成 SOC 三分类器；不把 MLM、NER 或漏洞数据的成绩当 ASA 成绩 |
| **任务域继续预训练**，ACL 2020 [8] | 在通用预训练后适应目标领域和任务文本 | 仅在编码器实验暴露词汇适配问题时，以本折官方拟合文本做一次有／无 MLM 对照 | 不能让 MLM 看到校准、评价或官方 valid_input；降低 MLM 损失不等于分类变好 |

| **KAIROS**，IEEE S&P 2024 [10] | 用主机系统实体与事件关系进行检测及调查 | 借鉴关系、时间和事件角色分开表达 | 本题没有完整进程／文件／系统调用溯源图，不部署完整图框架来假装补齐数据 |
| **PIDSMaker 与统一 PIDS 实证**，USENIX Security 2025、持续维护实现 [11] | 统一比较复杂图检测器，揭露不稳定与实际使用缺陷 | 同数据、同协议、同预算比较简单关系统计与神经融合 | 不因“GNN／Transformer 更先进”就默认更好；多种种子全部报告，不挑最好一次 |

| **安全 ML 评估研究**，USENIX Security 2022 [13] | 将采样、泄漏、评价和运行条件共同纳入实验 | 把赛事拟合、新主体、未知行为、真实运行证据分开 | 不继续把一个压力切分称为普遍泛化，也不把所有失败归咎于数据 |

进一步检索了 2026 年系统日志 LLM 比较研究及作者仓库。[14] 其公开任务仍主要是系统日志异常，未独立复现，故只作候选检索线索，不作为选用某模型的决定性证据。新近日期、论文名中的 comprehensive 或开源仓库的存在，都不等于方法已适合本题。

### 3.1 为什么主候选是可微调编码器，而不是直接让大模型逐条聊天判断

本任务已有百万级监督，需要稳定、快速输出固定类别。可微调编码器能把训练预算用于日志表示与分类目标，并与事实特征做明确对照。SecureBERT 2.0 的官方元数据显示权重共 149,655,232 个参数；本次只读取了配置和来源元数据，没有下载或训练权重。[7]

这个选择并不是因为“小模型必然更好”，而是当前需要检验语义能力是否提供独立收益。如果同样输入上它能显著超过简单学习器，再尝试更强上下文模型才有依据。如果不能，换一个更大解码器继续回答同一条 `Deny` 不会凭空得到业务意图。

4B 级生成式模型可作为后续有条件挑战者，例如采用 Qwen3-4B、关闭自由推理输出并用三类受限评分，按相同拟合边界进行 LoRA 微调。[15] 触发条件是编码器已显示可迁移的语义收益，但在可观察、非冲突样本上仍明显欠拟合。它不先充当教师改标签，也不自动生成所谓攻击真相。

### 3.2 预训练先验与额外训练数据的区别

新监督训练和可选的任务适配只使用官方数据。采用公开预训练权重意味着利用其外部语料形成的先验，必须披露，不能表述为“模型从未接触外部语料”。原题允许深度模型和 LLM 辅助方法，但附件没有细化所有预训练许可条款；本方案不据此推断主办方已经批准某个具体权重。

本次没有下载其他 SOC 数据，没有将本地日志上传第三方模型接口，也没有修改官方标签。规则文档只帮助解释协议和动作；从规则推导出的攻击判断不能自动替代赛事标签。

## 4. 新架构：保留事件证据，让关系成为可被否证的输入

推荐结构为：**最小规范化正文＋类型明确的事实 → 安全文本编码器／事实编码 → 可选的局部事件集合编码 → 三分类头**。这是一套联合训练候选，而非在旧预测上再加残差。当前模型保留作历史参考；在新划分上比较时，简单基线也必须重新拟合。

### 4.1 单事件输入

原件原样保留。输入文本清除明确的 event_id、绝对日期、产品／厂商包装、身份原值和已确认的标签拷贝；保留动作、结果、协议、真实端口、角色、否定、载荷及未被充分解释的事件正文。风险意见与实际观察分开记录，不进行全局关键词删除。

每项移除都有原文区间和理由；未知边界不能默默丢弃整段。结构事实作为补充，与正文一致性可检查，但不再把“已经解析出 13 项”当作全文可删除的依据。产品为空走相同内容处理路径；新模型的输入及路由均不读取产品缺失标记。

真实端口保留实际值、协议和端点角色。不透明 `CRED-*` 只表示未知数值的符号，禁止从后缀猜端口；在合法局部集合内，可以检验“两个符号是否相同”这类关系。数字端口字段与文本向量同时保留，避免子词切分再次抹掉方向和值。

ASA 原文大多是固定拒绝句式，额外文本未必有新的语义。上述新审查中，有限身份无关字段未降低冲突。因此，**不会以“恢复全文”本身作为已经补齐 ASA 信息的结论**；编码器仍需面对同输入的有限样本冲突和来源支持不足。

### 4.2 ASA 的重点：不用身份字符串的关系信息

从同一已核查命名空间内构建局部关系候选：一个主体联系多少不同目标、涉及多少不同真实目的端口、相同端点是否出现不同动作、是否存在双向事件、当前事件和其他记录之间的相等关系。初期先用少量明确统计，之后才比较可学习的事件集合融合。

IP、主机或不透明标识可作为构图的连接键，但不作为模型词汇，不学习全局实体 embedding，也不查训练实体的标签比例。每个样本只暴露局部匿名节点与事件事实；匿名编号的分配不能受标签、原数值排序或数据行顺序影响。相同拓扑在全局一致重命名后应给出相同输入。

重复整条消息不能直接当作多次独立连接。关系构建首先保留“存在过哪些不同事件／关系”，单独记录重复来源未知；只有核查出可靠真实发生次数后才引入速率。这样做与曾失败的监督样本重复降权不同：官方每行及标签仍参加原训练／评价，改变的是上下文含义，不能借此偷偷降低少数困难行的训练权重。

时间只在已确认局部顺序内形成间隔和先后，不能输入日历日期。不能将年份不可读的两段日志拼为连续历史，不能跨产品复用地址就假定同一设备，也不能从当前记录之后的事件推断在线时刻的类别。

若只能建立无序集合，则先研究离线批量分类，并明确依赖同一批可见事件；这种结果不能宣称在线预警有效。若本地关联完全无法核实，关系分支必须关闭，不能用随意窗口代替事实。其余单事件模型实验仍能执行。

### 4.3 判定与解释

分类器始终输出三类，不按 ASA 路由强制排除 benign，也不把未知或空输入固定归为正常。解释先呈现实际事件事实、参与关系及缺失项；模型分数尚未校准时不称真实正确概率。可疑类别仍由官方监督定义，不能变成模型拒答箱。

如未来加入风险置信度或复核标志，应作为附加字段。赛事 res.csv 仍覆盖全部事件，困难行不从分母中消失。正常 ACL 的有限支持单独保留；百万条异类正常日志不能替代相关正常拒绝连接的验证。

## 5. 重建验证目标，避免继续被不合适的门槛困住

### 5.1 分清五种试验

| 试验 | 要回答的问题 | 输入／划分约束 | 不支持的结论 |
|---|---|---|---|
| 分组开发 | 同事件族的新正文、新记录能否识别 | 原件重复和预定义近重复组不跨拟合、选择、评价 | 不代表新企业 |
| 新源主体 | 是否离开源地址记忆仍有效 | 源主体及重复约束隔离；标签只用于训练／分层，不进入关系特征 | 目的主体可能仍见过，不能称全新网络 |
| 新目的主体 | 是否依赖固定受访资产或其结构指纹 | 另行目的主体留出，报告每类、每种行为覆盖 | 若目的主体种类少，无法得到稳定总体估计 |
| 未见行为／旧压力 | 新协议方向组合、特殊 ICMP 等是否失效 | 已有失败保留，未支持的组合明确列出 | 不应伪装为与常规开发同分布 |
| 输入干预 | 是否利用身份捷径，删除信息造成什么影响 | 区分语义保持、信息删除、真实语义改变 | 删掉端口后仍要求同答不是合理的不变性要求 |

划分先审查标签、正文、主体与行为覆盖，再开始训练；不能看成绩挑折。源／目的主体同时隔离若形成巨型组件，可分别做两种外推，**不为让每折有三类而拆散必须隔离的重复记录**。关键类别独立组件太少时报告无法估计，不通过重新洗牌制造证据。

### 5.2 将“任何一个格子都不能退化”改为预先声明的阶段目标

新计划默认以 **ASA 的 M/S Macro-F1、S 召回和一对其余类别的 PR-AUC** 为主要效果面板，同时报告三类全局结果、M 召回、正常误报及各关键切片。ASA 的 M/S Macro-F1 在全部 ASA 行上计算 M、S 两项 F1 后平均，预测成 benign 的行仍计相应假阴性，并另报 ASA→benign；不能丢掉它们再计算条件二分类。PR-AUC 用来查看排序能力，不能单独替代最终分类计数。具体定义、分母和缺类处理写入配置。

为避免下一轮再事后挑目标，以下作为**首轮是否值得继续投入的工程标准**，不是赛事规定或生产 SLA：新源主体开发评价上，ASA M/S Macro-F1 比同划分基线至少提高 0.02，S 召回至少提高 5 个百分点；M 召回下降不超过 1 个百分点。重点改进的配对组级区间应支持正收益，且三个固定种子方向稳定。若这种门槛未达到，不以几个错例修复为由继续扩训。

全局三类 Macro-F1 下降不超过 0.002，正常误报率增加不超过 0.0001，作为后续全量整合的初始保护预算；关键正常 ACL 另列全部结果与支持量。这些预算必须在新评价前冻结。若正常独立组太少，结论是该保护尚无法验证，而不是认定误报预算已满足。上述门槛只决定是否继续扩大研究，**不代表“ASA 已解决”或“可部署”**。

缺字段压力逐项报告严重退化，但不要求所有信息删除条件都优于完整证据或全部 Pareto 改善。把样本全部判 M 导致 S 崩溃仍是失败。空干预记“不适用”；目标存在却缺少某类样本记“无法估计”；两者不能写成错误率 0。

主协议按独立主体／重复簇做配对重采样，预设 2,000 次；同时保留行权重结果与组等权结果，不把两者混成一个分数。主要终点在训练前限定，不对几十个探索切片逐个挑显著性。所有旧压力与历史开发结果均已被反复观察，下一轮重划分仍属于适应性开发；真正外部泛化仍未验证。

## 6. 下一轮执行设计：一个四组对照，回答两个真正不同的问题

### 6.1 预备工作及停止点

本次已经完成原题复核、关键历史结果复审、ASA 新统计、主候选配置与公开实现依赖核查。下一项实际工作是完成关系可用性与新分组资格检查，以及平台上的编码器前向／反向小试。它们不是又一轮主模型训练。

首先为官方允许拟合范围建立统一样本清单，正文、事实与关系均按同一职责读取；保留此前受保护的数据边界。上下文、词表、编码器适配、邻居索引和任何统计都不得事先遍历评价或 valid_input。评价侧若允许接收本批无标签事件上下文，必须单列离线协议，与严格历史协议分开。

检查关系能否在一致重命名后保持、重复压缩是否改变含义、时间局部顺序是否可用，以及同一行为是否有多个独立主体支持两种标签。**结构关联能被计算，不等于已证明是有效历史。** 若资格不满足，关闭关系两组，只执行单事件能力对照；输出缺失条件，不转向无限的窗口参数搜索。

### 6.2 四个核心配置

| 配置 | 单事件输入 | 学习器 | 上下文 | 回答的问题 |
|---|---|---|---|---|
| A | 同一最小正文＋类型事实 | TF-IDF／事实编码＋线性分类器 | 无 | 新协议上的低成本参照 |
| B | 与 A 相同 | SecureBERT 2.0＋事实编码＋三分类头 | 无 | 更强预训练和微调是否改善同样输入的学习 |
| C | 与 A 相同 | 同类简单学习器，追加固定关系统计 | 经核查的少量关系 | 不靠复杂模型，额外上下文是否已带来收益 |
| D | 与 B 相同 | 同一个编码器，追加局部集合融合 | 与 C 相同的事件范围和可见信息 | 关系信息是否需要可学习融合 |

C/D 只有在关系资格通过时执行。A/C 的上下文统计和 D 可见的邻居事实必须明确对齐；不同表达带来的差异应说明，不能宣称这是完全相同特征矩阵。B/A 与 D/C 的比较也不解释为“仅参数量的纯因果效应”，因为预训练先验、编码和学习器共同变化。

先使用固定种子完成四配置，神经配置最多 3 个训练 epoch，并保留全过程学习曲线；线性配置使用预定收敛条件，不套用神经网络 epoch 计数。不将 3 个检查点称作 3 个新模型路线。先在内层达到效果门槛的候选与同协议基线补齐另外两个固定种子，最终配置固定后才读取一次外层评价；**主协议核心比较最多 12 次拟合**。未通过则终止这一轮核心路线，不在结果后追加缺失残差、供体重采样或几十个阈值。

若主协议胜出，再将固定胜出配置与 A 在预先建立的目的主体留出协议上各拟合三个种子，最多增加 6 次；不同训练成员不能复用已见过评价主体的旧模型。两阶段监督拟合预算合计最多 18 次，单独记录环境小试与拟合侧过拟合检查，不把它们藏在核心计数里。目的主体结果不再用于本轮调参；未通过就限制或否定该迁移结论。

如果关系信息仅通过某个已见目的主体的结构指纹获得优势，新目的主体试验会成为必要反证。若 C 与 D 近似，优先保留 C 的有效信息机制；若 B 与 D 不优于简单对照，不因为它们是大模型相关方案而保留。

### 6.3 初始训练配置与足量训练

编码器使用公开安全预训练权重，首轮真正微调，而不是仅计算冻结句向量后宣称测试了大模型训练。初始建议 AdamW，编码器学习率 2e-5、分类／融合头 1e-4，weight decay 0.01、warmup 10%、有效 batch 64、梯度裁剪 1.0；1/2/3 epoch 的选择只使用内层开发。种子固定为 20260915、20260916、20260917。上述是新实验的起始配置，不是已经证实最优的参数。

起始分段长度 512 token，先测实际分词长度；超过长度的日志按字段／正文片段分块并汇聚，不默默截掉尾部。结构槽位单独保留动作、否定与端口方向，检查这些信息是否在最终张量中可读。设置 attention mask，避免跨样本拼接或 padding 位置变成信号。

首轮主对照统一使用官方原标签、原行训练质量和标准交叉熵，不同时更换数据、损失及阈值。训练先在拟合侧少量非冲突样本上做过拟合能力检查；对同输入异标签不要求训练错误为零。若训练尚未收敛且组外曲线仍在改善，可在独立的新阶段事先增加训练预算；若训练已好而新主体／行为崩溃，不能靠更多 epoch 解释为“还没训练够”。

分类器默认三类 argmax。单独报告分数排序，再在独立内层选择有明确代价的操作点。新的输入没有带来排序收益时，禁止以调阈值包装成能力提升；历史统一门槛失败也不能证明所有未来表示都不能进行合理决策校准。

### 6.4 两个有条件的训练加强项

**先验不均衡的处理。** 当 B/C/D 中有稳定有效的表示，却仍表现为稀有类分数边界受挤压时，只对胜出表示比较标准 CE 和一次固定 τ=1 的训练期 logit adjustment。类别先验仅来自拟合标签，校准／评价保持原比例。公式和推理使用方式明确记录，不叠加全逆频率权重、重复降权和人工缺字段增强。[12]

**语料适配的处理。** 若安全编码器的日志 token 化／表征诊断显示适配不足，增加一次有／无官方拟合文本 MLM 的成对实验；使用相同后续监督训练配置。先验适配不能读取评价文本或答案，不能将重建出不透明身份的能力当威胁能力。[8]

这两项不是默认追加训练包，也不计入首轮四配置已执行数量；只有对应诊断出现后，单独冻结假设与预算再执行。DAPT、LoRA、标签清洗、对比损失和 GNN 不同时叠加。

### 6.5 哪些结果会让我们果断换方向

| 结果 | 解释 | 下一步 |
|---|---|---|
| B 比 A 稳定提升，C/D 没有额外收益 | 单事件表示／学习能力是可修复缺口 | 扩展 B；不增加关系复杂度 |
| C 比 A 提升，D 不再提升 | 上下文有用，简单统计已足够 | 保留 C 机制；不继续加大融合模型 |
| D 跨新主体、新目的主体都提升 | 上下文与可学习表示共同有用 | 扩展 D，随后独立测试损失与校准 |
| 只在正文开发好，新主体明显变差 | 学到身份／结构指纹或支持依赖 | 不扩训；检查局部别名、目的端点指纹与划分 |
| 原文控制很好，但去身份／主体留出无收益 | 原文优势主要来自身份关联的解释得到支持 | 停止把该原文模型当可迁移路线 |
| 四配置都无有效收益，或关系资格不成立 | 当前可用观察／标签定义不足的解释增强；不是所有算法不可能的定理 | 停止本阶段算法扩张；交付可复现能力边界与具体所缺证据，不启动同类第十三轮 |

最后一种结果可能意味着：在“仅现有官方数据、不补规则或可信上下文”的限制下，暂时无法达到期待的跨环境 M/S 判断能力。对此应明确说明无法满足，而不是再制造一个带新名称的复杂模型。官方分布分类仍可继续有界优化，但须与真实迁移能力分开陈述。

## 7. 平台、效率与执行包边界

CPU 足以完成新的数据关系核查、分组和 A/C 参照；B/D 的有效微调建议使用主办方平台。之前平台提供两张 Ascend 910B、40 核 CPU、320 GiB 内存，但这属于历史环境信息，**本次没有连接平台重新确认**。不能据此保证新权重直接运行或估计训练时长。

SecureBERT 官方仓库的 requirements 包含 NVIDIA CUDA 组件和 `torch==2.7.0+cu128`；LogLLM 实现默认 CUDA、4bit bitsandbytes。这些安装文件不能原样用于昇腾。新的训练环境应按现场 CANN／驱动、PyTorch／torch_npu 和 Python 配套表建立，保留现有可用 `cm-model` 环境。先检查单卡、单批前向、反向、保存和重载，再考虑两卡训练。[6][7][16]

本次读取还发现 SecureBERT 模型卡写最大长度 1,024，而实际配置 `max_position_embeddings` 为 8,192；配置的框架记录为 Transformers 4.52.4。不能只看宣传参数决定长上下文预算。首轮采用实际分词长度检查和较短分块，attention 后端使用现场验证可用的实现，不默认依赖 NVIDIA FlashAttention。[7][17]

模型 revision 记录为 `7f7c16d1b2316c5046759667ed97f527aa1b7709`。公开 GitHub commit API 本次受限，故仅保存实际读取源码文件的字节摘要，不声称已固定完整作者仓库。权重仍未下载；正式训练需使用固定 revision 再记录实际权重摘要。

下一执行包应包含唯一命令入口、原数据位置参数、固定配置、进度／学习曲线、断点与四组配对结果；输出一个结果包。用真实 batch 测得每秒样本、内存峰值和预计总耗时后再扩展，避免单纯因有两张卡就执行超出验证价值的大任务。当前交付的是新研究方案和已完成审查证据，**不是可以直接启动 B/D 的完成版训练包**。

## 8. 五轮反证审查及设计修改

下列是本次围绕证据进行的连续反证审查，不是五次盲测或五位独立专家结论。

| 轮次 | 对新方向的质疑 | 实际查证 | 修改后的设计 |
|---|---|---|---|
| 1：目标 | 是不是降低标准给旧模型找借口？ | 官方无全项不退化要求；旧失败有实际类别退化 | 新门槛只适用于未来冻结实验；旧失败不追认，正常与 S 保护继续报告 |
| 2：输入 | 全文＋大模型会不会只是重新记住 IP？ | 新统计中源／目的地址均为单标签；原文零冲突不代表泛化 | 身份值不入分类词汇，增加主体外推与一致重命名；原文只作单独诊断控制 |
| 3：上下文 | 关系／时间是不是换一种来源捷径？ | 重复严重、完整年份多数不可读，但大量局部时钟和多目标关系存在 | 先核查命名空间和重复来源；不猜年份、不用未来、不用实体标签；增加标签无关的重连／顺序打乱诊断 |
| 4：模型 | 能否因为 SecureBERT/LogLLM 的高分就选它？ | 原任务与本题标签不同；SecureBERT 不是分类成品，LogLLM 依赖序列 | 同数据四组对照，预训练候选必须实际微调；不复制论文成绩 |
| 5：执行 | 会不会又只有调研、核验，没有可否证行动？ | 历史上已有多次相同方向建议却未完成核心模型对照 | 固定四配置、两个信息轴、主协议最多12次核心拟合、明确失败分流；首轮不追加残差 |

关系重连／时间打乱是效果诊断，会改变可能有意义的上下文，不被当作标签不变的新训练样本。只有身份一致重命名、全局日期平移且保留局部间隔等语义保持变换，才适合要求预测不变；真实方向交换、端口删除或动作改变不能一概套用这种要求。

## 9. 当前结论与待验证事项

已经可以确定：继续围绕旧压缩表示增加共享残差和人工缺失修正，投入产出不足；此前“检查全部可读字段”并未证明表示充分；把当前源／目的标识直接输入大模型会面临极强的样本身份混杂；过严且不对应明确成本的全项保护应在新实验前重设。

尚不能确定：身份无关的局部关系是否足以改善 ASA 的跨主体 M/S 判断；预训练安全编码器是否优于简单基线；现有平台是否能直接运行所选算子；官方标签规则是否依赖数据中没有提供的上下文。这些都由新实验或现场前置检查回答。

本阶段只用官方数据已经足够执行有限的模型能力、关系信息和验证设计对照。**不需要现在去搜更多同类日志，但也不能承诺现有数据足以证明真实环境中的高正确率。** 若新的两条轴均被反证，需要的将是类别规则、可信关联、相关正常反例或独立目标环境标签，而不是更多重复行或更长训练时间。

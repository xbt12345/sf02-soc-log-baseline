## 2. 表示审查：已修复什么，哪里仍失败

第一轮实现修复了未知命令中嵌入 JSON 被误删、完整对象外的尾部被当字段删除、普通 14 词文本误识别为 VPC、部分脱敏端口被拼成有效数字、请求正文被采集器规则删除、CEF 请求参数被当日志属性删除等问题。27 项针对性测试及 17 个串行/并行处理一致性样例通过，源码可按 Python 3.8 语法解析。

全量运行后，以下问题仍然阻止主训练：

1. **191,731 行规范化文本仍匹配 IPv4。** 独立回查的 5 条真实日志证实：原文含字面 `\t`/`\n`，第一次 IP 掩码因前面的 `t/n` 字母而没有匹配，随后全局转义展开才产生匹配边界。5 例解释得到复现，但尚未证明全部残留都只有这一原因。
2. **不能简单把全局展开提前。** 合法 JSON 的 Windows 路径 `C:\\tools\\runner.exe` 和未知正文的 `C:\tools\runner.exe` 均会被当前替换损坏。下一版须取消全局猜测性展开：只在确认的合法 JSON 字符串边界内按真实转义语义处理；损坏或未知正文保留原样，在确认地址字段/转义边界处理身份。须同时保护命令路径和原文删除区间。
3. **Falcon 上游分类仍有别名通道。** 两条实际原文中，删除 `tactic/technique/description` 后，`behaviors[].tactic_id`、`technique_id`、`display_name` 仍在主文本；`detection_id/cid`、进程图 ID、文件哈希还有可记忆的残片。应在确认字段路径内隔离上游字段、处理整个身份字段值。`behavior_id` 含义未核实，先放受限对照；不能把它当已确认原子行为码。命令、父子角色、文件类型及明确布尔值应保留，动作是否在预测时可得另核。

当前 714,175 行被标为未知/受限格式，原始空消息 356,315 行，过滤后空消息 0 行。字段 `informative` 在本轮仅表示“准备文本非空”，不能解释成“已确认含行为证据”。非空文本共有 427,129 个不同值。指定日期/完整脱敏标记没有正则残留，也不代表所有身份与时间都已移除。

语义拒绝依据与原文区间见 [v3_semantic_gate.json](../evidence/2026-09-12/v3_semantic_gate.json)。不允许将当前缓存改称“纯事实文本”后直接训练。

## 3. 同输入异标签揭示的是信息边界

全量有 **49 个混合标签的非空规范化文本组，涉及 2,423 行**。对这个固定文本表示作确定性分类，即使事先知道各组标签分布，至少也会错 692 行。这是该表示在当前样本上的计数结论，**不是所有模型的通用下界、不是 Macro-F1 上限，也不证明官方标签错误**。

最大组包含恶意 346、可疑 482，都是规范化后的 ASA 拒绝 TCP 消息；另有目的端口 23 保留、源端口已脱敏的同文异类组。原文差异包含日期、实体及不能还原的脱敏端口。不能为了分开它们，重新把日期、产品缺失或脱敏编号塞回主模型；也不能猜回原始端口。需要审查剩余可见事实和其他官方记录中的可验证关联，或如实报告这一受限任务的不可区分部分。

全部计数已由独立读取程序重算。目的选取的原文对照见 [最大冲突组](../evidence/2026-09-12/v3_largest_collision_review.json)。这些组保留原标签、整体分配，不多数投票改标签、不删除困难行。

## 4. 不是样本总量少，而是分配目标错了

全量每类非空文本组数：正常 **404,236**、恶意 **16,975**、可疑 **5,967**。混合标签组会在多个类别中计数，因此不能将这三数相加作为不同组总数。

fold 0 外折以外有 **3,971 个可疑组**，但 SGKF 内层 selection 只收到 `group_id=18058`：6,746 条 ASA Firewall 可疑记录，内容为同一条规范化的拒绝 UDP、目的端口 53 消息。该组属于 outer fold 2，占该外折可疑行数的 **44.56%**。相同文本不是已确认的同一真实事件；拒绝 DNS 也不是新的标注依据。

SGKF 的按行分层没有保证每类组数和组支配程度。下一版不能仅挪入 29 个单例让计数“达到 30”——那样大组仍约占 99.6%。修改顺序是：

1. 先修表示并重新建组；表示变化可能合并旧组，故不能直接复制旧外折。仅在组约束未变且重新核对无跨折合并时，才可复用旧外折。
2. 分配前预声明每类每用途至少 30 个非空候选组；选参/校准区内，单一组不占该类非空行数的多数（首轮工程上限 50%）。两个数字均不是统计独立性或样本充分性证明。
3. 组支持为硬约束，行数平衡为软目标；只根据类别/组数/大小/来源支持做确定性整组分配或有界移动/交换，固定排序与平局规则，不读模型成绩，不换种子追分。
4. 不拆巨组、不删除巨组、不以旧用途冲突排掉整组。有界搜索未找到解，报告“未找到满足约束的分配”，不冒称已证明数学不可行。
5. 重新核对逐行用途、组不跨区、标签/总权重不变、最大组占比；新旧职责变动可追踪。对照和主模型必须使用同一新清单，并保留去最大组敏感性。

这是下一版的协议修订要求，**本轮尚未生成修复后的表示或切分，也没有放行主训练。**

## 5. N 对照：较好分数仍不足以证明目标能力

N 只在 fit＋selection 学习每种格式的类别频率；校准区只选报警阈值，外折不参与拟合。它未学习文本词表或正文词向量。格式识别包含部分动作词，且有空消息类别，所以它是“格式/消息族粗对照”，**不是完全没有行为信息的纯来源对照**。

| 合并外折指标 | 全判正常 C0 | 格式/消息族 N |
|---|---:|---:|
| Macro-F1 | 0.320094 | 0.748256 |
| 恶意召回 | 0% | 99.6563% |
| 可疑三分类召回 | 0% | 23.3818% |
| 正常三分类误报数 | 0 | 0 |

N 将全部 34,059 条 ASA 可疑判成恶意，将 10,620 条 VPC 可疑判成可疑。三个外折 Macro-F1 分别为 0.770435、0.823240、0.621354；合并外折指标不是它们的简单平均。

在校准正常误报预算 0.001 的风险阈值下，各外折观察到正常误报为 0，恶意报警召回约 99.61%–99.68%，可疑报警召回约 98.35%–98.38%。因此即使同时有“高风险召回＋零观察误报”，仍不能证明已识别同族内的新威胁。ASA 与流记录在该格式划分中没有正常反例，VPC 则只有可疑；这些缺口仍需在官方数据内部进一步诊断。

本结果用于解释分数，不能晋升为主模型；fold 0 选参支持失败仍然成立。结果、逐行概率与混淆回放见 [N 对照](../artifacts/v3_format_control_20260912/result.json) 和 [独立预测核对](../evidence/2026-09-12/v3_control_prediction_check.json)。没有运行完整来源留出或独立环境测试。

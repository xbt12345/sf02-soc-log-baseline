# 原方案重新评估与三轮对抗审查

历史阶段：2026-09-11。**当时 v1/v2 已退出主线，新方案完成设计而未实施。** 本文保留该阶段的审查证据和修改理由。2026-09-12 已完成全量 V0/V1 和 N 对照，当前批次未通过语义与全部用途组支持，见 [实施审查](V3_PREPARATION_REVIEW.md)；唯一当前方案为 [TRAINING_PLAN.md](TRAINING_PLAN.md)。

本轮由主审直接核对全量官方训练数据和原始样例，另有验证、模型两条独立审查线，分别进行了三轮挑战。采用 arch-review 的源文件与实际结果审查方式，没有用自评分或审查通过代替模型验收。

## 先纠正上一轮判断

ASA/VPC 上下文模型的可疑召回为零，是把可疑全部判成恶意，不是判成正常：

```text
ASA：[[1,0,0], [0,0,0], [0,1005,0]]
VPC：[[0,0,0], [0,0,0], [0,136,0]]
顺序：benign、malicious、suspicious；行是真值，列是预测。
```

它们在三分类上失败，但两版在校准预算 0.001 的风险阈值下，对这些可疑的报警召回都是 100%。不能据此说上下文完全丢掉了威胁检出能力，更不能永久排除协议或端口。旧说明中的相关解释已经更正；不修改原始指标。

更直接的风险报警失败是 Windows Active Directory 留出：两版在同一预算下都将 484 / 11,340 条正常报警，约每万条 426.81 次；argmax 三分类的正常误报却为零。每个成绩必须绑定同一决策规则，不能拼接不同规则的最佳数字。

依据：[来源留出原始结果](../artifacts/behavior_v2_local_20260911/source_holdout_results.json)、[本轮保存的对抗案例与原报告片段](../evidence/2026-09-11/reassessment_adversarial_cases.json)。

## 第一轮：攻击原方案的承重假设

| 严重程度及证据 | 什么时候失败 | 结论与最小修改 | 后续怎么验证 |
|---|---|---|---|
| 高：v2 29,253 行仅 11/17 种向量；112/135 恶意没有行为证据 | 不同事件被压成相同输入，再调权重也不能逐条区分 | 布尔规则退出主表示，保留为对照；新主表示保留可读文本上下文 | 统计信息丢失、输入碰撞与拟合/组外差距 |
| 高：[v2 源码](../training/soc_behavior_v2.py) 的 `quarantined = ...`、`usable = (~quarantined) ...` | 新旧组跨旧角色就全部排除，造成大组与类别选择偏差 | 舍弃维护旧角色的隔离路线，重新整体分配开发数据 | 核对全量类别×组支持、每类留存、最大组支配 |
| 高：同源码 `re.sub(r"\d+", "<number>", raw)` | 事件码、状态码和端口等语义被归为相同模板 | 禁止无差别删数字；事件重复与模板外推分开 | 4624/4625、200/403、443/3389 的语义反例必须保留差异 |
| 高：开发可疑 1 行/1 组件；校准可疑 799 行/2 组件 | 用巨量相关行或一个样本选择复杂模型与阈值 | 先审计各用途组支持，再做内外层开发；不足的指标明确 N/A | 去最大组稳定性、置信区间和单边来源可评价指标 |
| 高：三分类错误被称为威胁漏报 | 把可疑→恶意误读为正常，错误归因于上下文 | 更正说明，三分类与报警两套输出分开 | 每次保存概率、混淆、阈值和实际判定，按同一规则复算 |

主审本次实际扫描全部 2,056,871 行并核验官方训练 SHA：

- 正常 1,899,723；恶意 111,728；可疑 45,420。
- 716,699 个原始消息值，没有发现同一完整原始消息的混合标签。统计包含空字符串，null 单独编码。这不证明去掉身份后仍可区分、不证明标签正确，也不证明可迁移。
- 旧训练/开发恶意从 4,556 留存为 135，排除 **97.04%**；正常排除 52.26%，可疑排除 40.29%。无标签参与的筛选也能有强烈类别偏差。
- 全部恶意的产品字段确实为字符串空值；同一空值桶也包含大量正常。ASA 有 34,059 可疑、20 正常；VPC 的 10,620 行全部可疑。
- 356,315 条空消息全部为正常。不能据此把外部空日志默认认定安全。

依据：[全量核查结果](../evidence/2026-09-11/reassessment_full_train_verified.json)、[复现脚本](../evidence/2026-09-11/reassess_representation.py)。为修正一个统计字段名称中误写的 nonempty，重新执行核查，所有计数一致；仅保留命名正确的最终记录。

另外核对了六条指定原始训练样例：两条 flows 恶意、两条 Falcon 可疑、两条 Windows 正常，v2 行为与上下文字段均全零。原文实际含协议/端口、进程描述/命令或可读事件码；说明解析未使用现有信息，不能反推端口或某个词就是攻击真值。样例是针对性反例，不是代表性性能抽样。[原文与提取输出](../evidence/2026-09-11/reassessment_raw_examples.json)

三个合成语义反例在旧 v2 上均复现“语义字段不同，分组相同”：事件码、目的服务端口、HTTP 结果码。它们证明规则可过度合并，不证明真实数据恰有相同数量的错误合并。新分组还未实现，因此不能把该复现称为修复后测试通过。

## 第二轮：攻击新文本方案

新候选确定为受控文本 TF-IDF＋正则化线性三分类，结构字段作增量候选。两条审查线继续尝试推翻它，促成以下修改：

| 反例或漏洞 | 已写入当前设计的修正 |
|---|---|
| 去掉产品列，字符片段、字段顺序、REJECT OK 仍能识别来源 | 加可确认格式类别的负面对照；检查同格式异类及词/字符身份扰动，不把格式可预测本身当作失败 |
| 一句检测说明同时包含篡改动作与“可疑”结论；整句删除会丢事实 | 以字段路径和原文区间审查；未知正文不叫纯事实；包含/剔除说明的收益不能直接归因判词 |
| 先按唯一消息或组等权，会改变类内分布，校准无法保证恢复 | 首轮原始每行等权；类别/组/抽样权重分别记录，新轮次才增加权重对照；校准不承诺恢复未知目标域 |
| 原始空、过滤后空、纯 OOV 都可能变零向量并高置信判正常 | 三种状态分别记录支持、分数、误判；完整计入评分，不能靠 needs_review 标记跳过质量问题 |
| 30 组可能是一个巨组加 29 个单例 | 加最大组占比与去最大组稳定性；30 只是运行筛查，不是统计充分性 |
| 原始消息不同，规范化后相同，可跨开发折被记忆 | 经过审计的非空规范化全文重复纳入分配约束，保存跨折重合；词袋碰撞另统计 |
| 看到外层成绩后再决定 C 或加权，会反复适配外层 | 固定 C=0.1/1.0、内层 Macro-F1 和平局规则；重拟合职责明确；加权另开登记的新开发轮次 |
| 线性拟合差可能是无法表达关系，不一定原文无信息 | 先查优化收敛与信息损失；可观察事实足够时允许针对组合的浅非线性对照，embedding 不直接上场 |

这些是设计修正，不是已运行的新模型结果。现有证据只能支持这个方案比继续调 v2 更值得做一次受控实验。

## 第三轮：攻击执行和最终交付边界

| 最后反例 | 当前设计中的约束 |
|---|---|
| 重复聚合后 sample_weight=n 恢复了分类损失，却没恢复 TF-IDF/词表 | 原始行频率学习词表、DF/IDF；一致向量化之后才聚合监督拟合，或验证等价加权统计 |
| 留出某来源时复用包含它的词表、校准映射或阈值 | 每个完整留出重建整条学习链；受限复用只能标为消融 |
| 不用时序模型，但文本里的 triaged/resolved 仍可能是未来回填 | 固定收到事件时的判断目标；核实字段可得时点，未知事后信息进入受限诊断 |
| 把折模型阈值移到最终全量重训模型，仍沿用旧低误报成绩 | 表示、模型、校准和阈值身份绑定；最终实际包独立校准/回放，数据用尽则不能宣称该保证 |

两个独立审查者均未发现需要再次推倒新主线的原则性缺陷，以上执行边界已经补入方案。**最终状态仅为“设计审查完成，待 V0/V1 实施验证”。**

## 新方案要补强什么

执行顺序已经改变为：

1. 用全量官方训练数据建立有类别支持的开发协议，审计重复、近重复、模板和来源，停止继承旧角色。
2. 建立保留片段、删除区间、未知状态可追踪的规范化；保护语义变化，验证身份和日期等无关变化。
3. 在同一协议中比较文本 C1 与增加可信结构字段的 C2；旧规则和格式查表只作负面对照。
4. 分别检查三分类、风险排序和固定阈值误报，必要时再做独立校准，不能只选最高分。
5. 对当前缺少对照的来源定向补样本；用独立环境检验迁移，外部训练资格和标签含义另核对。

官方数据足够启动新的开发，并不保证最终能支持所需迁移。需要补的是同来源/同采集条件的相反类别和独立环境，不是堆相同模板；已经确认 ASA/VPC、空字段与标签关系存在结构性覆盖缺口。原始数据可能还有未利用的格式反例，应先挖掘再采购或大量混入外部训练数据。

新方案仍有五个未测承重假设：规范化保住真正有用的信息；文本收益不由来源或判词残留主导；分组没有严重过合并/漏关联；官方标签存在足够可比较的行为依据；新环境标签与校准条件可以成立。方案审查不能消除这些不确定性，首次实现和独立评价必须能推翻它们。

本轮没有训练 v3，没有调用云端或昇腾卡，没有下载或混入外部数据，没有对外发送消息。旧实验源文件与模型未改写；主方案和错误说明已经更新。

# v4.7 方向重审：先修复证据链，再决定怎样学习

日期：2026-09-14。**是的，最近几轮的研究优先级和部分输入处理出现了方向性偏差。应暂停“下一轮优先校准 ASA”，把主线改为：完整理解日志语义 → 恢复被遗漏的真实证据 → 在困难模板上验证 → 最后才做模型与概率优化。** 这不等于所有旧模型无效，也不证明现有数据完全不可学。

本轮重新核对题目 DOCX 原件、全量产品/标签分布、两套历史评价、实际解析源码、4,026 条相关原文以及厂商文档。完成一次不训练的冻结模型推理诊断。**新分类器拟合 0 次，生产解析器和模型没有修改。** 本文替代 v4.6 第 4 节的下一步优先级；v4.6 的结果与失败门槛仍原样保留。

## 1. 这次找到的直接证据，足以改变下一步

### 1.1 一直优化的部分，并非困难协议中最大的失败来源

重新按路由核算已有 v3.9 基准 B 的两套评价：

| 评价协议 | ASA 错误 | native_flow 错误 | 全部错误 |
|---|---:|---:|---:|
| 正文分组三折开发，1,378,650 行 | 6,018 | 76 | 6,153 |
| 旧宽模板及部分来源压力，179,075 行 | 827 | **3,144** | 3,988 |

两行对应不同训练/评价职责与模型，不能直接把差值当成同一模型的退化量。但它们清楚显示：**看起来占主要问题的路由，会随验证任务改变。** 在困难协议中，native_flow 占全部错误约 78.84%；ASA 以外共有 3,161 条错误。

最近的 ASA 条件分类器既不处理 native_flow，又冻结公共 B 的正常判定。即使 ASA 恶意/可疑分型完美，也不能修好那些范围外的错误。保护边界原本是局部实验的防回归手段，却逐渐变成了整个项目的能力上限。

**修正：B 保留为不可覆盖的实物基准，但它的每条预测不再被视为永远正确。** 后续有证据的修复可以纠正“恶意被判正常”，同时单独审核正常误报与范围外退化；不能用永久冻结正常边界来宣称系统安全。

### 1.2 真实的动作信息被解析器遗漏了

来源位置：冻结执行依赖 `v37_representation.py` 的 `network_fields()`。该函数已经捕获 `pattern`，但动作只读取独立的 `allow/deny` 或 `decision`，随后返回的事实没有使用 `pattern`。`v38_representation.py` 又把这类由结构生成的正文清空，未解析的动作也无法从文本分支补回来。

下面两种写法都可能表达设备拒绝流量：

```text
flows deny src=... dst=... protocol=tcp ...
flows src=... dst=... protocol=udp ... pattern: 1 all
```

第二种写法中的 `1` 不是在这里猜出的风险编号。[Cisco Meraki 官方说明](https://documentation.meraki.com/Platform_Management/Dashboard_Administration/Operate_and_Maintain/Monitoring_and_Reporting/Syslog_Server_Overview_and_Configuration)明确说明该入站规则字段的 `1=deny`、`0=allow`，并给出对应日志样例。[官方事件类型表](https://documentation.meraki.com/Platform_Management/Dashboard_Administration/Operate_and_Maintain/Monitoring_and_Reporting/Syslog_Event_Types_and_Log_Samples)同时解释了独立 `flows deny` 写法。

本次仅在已经通过原 native_flow 完整语法的消息内审查该动作，不把任意数字 1 解释为拒绝，不根据标签决定映射，不从设备名或产品空值推断风险。

| 旧协议职责 | 原始形态 | 行数 / 正文组数 | 当前解析结果 | 厂商语义支持的结果 |
|---|---|---:|---|---|
| 拟合 | TCP 独立 deny | 790 / 94 | deny | deny |
| 拟合 | UDP 独立 deny | 48 / 6 | deny | deny |
| 拟合 | 协议 47，pattern: 1 | 8 / 1 | **动作缺失** | deny |
| 压力评价 | UDP，pattern: 1 | 2,858 / 472 | **动作缺失** | deny |
| 压力评价 | ICMP，pattern: 1 | 322 / 52 | **动作缺失** | deny |

允许开发的 4,026 条 native_flow 中，**3,188 条遗漏了可解释的动作**。压力部分 3,180 条全部受影响。这不是“模型一定需要更大容量”，而是训练多数形态有动作、评价形态的等价动作却被丢弃，形成了人为的表示差异。

这也修正了“减少原始字段影响”的操作原则：**应该排除没有安全含义的身份关联，而不是仅凭字段是数字、很强或以前未解释，就丢掉它。** 有上下文和标准定义的编码，应先译成事件语义。保留的是 `action=deny`，不是把原编码作为标签捷径。

### 1.3 不重训的诊断已经显示，这个问题值得先解决

从 4,026 条官方原文重建当前事实，逐条与冻结准备数据核对。随后在审查副本里补回缺失的 `action=deny` 与 `outcome=blocked`，使用**同一个冻结压力模型**做成对推理：

| 3,180 条 native_flow 压力记录 | 原输入 | 语义修复审查副本 |
|---|---:|---:|
| 官方恶意被判正常 | 3,144 | **0** |
| 官方恶意被判可疑 | 0 | 48 |
| 官方恶意判对 | 36 | **3,132** |
| 全部错误 | 3,144 | **48** |

净减少 3,096 条错误；原输入的保存概率精确回放，最大差为 0。该成对诊断使用同一评价行、同一模型和同一标签，变化仅来自已核实的语义补充。

**它是输入修复的价值证据，不是重训结果或新的正式成绩。** 拟合侧也有 8 条需要一致修复；本批 native_flow 全标恶意，没有同族正常反例，因此不能从这个结果推导正常误报率，更不能写成“deny 就等于 malicious”。不同实验协议下的 3,096 与 v4.6 的 170 也不能直接做倍数比较。

## 2. 第一性原理：目前真正错在哪里

判别质量取决于三个不同条件：输入是否表达了事件事实；监督是否覆盖要判断的情况；验证是否检验真实使用时的变化。换模型只直接作用于学习部分，不能代替前两项。

| 严重性与具体问题 | 已有证据 | 本次取舍 |
|---|---|---|
| P0：先压缩成少量字段，后围绕剩余字段反复优化 | 原生规则动作遗漏，正文清空后失去补救路径 | 先审语义覆盖；未解释片段保留审计位置，不能自动当作无价值删除 |
| P0：把局部 ASA 优化当成全项目主线 | 困难协议约 79% 的错误来自 native_flow，局部头无法处理 | 改为按“错误影响 × 独立正文覆盖 × 证据可修复性”安排优先级，不只追总开发分数 |
| P1：把所有字段依赖都视为坏事 | 标准编码 1 实际表示动作，真实端口也可能有信息 | 身份包装、设备动作、业务上下文、事后结论分别判断；做语义等价与语义变化两类测试 |
| P1：把校准排在恢复证据之前 | 校准只映射旧模型分数，不能读取被丢弃的动作 | 校准降为最后一步，暂停上一版的 36 次内层拟合计划 |
| P1：只在容易协议达标后才检查困难协议 | 多次 ASA 实验没有走到旧模板压力 | 困难协议提前作为首个筛查；同时保留正文开发对照，不能用换分组制造成绩提升 |
| P1：用所有切片绝对不退化代替目标判断 | 14 条可疑退化、微小 AURC 变化成为停止点，但更大的范围外漏检未处理 | 事先明确主指标、正常误报约束、正文敏感性及逐项退化账；局部门槛不再决定是否检查根本缺陷 |

上一轮在现有表示中仅剩 6 条差额的结论，只针对“遮掉两端端口”的特定 ASA 子集。**不能把这个有限样本界限扩大成全项目已经没空间。** 本次遗漏的 native_flow 动作就是反例。

这一研究优先级调整也符合安全机器学习研究对采样、特征语义与评价失真的警示：[Arp 等，USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/arp)。引用的是研究方法，不是声称该论文已经证明本项目的新结果。

## 3. 新方向：可追溯的事件事实，加有支持边界的三分类

不立即换大模型、GNN 或异常检测栈。先沿用现成学习器，把输入处理变得可靠：

```text
原始脱敏日志
    ↓ 按确证语法读取，保留原文位置与解释依据
事件事实：动作、结果、协议、可用参数、否定与必要正文
    ↓ 使用官方标签学习；保留未知、冲突与支持不足的审计说明
benign / malicious / suspicious 三分类
    ↓ 在独立于拟合的数据上检查概率与风险
校准、解释和完整提交输出
```

这是对已有解析和分类流程的纠正，不是新增一套大型系统。来源格式可以选择解码方法，但不直接决定风险类别；原文中的证据位置用于解释，不等于分类标签已经有独立攻击真值。

**否决四个看起来容易的替代方案：**

- 直接恢复所有原文/编号：可能恢复旧的身份和时间捷径。仅恢复有明确语义依据的事实；未知部分先保留在审计侧。
- 把所有拒绝、认证失败判恶意：当前数据里就有标为正常的 ASA ACL 拒绝事件；设备处置和攻击性质必须分开。
- 用异常检测代替三分类：罕见不等于攻击，而且本题没有足够可信的各环境正常参照。安全事件解释与异常分数之间存在语义差距。[Sommer / Paxson 原论文](https://www.icir.org/robin/papers/oakland10-ml.pdf)
- 让大模型补全攻击链或改标签：缺少脱敏关联真实性和主办方标签细则，不能把生成结论作为新的监督事实。只有未来发现现有方法不能解释的真实文本证据时，才比较额外语义编码器。

## 4. 下一步最小执行计划

### 第一阶段：只修原生动作解释

建立新版本的解析适配层，依赖冻结旧版本，避免修改历史模型的加载依赖。只针对已核对的 Meraki 原生语法，将有定义的 pattern 动作转换为现有 `action/outcome`；原时间、IP、设备名、产品名与规则尾部地址均不进入风险特征。

同一适配层同时用于训练、评价与推理。记录动作来自哪个原文区间以及哪个解释规则。未知值、歧义或独立动作与 pattern 冲突时保留未解决状态，禁止静默按有利标签选一个解释。新固件格式尚未在本批错例里确证，不因文档列出就顺便扩大支持范围。

验收包括：

- 覆盖已定位的 3,188 条动作遗漏；其他字段和不相关路由没有意外变化。
- `flows deny` 与对应 `pattern: 1 ...` 在相同其余事件事实下得到一致语义；`0/allow` 得到允许，而非同样判拒绝；未知数字不猜测。
- 改变身份、日期和脱敏编号不改变对应事实。改变真实动作则必须改变事实；这种构造测试只验证语法和语义，不计作带攻击标签的新增训练数据。
- 原文动作修复不能直接修改 malicious/suspicious/benign 标签，也不能把空产品、缺字段状态当成新的分类规则。

### 第二阶段：先做一次困难协议的一致重训对照

复用已冻结的旧宽模板/来源职责、原行次数、标签、学习器和 C=0.1。基准模型已核验，可直接复用；只新增**一次**使用修复后训练输入的同配置拟合，评价也使用同一新解析层。保留本次冻结模型推理修复作为归因参考，但不把它冒充一致重训。

首要回答的是：补回动作后，3,144 条正常漏判是否稳定减少；48 条剩余分型问题如何变化；收益覆盖多少正文，而不是单个重复组。必须同时报告全部三类指标、全部正常误报、native_flow 及其他路由的逐项退化。

这一旧压力集已经看过，只是高价值开发压力，不是盲测。它提前执行是因为更贴近已发现的失败，不能在不通过时重新选一个容易的划分。

### 第三阶段：通过后再做原正文三折回归

使用同一修复、同一冻结参数，完成原三折的对应候选，总计再新增三次拟合，不加模型搜索。检查其他路由的概率和分类变化，尤其是正常拒绝事件、认证失败、少数恶意与可疑组。新的原始行指标必须与正文层面统计并列，保留最大重复组贡献剔除后的敏感性诊断。

当前正文开发集的 ASA ACL 路由有 16 条正常记录，基准已全部误报。它们是对“拒绝即攻击”的真实反例，不能因为不是本次主路由就不报告；也不能把它们与 native_flow 同族正常样本混称。

在执行第二阶段前冻结具体接受标准：至少包括三类完整混淆矩阵、恶意判正常、每万正常误报、Macro-F1、正文净改善/退化及来源/模板支持范围。正常误报不能被百万条容易正常样本稀释。未给出实际运营风险预算时，先报告成对权衡与回归，不自行宣布可以部署。

### 第四阶段：只有表示和区分表现稳定后，才考虑校准

如果主要剩余问题确实是概率偏差，再用正文组隔离的内层样本外分数做小规模校准。校准是将分数映射为更可靠概率的步骤，不能补出旧分数里没有的信息；其数据应与底层拟合隔离。[scikit-learn 官方校准说明](https://scikit-learn.org/stable/modules/calibration.html)

若第二阶段没有复现输入修复收益，首先核查解析一致性、特征编码与拟合分布；不马上追加十几个模型。如果真实动作已保留而错误主要落在无支持或同事实异标签范围，记录边界并停止对应无证据的参数搜索。

## 5. 数据是否够用，必须分目标回答

题目原件要求三分类及完整 event_id 输出，没有给出 malicious 与 suspicious 的操作定义。用户也已确认没有其他说明。

本次重新统计 2,056,871 条官方训练数据：111,728 条恶意的产品名全部为空；17 个有名产品中，13 个只出现一个标签。仅删产品字段无法补齐缺失的同场景类别对照。当前开发 native_flow 的 4,026 条全部为恶意，正常支持为 0。

**官方数据足够执行这次语义修复与有边界的竞赛模型比较，不足以单独证明任意新环境的可靠威胁识别。** 继续遵守只用官方数据的约束，不下载其他训练集、不改标，也不把语法构造样本算作真实正常/恶意样本。可以改进已有证据的使用；不能把不存在的正常对照、资产角色与攻击上下文通过算法补成已验证事实。

这不是将现有标签宣布为错误：现有资料无法区分标签来自额外上下文、策略差异、样本构造还是标注问题。三分类成绩与独立安全语义可靠性应分别陈述。

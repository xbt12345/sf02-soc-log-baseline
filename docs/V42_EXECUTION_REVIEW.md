## 1. 两个重点具体怎样落地

**公共模型冻结。** 原 B 的词表、事实编码器、系数和截距完全保留。新 R 仅在适用上下文上学习恶意/可疑的局部分数偏移；各上下文没有共享的新参数。正常概率和正常/非正常最终判定逐值保持 B；范围外全部三类概率保持 B。它避免修 ASA 时再次影响 Duo、Windows、CEF，不能修正这些记录已有的错误。

**支持范围按完整组合判定。** 不用产品名、外层时间、IP、用户名或标签作为支持键。语义和必要观测完整，且全部语义正文与事实的组合在本折拟合侧至少出现于三个不同正文键，才允许修正；重复一百次仍只有一个正文键。单个协议或端口见过不够，未知完整组合回到 B。ICMP 不需要不适用的端口，但要求 type/code 完整。

R 每个上下文的偏移带固定 L2 惩罚 10，条件恶意/可疑赔率最多改变两倍。三折分别拟合 67、51、60 个局部参数。G 将旧 P 的分数提议放入完全相同的范围和幅度保护，不重新训练，只作对照。没有改用重复降权、全局类别偏置或结果后的参数搜索。

## 3. 为什么没有收益：本轮方案自身的局限

### 3.1 支持范围只触及 0.565% 的 ASA 错误

训练前已知道合格评价范围只有 2,750 行，约占 ASA 的 2.57%，其中恶意 2,716、可疑 34、正常 0。结果后进一步确认：这 2,750 行仅包含 **34 / 6,018** 条 ASA 错误，其余 5,984 条完全不允许修改。

| ASA 按首个阻断理由归类 | 记录数 | 基准错误数 |
|---|---:|---:|
| 源端口不可用 | 33,670 | 4,076 |
| 目的端口不可用 | 11,724 | 142 |
| 完整组合未见 | 54,103 | 865 |
| 不同正文支持不足 | 4,204 | 901 |
| 端点角色缺失 | 502 | 0 |
| 允许修正 | 2,750 | 34 |

这些理由依检查顺序互斥分组，不能理解成每条记录只有一个缺失字段，也不能推断“缺源端口导致了误判”。它们说明当前门控挡住了哪些错误。

**这暴露了我的方案取舍过于保守：要求完整语义组合完全一致，已接近受限记忆表；它能防止不可靠外推，却难以学习新组合。** “足够的相关语义证据”不能长期被等同于“所有字段都齐全且完全相同”。保留冻结公共模型的职责边界，停止把该精确匹配小修正当成主要迁移或提分方法。

### 3.2 固定幅度与晋升条件在本批记录上不兼容

对结果做只读上界分析：假设事后知道每行正确标签，给出允许范围内最有利的偏移，三折最多能修正 **2 / 0 / 0** 条错误，且两条属于同一个正文键。即使这个不可用于预测的理想答案也达不到“两折改善、三个正文键修复”。

因此，本轮失败不能仅归为优化器没有训练好。这组范围和幅度在当前评估上根本没有足够的可改善空间。该分析使用评价标签，只是事后解释，**没有把答案用于训练、重新选幅度或放宽本轮验收**。下一轮应在既有开发资料中先检查错误覆盖与可改善空间，再冻结新的比较；不能让保守约束组成一个必然无收益的实验。

### 3.3 支持充分也不等于类别可区分

合格范围的 34 条错误全部是可疑判恶意，集中在 5 个“折×语义上下文”中。例如，同一 ICMP 回显请求上下文，拟合侧 484 行全部为恶意、来自 111 个正文键，评价侧却有 6 条可疑来自 2 个正文键。另一 ICMP 上下文拟合侧为 84 条恶意、2 条可疑，评价中的 20 条可疑仍被判恶意。

这说明正文支持数量不是类别信息质量的替代品。偏移只看同一输入的标签分布，不能区分被当前表示压成相同输入的个体。更强地追随多数类，甚至会提高原有错误的信心。这里观察到的是**规范化语义冲突**，不是已经证明官方原始标签错误；不得自动改标签或将少数类合并。

证据：[覆盖、极限幅度与冲突诊断](../artifacts/v42_local_r1_20260914/scope_diagnosis/diagnosis.json)。

## 4. 原文复核发现：重点是脱敏后信息不可读

对上述 4,076 条源端口不可用的错误逐条读取官方原文，共 1,990 个正文键：**4,076 条源端口槽位全部含脱敏占位符**，例如 `/3CRED-31030`、`/ORG-1721`。其中 160 条真值为恶意、3,916 条为可疑。

这里既不能把 `3` 当作完整端口，也不能把 `31030` 当作端口恢复结果；占位符映射并未提供。当前审查未发现这批记录中存在可完整读取、却被遗漏的纯数字源端口。该结论只覆盖这 4,076 条和明确的源端点语法，不是全数据所有字段的解析正确性证明。

初版辅助诊断用“纯数字端口”正则，把这些槽位误记为“端口省略”。原文复核后，已改为完整槽位读取并增加数字前缀加占位符的反例，再跑全部 4,076 条。**修正仅涉及诊断用语和统计原因，训练源码、门控和模型预测未变。** 正式结果是 [missing_context_review_v2.json](../artifacts/v42_local_r1_20260914/missing_context_review_v2.json)，其中绑定初版摘要并说明替代关系。

## 6. 下一步应如何调整

**保留隔离改动的边界，舍弃“完整精确匹配加小偏移”作为主提分路线。** 不再原样重复 R/G、增加正则参数搜索或仅因为训练顺利就上平台扩训。

1. **先审查错误中的可观察信息，目标优先落在 4,076 条脱敏源端口错误及 901 条支持不足错误。** 将“真实可读、脱敏不可恢复、该协议不适用、解析失败”分开记录；状态用于审计和适用性约束，不直接学习成类别暗号。已确认的脱敏端口不再尝试从占位符数字恢复，也不通过产品、时间、IP 身份补回。
2. **把“每字段齐全”改为“所需行为证据充分”的待验证假设。** 源端口脱敏不必否定全部日志，但协议、方向、目的服务、动作或结果能否支持分型，必须在拟合侧获得同等观察条件下的恶意/可疑对照，并经完整组合留出检验。若对照不足就记录不足；不得仅凭常见端口、缺失模式或类别比例硬判。当前尚未训练这类新方法。
3. **单独处理相同语义的混标组。** 回查原文是否有被过度删除、且能解释行为差异的字段；只有观察证据可恢复才改表示。原文已脱敏或只有身份差别时，不自动多数票改标，也不把“支持正文多”当可靠类别证据。报告可区分部分和信息受限部分，保留题目三分类契约。
4. **先做开发侧效用预检，再决定是否训练。** 看目标错误覆盖、类间对照、跨组合支持及约束下能否改变决策；配置与评估目标若明显不兼容，训练前停止。任何有依据的新表示只在限定局部分支比较，公共 B 与非目标记录继续固定；重新冻结候选与门槛后才做下一轮，已看过的数据始终按开发或压力资料报告。

官方数据仍可用于这些诊断和同协议比较；但 ASA 开发记录没有正常类，无法证明现实同类正常流量的误报率。用户要求暂只用官方数据，因此不补外部数据、不造正常标签、不声称本轮解决了迁移问题。原生 Windows 失败状态的 378 条记录也仍缺正常对照，本轮没有借修 ASA 再训练认证补丁。

## 1. 这一轮只解决三个决策

1. 认证回退主要来自有限值换码、无尺度补偿的去副本，还是两者相互作用？
2. 仅加入参数主效应/交互，能否获得 ASA 改善而保住认证和未见输入？
3. Windows 原文已有的状态事实，如何可靠进入模型；其效果必须与前两项分开评价。

顺序为“验证输入和对照隔离 → 九次单因素拟合 → 根据结果决定是否做一次独立解析修复比较”。不一开始拼接三个改动，不进行新的权重或 C 搜索。

本次已经完成：三对副本的全开发输入/系数核查、等价尺度的冻结模型分数校验、全部端口换码影响检查，以及 18 条 Windows 退化原文的状态候选核查。

实施前还需完成：

- P 的类别词表和联合支持与 v4.0 同折构造一致：参数为源/目的端口与 ICMP type/code；交互仅为协议×源端口、协议×目的端口、ICMP type×code、action×协议；联合项至少三个不同拟合正文键。不存在时不生成“缺失×缺失”。

## 3. 阶段 1：三项单因素对照，共九次新拟合

全部 C=0.1、原行等权、完整三分类，无重复降权、类别偏置、伪标签或报警门槛。每个分支固定三折，不按第一折结果选择停止某个不利分支。

| 分支 | 相对 B 唯一改动 | 目的与比较对象 |
|---|---|---|
| P：参数分支，先执行 | 只加 v4.0 相同的参数主项与限定交互；保留 B 的有限码和别名 | 与 B 比较局部增益；与 I 比较整套编码调整的附加影响。仍是对照，不承诺原缺省结构可部署 |
| F：有限码诊断 | 仅用合法值 n+1、缺失零码；保留 B 的全部枚举与事实副本 | B→F 单独测有限码影响；F→旧 N 测该编码下去副本影响 |
| D：去副本诊断 | 只执行 v4.0 的两种别名合并，使用原 B 有限码，先不作尺度补偿 | B→D 单独测直接删副本的影响；D→旧 N 测去副本后换码影响 |

这样，旧 B、旧 N 与新 F、D 组成完整的两个因素开/关对照；P 单独回答最有希望的参数改进能否保留。F、D 首先用于归因，不因某个总分较高就自动成为部署候选。R 已证明单纯放宽全局 C 不能解决 ASA，首批不重复搜索。

预期决策：

- 若 D 明显损伤认证而 F 不损伤，优先修正去副本的特征尺度/惩罚；不恢复两份“独立证据”的说法。
- 若 F 明显损伤而 D 不损伤，停止全字段 n+1 换码路线，单独设计实际受影响字段的表示；不归咎于缺失必须参与预测。
- 若二者单独可接受，只有 N 组合失败，记录相互作用，停止强行组合。
- 若 P 改善 ASA且守住全部退化线，保留参数分支；若 P 仍造成其他行为族回退，说明共同再拟合也可能有干扰。后续才考虑冻结基准、仅学习语义限定的增量，不能本轮偷偷新增该模型。
- 若 P 也使未见参数更差，停止精确参数项扩张，回到支持覆盖和可迁移关系审查；不自动上树、EBM 或更大语言模型。

## 4. 阶段 2：最多一个原生认证解析修复对照，三次拟合

仅当阶段 0 的全范围原文审计确定可实施的边界，且阶段 1 已结束并固定解释时启动。以 **B 为唯一参照**，不叠加 P/F/D，不改标签、类权重或全局 C。这样可测解析事实的增量，而不会再混入参数变化。

该分支将已确认原生 Status/SubStatus 转为有来源位置的事实；检查是否沿用已有事实及状态码表示。原文重复载体只算同一观测，冲突不静默覆盖。如何替换正文中的对应状态值、避免新旧载体重复助分，须在阶段 0 覆盖审计后写入独立配置；不能看到拟合成绩后修改。正文发生变化时，词表只能在对应拟合侧重新构造。

执行前全量审计覆盖允许开发的 962,244 条 Windows 记录，进一步解析全部 95,278 条已识别认证记录：378 条失败认证有可确认的 Status/SubStatus，其中 357 条原来已有结构化状态事实，21 条仅正文保留状态。94,900 条成功认证的标题被脱敏，保持原 B 处理，不把未识别标题当作真实事件冲突。

本轮 A 固定如下：仅接收唯一原生认证 provider/code 与匹配完整标题；正文状态限定在 `Failure Reason` 后连续状态行、进程/命令段之前，或完整 winlog 对象中的原生字段。来源位置保留为原文容器位置及解码文本值位置，完整结构化字段则记录原文值位置。破损父对象里的候选只能否决冲突，不能向模型提供事实。正文中对应的带类型状态数值替换成 `native_code`，数值进入原 B 的状态码列一次；不新增“状态→标签”或凭据真假映射。发生未知或冲突时使用原 B 表示，这只是保守回退，不能声称原 B 信息因此都已核实。旧投影可能对应不同修复结果，按原始行保存投影映射，不假设旧投影内部一致。

如果边界仍不可靠，或语义映射需要猜测，**不执行这三次拟合**，交付覆盖缺口及失败例即可。Duo 未响应不能由 Windows 状态码补出来，必须继续分别计分。

最多 12 次主/诊断拟合；前九次是确定的单因素比较，后三次有明确前提。上一轮九个任务合计约五分钟只是历史参考，不承诺本轮相同耗时。本地顺序 CPU 优先，实际资源不足才交付单个执行包。

## 5. 验收：先守住失败切片，再看总体

所有模型输出每条 B/M/S 概率与标签、完整混淆矩阵、每类精确率/召回、Macro-F1、log loss/Brier、正常误报以及每条修复/退化记录。相同源码运行、收敛和回放是实现检查，不是质量结论。

对 P 的保留条件在训练前固定：

1. ASA 至少两折改善，合计错误少于 B 的 6,018。继续使用旧四分区，不能改分区让错误消失。
2. 已知认证退化不能被总分抵消：Duo 10 条可疑及 Windows AD 18 条原先正确的可疑不得新增回退；同时扫描所有行为族和类的小支持切片，不只维护这个名单。任何新出现的小切片整体失守均拒绝晋升。
3. ASA 未见实际输入、未见参数、未见联合值的合计错误分别不高于 B 的 1,096 / 652 / 740，逐折及正文支持同时公开。相反标签区和拟合冲突区也不得隐藏。此处是保守的本项目推进规则，不是统计上显著性或迁移保证。
4. M/S 召回下降均不超过 0.5 个百分点；新增正常误报不超过每万正常一条。满足总体容忍线不能豁免第 2、3 条。
5. 指定产品、时钟、身份包装变换保持预测；参数事实改变时允许改变分数。单纯零向量、缺省表、解析路线或产品缺失不能被宣称为行为证据。

第 2 条的“小支持”在训练前量化：扫描每个“行为路线×类别”以及“行为路线×原 B 可用性结构×类别”，样本不超过 100 行**或**正文键不超过 30 个均计入。原先至少一条判对而新模型全部判错，视为新失守；并保护原先正确的认证、WAF 可疑、有限正文切片及 18 条 Windows 已知退化记录。固定使用 B 的切片定义，不能用新表示重新分组规避检查。

认证解析修复分支的目标限定在本次可确认的原生认证范围：总错误必须下降、至少两折不变差；每个非目标“行为路线×类别”的错误总数不得增加，ASA 也不得净增加错误，仍须通过上述小切片、召回和正常误报保护。各类概率与原文证据一同解释，不能直接硬设 `failure/no_response/status_code → suspicious`。全部可提取失败记录若缺少正常反例，解析成功只能证明信息恢复，不能证明安全判定具有可迁移性。

## 6. 压力检查及明确停止规则

只有一个完整候选在上述同协议审查中成立，才允许一次旧模板/来源协议压力拟合；压力结果不得用于早停、选择 C、补词表或反复更换候选。首批 P 如通过，优先检查 P；否则只有独立认证分支满足其目标与保护条件时才考虑该分支。不得临时把两个模型按产品名拼接。

旧压力已经查看，是更难的历史回归检查，不是新盲测。Duo、WAF、原生流量及 code 13 的能力分别报告。只有同来源高分仍不能宣称可迁移。若同输入异标签仍缺上下文、某行为族仍缺正常反例，明确能力未验证；不为了结束项目而改标签、删除困难样本或制造伪独立数据。

若进入旧压力协议，保持同一配置；错误总数、ASA 总错误及各类召回不得比旧 B 更差，已知小切片中原先正确的记录不得新增退化。即使这些历史回归条件通过，也只保留候选，不等于外部迁移或比赛提交已验收。

当前授权执行以上最多 12 次主/诊断拟合，另有至多一次条件触发的历史压力拟合；不启动比赛提交或新的平台作业。

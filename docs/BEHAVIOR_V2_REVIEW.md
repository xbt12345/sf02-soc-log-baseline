# 第二版行为解析与来源留出：结果和决策

2026-09-11。**v1 两端内容核对已通过；v2 已实现并在本地执行，但没有通过检测或迁移验收。当前不采用上下文增强方案，也不把任何本轮模型作为最终参赛模型。**

后续对抗审查更正：ASA/VPC 的可疑召回归零是被全部判成恶意，不是判成正常；风险报警召回仍为 100%。当前这次三分类模型不能采用，但不能因此永久排除协议/端口。v1/v2 已退出训练主线，新的设计以 [TRAINING_PLAN.md](TRAINING_PLAN.md) 为准。

## 已完成的工作

用户回传的只读核对结果确认：v1.1 的本地/云端切分清单内容、逐行预测类别相同，三类召回和此前指标一致。比较不包含完整概率数组；原始输入没有在这次只读核对中重新计算哈希，而是核对前次训练的身份记录。环境复核已结束，见 [云端核对回传](../platform/pilot_content_verification_cloud_user.json)。

新入口 [soc_behavior_v2.py](../training/soc_behavior_v2.py) 实现 24 个行为字段和独立的 21 个上下文字段：

- 保留认证成功/失败、会话关闭、对象句柄关闭，以及口令无效、无响应、策略拒绝等原因。
- 从已明确的 Windows JSON/XML 字段提取事件语义；整体 JSON 损坏时，只读取可确认的完整字段片段，不猜脱敏前的原值。明确事件代码优先于说明文字，避免把事件里的解释性文本当成本次动作。
- 解析 ASA 拒绝流量、默认 14 字段 VPC 流日志、有限 HTTP 请求字段；业务动作和日志状态分开。端口被部分脱敏时保留未知，不把残存数字拼成一个端口。
- 仅明确的布尔 true 表示已发生的拦截/隔离动作；false 和字符串 "true" 不算肯定动作。
- 协议、服务端口类别、登录方式、HTTP 方法/状态单独作为上下文对照。产品、管线、绝对时间、身份、解析器编号、解析成功/失败都未直接进入模型。

字段语义依据：[Microsoft 4624](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4624)、[4625](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625)、[4634](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4634)、[4658](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4658)、[AWS 流日志字段](https://docs.aws.amazon.com/vpc/latest/userguide/flow-log-records.html)、[Duo 认证日志](https://duo.com/docs/adminapi#authentication-logs)。这些文档解释事件含义，不提供本赛事三分类真值。

## 切分发生了什么

继续使用 v1 固定抽样的 100,000 行；没有重新挑种子。新规范化补充了 syslog 月份/年份、部分损坏脱敏片段等处理，然后同时连接新消息组和旧消息组。一个连通分量若跨越原来的用途区域，就从本轮训练/开发比较中隔离。原始官方文件和旧清单均未改动，隔离不是删除数据。

这次发现 1,489 个跨区分量，共涉及 47,735 行。它们是**按当前保守分组规则产生的跨区关联**，不等于 47,735 条已确认重复事件；去掉所有数字也可能合并实际不同的事件。这个结果说明原先切分对规范化规则敏感，后续需要审计过度合并与遗漏，不能直接据此宣称原先存在某个比例的真实泄漏。

模型仅使用原训练/开发区中剩余的 29,253 行。原校准/评价区的消息只参与无标签的分组关联检查，其标签未参与本轮拟合、校准、早停或评分。原训练区再按组件固定哈希留出约 15% 的组作内部阈值校准，实际行数不保证 15%。

| 用途 | 正常 | 恶意 | 可疑 |
|---|---:|---:|---:|
| 拟合 | 20,876 | 87 | 365 |
| 内部阈值校准 | 4,633 | 21 | 799 |
| 开发/早停 | 2,444 | 27 | **1** |

**开发区仅有 1 条可疑，不能用其召回判断可疑检测能力。** 开发区也参与早停，指标属于开发诊断，并非未见测试。以下分数不能与 v1 原评价区的 0.595 直接比较；本轮另外重训旧表示作为相同样本条件下的对照。

## 相同数据条件下的四组比较

各组均采用固定参数的 CPU CatBoost、最多 200 棵深度 5 的树，只有输入表示和声明的权重对照不同。

| 方法 | 开发 Macro-F1 | 恶意 Recall | 可疑 Recall |
|---|---:|---:|---:|
| 旧 v1 表示重训 | 0.33184 | 0 / 27 | 0 / 1 |
| v2 行为字段 | 0.33184 | 0 / 27 | 0 / 1 |
| v2 行为字段 + 平方根权重（上限 5） | 0.33184 | 0 / 27 | 0 / 1 |
| v2 行为 + 上下文 | 0.39851 | 3 / 27 | 0 / 1 |

在同一可用样本范围，旧表示有 6 种不同向量，v2 行为有 11 种，加入上下文后有 17 种。特征变多没有自动带来可靠检测能力；行为表示仍有 24,602 / 29,253 行没有核心证据。缺少证据的行保留在指标和覆盖统计里，不从评价中删掉。

## 来源留出揭示的反例

在看分数前，根据可用样本数量确定所有至少 100 行的产品来源，共 9 组。每组完整留出，其关联的消息分量也从其他来源的拟合、校准和早停区域排除。行为方案和上下文方案各执行一次：共 16 次可执行试验、2 次因训练缺类报告不可评价。这里的“来源”是产品元数据，不是独立采集环境；缺失产品桶还混有未知来源。

| 留出来源 | 正常/恶意/可疑支持 | 行为方案可疑召回 | 加上下文后的可疑召回 |
|---|---:|---:|---:|
| ASA Firewall | 1 / 0 / 1,005 | 100% | **0%** |
| AWS VPC Security | 0 / 0 / 136 | 100% | **0%** |
| Windows Active Directory | 11,340 / 0 / 11 | 0% | 0% |

**开发分数更高的上下文方案，在两个来源留出中把全部可疑判成恶意，三分类失败。当前不采用这个已训练模型。** 原先“完全漏掉”表述混淆了类别正确性与报警：在校准预算 0.001 的风险阈值下，两版对这两来源的可疑报警召回均为 100%。本结果不能证明上下文丢失了威胁报警能力，更不能永久排除协议或端口。应在可信的新协议中分别检查语义字段与决策校准。

基础行为方案的两个 100% 也不能证明可靠：ASA 只有 1 条正常，VPC 没有正常，无法据此确认低误报的可疑检测。另有明确误报：Windows Logs 留出中，26 / 10,629 条正常被报为非正常，约每万条 24.46 次；ManageEngine ADManager 为 1 / 144，样本太少，比例不稳定。

上段误报是 argmax 三分类的统计。风险阈值需要另看：Windows Active Directory 留出在校准预算 0.001 下，两版均报警 484 / 11,340 条正常，即每万条约 426.81 次；同折 argmax 正常误报为 0。这个阈值失配是更直接的低误报失败证据，不能把两套决策的数字拼接成一个模型成绩。

在本轮可用样本中，全部 135 条恶意都来自产品字段缺失桶。留出该桶后，拟合区恶意数量变为零，两组试验都报告 `insufficient_support`。这是当前样本的来源/标签覆盖缺口，不是训练软件报错，也不支持将“缺产品”重新放回模型作为答案。

## 下一步的实际优先级

以下保留 v2 当时的建议。重新审查已决定停止继承旧角色后跨区隔离、停止用少量布尔信号作主表示；当前训练设计以唯一训练方案为准。

1. **审计分组边界后再建立完整开发集。** 检查跨区大组是否只是月份/身份变化，或因去掉事件码、端口等数字而过度合并。分别记录相同事件、相同模板、相似行为，不把它们当同一个概念。冻结明确的新分组契约后，在全量官方训练集上评估每类独立组数和用途覆盖；不靠换随机种子让少数类“刚好出现”。现有旧评价数据已见，不能重新包装为盲测。
2. **优先补同来源的类别对照。** 正常被拒绝的 ASA/VPC 流量、恶意被放行的流量、合法失败登录和有真实攻击记录的失败登录，必须有独立依据标注。重点补字段齐全的恶意和字段缺失的正常，保持输入语义和标签定义可审查。
3. **继续补真实行为字段和必要上下文。** 已明确的认证原因保留，但失败登录本身不能区分误输和攻击。只有能确认采集会话、时间可比性与关联实体时才做因果窗口；不把不同年份、不同来源日志拼成攻击链。上下文重新进入主模型，需要在完整类别支持的来源留出与固定误报成本下证明收益。
4. **用独立环境证明迁移。** 官方训练集仍足以继续开发解析与分组，但本轮证据不支持广泛迁移。外部数据用于独立评价需要明确标签映射；能否混入最终参赛训练仍以主办方规则为准。当前未下载或混入外部数据。

当前建议保留 v2 作为可复核的失败实验，不继续通过云端重复此版本来追求高分。云端环境已验证；下一项工作应针对数据可比性和分组覆盖，形成新的有信息量的实验。

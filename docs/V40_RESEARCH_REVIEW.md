# v4.0 定向复审：先消除缺省编码投票，再解决 ASA 的函数表达不足

制定阶段记录：2026-09-13。本文记录当时的官方数据诊断、一手资料与源码核查、八轮顺序反证；当时没有训练 v4.0。**后续九次主拟合现已完成，整体质量未通过，当前状态见 [V40_EXECUTION_REVIEW.md](V40_EXECUTION_REVIEW.md)。** 本文的推荐路线是训练前假设，不能当作执行成功结论；缺失零码及去副本的整套替换已被实际退化否定。已执行约定见 [V40_NEXT_PLAN.md](V40_NEXT_PLAN.md)。

当前最有依据的路线是：**观察到的事实单独编码、缺失不主动贡献类别分数、同一事实只表达一次，再用可检查的类别主效应与少量交互解决 ASA 拟合不足。** 保留已经通过的时间/包装修复，舍弃“无合格对比样本就不能检验模型容量”的限制。没有证据能在训练前断言某个开源模型是本项目的最优解。

## 1. 新增的实测证据，改变了哪些判断

### 1.1 ASA 不全是信息不足，确有尚未学好的部分

从三份冻结模型重新构造实际输入矩阵，逐折重算拟合侧同输入标签分布，再与每条折外预测对照。全部概率与保存结果的最大差异为 0。三折合计 1,378,650 行仍是已查看开发数据，不是新盲测。

ASA 的 6,018 条折外错误分成四类：

| 相对该折拟合数据的状态 | 错误数 | 可支持的处理方向 |
|---|---:|---|
| 相同输入只见过一种标签，而且与本条真实标签一致 | **1,522** | 有明确拟合/决策改善空间；先比较正则化与函数表达，不恢复身份字段 |
| 相同输入只见过另一种标签 | **921** | 存在跨正文标签关系变化；不能靠记住拟合标签解决，其中包括 code 13 的 865 行 |
| 相同输入在拟合侧已经有多种标签 | **2,479** | 保留冲突分布、分别报错；不能统称原始错标，也不能把所有错误都当不可避免 |
| 实际输入在拟合侧未出现 | **1,096** | 检验未见值、参数组合和模板迁移；不能从已见输入改善推导此项改善 |

训练本身也没有把无冲突输入学好：三折 ASA 无冲突拟合记录分别错 **1,637、1,637、1,608** 条。相应 ASA 拟合总错误为 3,267、3,370、3,437；按拟合输入计算的经验最少错误仅为 1,466、1,508、1,662。

这证明当前拟合结果没有达到其输入可区分性允许的经验水平；**尚不能单凭这点区分正则化、线性限制、跨事件任务干扰，也不能保证消除这些训练错误就改善迁移。** 因此下一轮设置一个固定的减弱正则化对照，并检验类别/交互表示。不能把经验下界当成已取得的准确率。

原端口位编码可以保存数值，但线性模型只能给每个位加权求和。完整保存数值与能方便学习“协议＋端口”的关系，是两件事。新增类别和交互不是恢复 IP、产品名或 `dmz-1/2`，也不代表某个端口本身就是攻击。

证据：[逐折完整诊断](../evidence/2026-09-13/v40_mechanisms/summary.json)、[第一折具体输入与错误](../evidence/2026-09-13/v40_mechanisms/fold_0.json)。

### 1.2 未响应并非完全没有共享证据，缺省编码正在参与判决

在旧模板/来源压力协议中，Duo 未参与拟合。8 条 `no_response denied` 已经得到 `auth_result=failure`；拟合侧另有 Windows 331 条、syslog 153 条明确认证失败，均标为可疑。它们不证明真实环境里所有认证失败都可疑，但说明“共享认证失败毫无拟合支持”并不成立。

冻结模型对这 8 条记录的三类概率为：正常 **0.57414**，恶意 **0.00264**，可疑 **0.42322**。可疑相对正常的线性分数可以精确分解为：

| 项目 | 对可疑相对正常分数的贡献 |
|---|---:|
| 截距 | −8.22108 |
| `auth_result=failure` | +4.35391 |
| `outcome=failure` | +4.35391 |
| 未观测到的端口、ICMP、HTTP、Windows 状态等有限码的缺省编码合计 | **−0.79172** |
| 合计 | **−0.30498** |

两个 `no_response` 特征在拟合侧没有出现，系数为 0。真正已有跨格式支持的父类事实，被截距与全局缺省字段共同抵消了一部分。这里是精确的模型分数分解，不是攻击原因的因果证明。

**“不适用”不应自动变成“支持正常/恶意/可疑的证据”。** 当前 `FixedFacts.raw` 为每个事件都填充所有有限码的缺省值，使认证事件连不存在的网络/Windows 字段也能投票。下一轮改为缺失中性编码：观察到的值参与分类；缺失、脱敏、解析失败等保留在质量记录中，不直接生成独立类别加分。观察到的零值仍必须与未观测值区分。

边界：这样可以移除显式缺省码的贡献，却不能数学保证模型完全不利用字段是否可用；“出现了某个有效事实”本身仍透露信息，文本也可能暴露来源形态。因此可用性对照与同条件切片仍需保留。

证据：[压力模型分数分解与拟合支持](../evidence/2026-09-13/v40_mechanisms/stress_support.json)。Duo 对 `no_response` 的定义是用户没有响应导致认证被拒绝，不是恶意意图判定，见 [Duo 官方字段说明](https://duo.com/docs/adminapi#authentication-logs)。

### 1.3 同一认证失败被重复输入，改变了正则化效果

检查压力拟合使用的全部 **68,952 个投影**，`auth_result=failure` 与 `outcome=failure` 两个布尔列完全相同，两个系数也相同。对于 L2 线性模型，一份总权重可以分摊到重复列上，降低实现相同总权重所受的惩罚。因此，重复一个特征可能改变分数，却没有增加信息。

最小修复是按明确的语义关系将同一个认证结果规范化为一个事实；不按“统计上相关”随意删除其他事实。重新训练，并用固定正则化对照区分收益来源。不要在旧模型里直接删一个等价列后声称其他条件不变。

证据：[拟合列一致性检查](../evidence/2026-09-13/v40_mechanisms/duplicate_failure_check.json)。

### 1.4 一项看似漂亮的补丁，经三分类反证失败

在**不重训**的冻结压力模型上，仅在推理输入中清零有限码的缺省贡献，得到以下诊断结果：

| 诊断干预 | 总错误 | Macro-F1 | 正常误报 | Duo 可疑正确 |
|---|---:|---:|---:|---:|
| 原模型 | 3,988 | 0.82694 | 0 | 2/10 |
| 推理时清零缺省码 | 2,238 | 0.86401 | 0 | **0/10** |

原生流量修复 1,748 条；ASA 修复 30 条、退化 26 条；Duo 两条原本正确的记录退化。十条 Duo 可疑此时全被判为恶意。未响应的可疑分数确实超过正常，但恶意分数上升得更多。**只解释“可疑与正常”一对分数，会遗漏第三类竞争。**

这个补丁按预期淘汰。它只证明输入缺省编码有实质影响，不证明新的分类器有效。必须从拟合开始使用一致的新表示，三类共同优化、完整评价。流量该格式仍没有正常反例，修复恶意召回不能验证其正常误报能力。

证据：[完整干预结果](../evidence/2026-09-13/v40_mechanisms/missing_ablation.json)。此文件明确禁止将干预当成可部署候选。

### 1.5 原配对门槛不能再充当增加表达能力的前提

逐字重放旧 `pair_support`，三折结果与原凭据一致，合格组仍为零。但门槛要求待比较字段不同，同时要求其余全文完全相同；结果词经常也出现在全文里。单纯去掉全文限制、补充路线/字段集合及派生别名控制后，三折各出现一个 Windows 结果对照单元。

这只是**宽松诊断单元**，其中正文还存在其他差别，未证明合法行为配对，不用于训练。它说明旧结论只能表述为“旧严格规则没有找到配对”，不能推出“数据里不存在可学关系”或“不能检验非线性分类器”。取消这个不适当的前置依赖，暂不做辅助对比损失。

## 2. 一手研究与开源实现，具体吸收什么

| 来源 | 经核查的方法或限制 | 对本项目的采用决定 |
|---|---|---|
| [GA²M 原论文，KDD 2013](https://www.cs.cornell.edu/~yinlou/papers/lou-kdd13.pdf) | 用单变量函数与少量双变量交互兼顾表达能力和可解释性 | 采用“主效应＋受控交互”的结构；先检验协议、端口和 ICMP 参数关系，不能把可解释等同因果正确 |
| [InterpretML / EBM 官方实现](https://github.com/interpretml/interpret/blob/develop/python/interpret-core/interpret/glassbox/_ebm/_ebm.py)与[API](https://interpret.ml/docs/python/api/ExplainableBoostingClassifier.html) | 支持指定交互、逐项贡献、以 `init_score` 接续模型；默认自动交互、分箱与内部验证并不自动符合我们的约束 | 借鉴结构和审计方法；本轮首选现有稀疏工具实现有限类别主效应/交互，不宣称复现 EBM。EBM 是后续非线性对照，不直接照用默认配置 |
| [scikit-learn 1.3.2 DictVectorizer 源码](https://github.com/scikit-learn/scikit-learn/blob/1.3.2/sklearn/feature_extraction/_dict_vectorizer.py) | 训练建立类别词表，变换时忽略未见项 | 可用于稀疏类别/交互项；必须保留观察值的固定编码作为回退，防止所有未见端口重新合并为同一输入。不用有碰撞的特征哈希代替精确参数 |
| [scikit-learn 1.3.2 HistGradientBoostingClassifier](https://scikit-learn.org/1.3/modules/generated/sklearn.ensemble.HistGradientBoostingClassifier.html)及其源码 | 可限制交互；类别数受 `max_bins≤255` 限制；默认早停可能内部随机分行；缺失值的分支本身可以被学习 | 不把 65,536 个端口直接送入默认类别分箱；不把“支持 NaN”误当“不会利用缺失捷径”。首轮无需为这个对照稠密化全部日志 |
| [Grinsztajn 等，NeurIPS 2022](https://arxiv.org/abs/2207.08815) | 在所研究的表格基准中，树模型的归纳偏好常有优势；结论有数据规模和任务范围 | 支持认真检查结构化参数的模型归纳偏好，不支持断言树、TabPFN 或大模型在本 SOC 数据上必胜 |
| [Selective Classification，NeurIPS 2017](https://arxiv.org/abs/1705.08500)；[MAPIE 的交换性说明](https://mapie.readthedocs.io/en/stable/content/exchangeability-testing/) | 拒判需一起报告风险与覆盖；分布变化会破坏统计保证的前提 | 仅增加证据不足的诊断标记，正式三类仍完整评分。当前不做“高置信就是可信”或“套共形预测便能保证跨域准确”的承诺 |
| [Dos and Don'ts of ML in Computer Security，USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/arp) | 安全任务中的数据偏差、标签、虚假关联和评价陷阱必须一起检查 | 保留已查看数据声明、原行完整指标、模板/来源压力测试；不靠某个总分晋级 |

本次实际获取两个项目的八份源码/许可证文件，只阅读、未安装或执行。Git 连接和提交 API 解析失败，已保留失败；文件从标签/分支原始地址获取并记录 SHA-256，**没有冒称取得固定提交身份**。PyPI 元数据也不足以证明旧平台 Python 3.8 的 EBM 导入兼容性。凭据与实际文件见[来源记录](../evidence/2026-09-13/v40_methods/source_receipts.json)。

选择首轮稀疏主效应/交互实现，是因为目标参数是有限类别，现有工具足以检验关键假设；不是认定线性软件包永远优于树。新增的类别查表函数和字段交互，相对原始参数已经是非线性表达。若这一轮仍有大面积无冲突拟合不足，再进行真正的浅层 boosting 对照，不让配对门槛阻止它。

## 3. 哪些问题可以继续优化，哪些不能宣称解决

- **ASA 的 1,522 条已见一致输入错误：**优先解决编码几何、正则化和交互；以其余三类 ASA 错误是否退化作为反证。修复这批不等于修复全部 6,018 条。
- **code 13 两正文、其他同输入标签冲突：**保留原标签与全部评价，只用拟合侧建立支持/冲突记录。恢复资产编号能拟合身份关系，但缺少资产语义，继续禁止。多个折模型对同输入的不同判决不等于单模型有了新信息。
- **Duo 未响应：**使用已有明确认证结果进行共享，零响应的未知细节继续未知。不得硬写 `no_response→suspicious`；重新训练缺失中性且去语义副本的三分类器，来源留出仍只在最终检查时运行。
- **原生流量：**缺省干预证实模型决策受这些码影响；同时该格式缺正常反例。可以检查外推和编码修复，不能宣称已学会在同格式正常与恶意间区分。不给其他来源正常日志伪造一个流量外壳来充当真实反例。
- **WAF 唯一可疑正文、有限命令正文：**先检查真实原文是否有尚未提取的有效行为，修复解析只依据字段定义；缺失内容不能猜。WAF 只有一份独立正文的可疑支持，重复、增强、伪标签都不能生成独立验证。
- **缺产品名与时间干扰：**保持产品名不进入预测、从正文识别格式；继续真实包装/时间替换回归。不能把已经通过的指定变换检查升级为所有环境的独立性证明。

官方数据足以进行这轮针对性实验；它不足以证明上述缺反例或缺上下文的能力。按用户约定，本轮不找额外数据。已明确缺失的能力继续记录为未验证，不用无限重跑掩盖。

## 4. 八轮实际顺序反证

以下是同一执行者的顺序审查，不是八位独立评审，也不是八轮训练。

| 轮次 | 挑战的问题与证据 | 对方案的实际修订 |
|---|---|---|
| 1 | ASA 错误是否全不可恢复？1,522 条折外错误在拟合侧已有一致正确标签，每折另有约 1,600 条无冲突拟合错误 | 将表达/正则化诊断列为必做，不再只改语义名称 |
| 2 | 保留全部位是否代表模型能用好？位相加不能自由表达端口类别与协议条件关系 | 增加精确类别主效应和有限交互，固定观察值回退，禁止哈希碰撞 |
| 3 | 未响应是否完全没证据？共享失败在拟合侧有 484 条，缺省码贡献 −0.79172 | 优先改缺省投票结构；保留未知交互细节，不造新标签 |
| 4 | 父类语义是否增加了两份独立证据？68,952 个拟合投影中两个失败列完全相同 | 同事实规范化，保留正则化对照，不用重复列涨分证明语义能力 |
| 5 | 清掉缺省码后总分更好，可以上线吗？错误减少 1,750，但 Duo 从 2/10 退化到 0/10 | 淘汰推理补丁；改为一致表示下重训并检查三类竞争 |
| 6 | 配对零支持是否阻止所有其他方法？放宽全文匹配后有一个诊断单元，但没有因果可比保证 | 暂停对比损失；解除其对模型容量实验的前置依赖 |
| 7 | 直接用先进库默认参数即可？发现未见类别忽略、分箱、NaN 分支、内部随机验证等限制 | 保留固定回退与分组验证；首轮用现有稀疏实现，不把默认树配置当捷径消除器 |
| 8 | 加可信度阈值能补足迁移吗？压力错误中 **2,528/3,988** 条原始最大概率已大于 0.95 | 证据不足标记独立于概率阈值；不删难例、不加比赛第四类、不声称跨分布保证 |

本次诊断和方案文件的绑定核查见[验证记录](../evidence/2026-09-13/v40_methods/verification.json)。检查通过只支持所列重放和文件一致性，新的分类性能仍须下一轮真实训练验证。

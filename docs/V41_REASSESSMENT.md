# v4.1 规划前复审：把编码、惩罚强度和行为证据分开

2026-09-13。**本次完成只读模型诊断、原文核查与下一步方案；没有训练新分类器。** 上一轮实际结果仍以 [v4.0 执行报告](V40_EXECUTION_REVIEW.md)为准。当前不晋升 N/I，不恢复时间或产品字段，不增加训练数据。

结论：之前的偏差主要在实验设计和问题归因。我们同时改变了有限值编码、重复事实和参数表达，使“缺失处理”“正则化变化”“表达能力增强”混在一起；又低估了尾部事实解析不足和标签支持单一的问题。不能由本轮失败推出全部特征都有害，也不能把原基准的正确答案当作真实迁移能力。

## 1. 第一性原理：先确定什么可以被学到

模型只能利用实际观测区分标签。如果两条记录在模型中成为同一个输入，确定性分类器就只能给出同一个答案；没有新可用信息，扩大模型无法同时满足相反标签。反过来，有效事实仍在却被错误分类，则要检查提取、表达和训练目标，而不是直接判定信息不足。

应让真实认证结果、协议参数、有效状态变化影响模型；产品名、绝对时钟和字面身份的变化不应在行为不变时改变判断。目标不是“任何字段都不能影响模型”，也不是“消除所有缺失信息”，而是让能力来自任务相关证据，并在不利切片上证明其适用范围。

本轮指定时间/产品变换与保存模型回放通过，没有证据将新增退化直接归因于这些已测字段。未见环境仍未验证，这两件事须分开。

## 2. 新确认的问题一：直接删重复列，会改变正则化

位置：[v40_core.py 的 canonicalize](../training/v40_core.py)在 `auth_result` 与 `outcome` 相等时删除后者；N 同时做有限码替换。这个操作语义上去副本，却不是训练目标不变的整理。

设两个完全相同的输入列都是 x，系数 u、v 的总作用为 `(u+v)x`。若总作用固定为 w，L2 惩罚在 `u=v=w/2` 时最小，为 `w²/2`；直接删成一列 x 后，同样作用需要系数 w，惩罚变成 `w²`。因此保持相同 C，等于对该方向施加两倍的有效惩罚。这里省略两种目标共同的常数。这是从当前 L2 目标推导的结论，目标函数可核对 [scikit-learn 官方文档](https://scikit-learn.org/stable/modules/linear_model.html#multinomial-case)；不能推广到所有损失和惩罚。

**本次真实检查了全部 79,900 个允许开发投影及三折拟合/评价记录：**

| 事实列对 | 三折拟合及评价中的不一致行数 | 旧模型两列系数差 |
|---|---:|---:|
| outcome=failure / auth_result=failure | 0 | 0 |
| outcome=success / auth_result=success | 0 | 0 |
| response=missing / authentication_interaction=no_response | 0 | 0 |

将每对压成一列 `sqrt(2) × x`，系数变为 `(u+v)/sqrt(2)`，三折旧模型的最大分数差不超过 **5.56×10⁻¹⁷**，相应 L2 平方和也保持到浮点误差。没有重新拟合，也没有导出替代部署模型。证据见 [diagnosis.json](../evidence/2026-09-13/v41_planning/diagnosis.json)。

这给出更准确的结论：**去副本不必然损失已有效果；不保持尺度的去副本改变了训练偏好。** 但它仍不能单独证明这是 N 退化的全部原因。当前数据上相同，也不等于未知环境中所有同名字段永远等价；通用操作失败与认证失败若分离，不能强制合并。

## 3. 新确认的问题二：“只改缺失”实际上改了所有合法值

N 将有限值 n 的位编码换为 n+1，再把缺失设为零。穷举结果：**65,536 个合法端口全部改变位表示，其中 32,768 个改变不止一位，最大改变 17 位。** 这保留数值可区分性，却改变线性模型的函数表达和惩罚几何。

因此，N 失败不能归结为“缺失信息很重要，所以必须保留缺失捷径”；N 成功也不能被命名为“缺失捷径已消除”。合适的做法是把有限码转换单独做对照，并持续承认零向量仍能暴露缺失。不要再把所有数值字段一并换码后，用一个总指标解释多个机制。特征尺度影响正则化的实例可参阅 [scikit-learn 官方示例](https://scikit-learn.org/1.5/auto_examples/preprocessing/plot_scaling_importance.html)，它支持检查尺度，不代表本项目应该直接全量标准化。

## 4. 新确认的问题三：Windows 退化包含具体事实提取缺口

针对额外退化的 18 条 Windows AD 可疑记录，已重新读取官方原文字节并复现旧解析结果：**18 条都含 Status/SubStatus 状态码候选，结构化事实中的提取数为 0**；规范化正文仍保留 `0xc000006d` / `0xc0000064`。其中 5 条在拟合侧已有同输入同标签支持，13 条为未见实际输入。

原文同时存在转义的渲染文本和受脱敏影响的嵌套字段；本次逐条核查的两处 Status/SubStatus 值全部一致。仅按普通空白匹配会漏掉字面 `\\t`；不限定字段起点也可能将 Sub Status 误认作 Status；仅认未脱敏的父字段名则可能漏掉仍完整的状态字段。旧解析器已能从部分原生字段建立状态事实，但没有覆盖这批载体。证据见 [原文探针记录](../evidence/2026-09-13/v41_planning/native_status_probe.json)。探针只查明值和位置，没有证明通用生产解析边界已经实现。

这些是认证诊断事实，不是事件身份。Microsoft 将 Status/SubStatus 定义为登录失败原因和进一步说明；`0xC0000064` 涉及错误账户，连续出现时才可能支持账户枚举等调查。**不能硬写“该码必为可疑/恶意”。** [Microsoft 4625 官方说明](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625)

最小修复方向是从已定位的原生认证区域提取状态、保留原文位置，并检查渲染文本与原生键冲突。遇到脱敏破坏或相互矛盾时保留未知和诊断，不猜值，不从全日志任意 `Status` 字样取数。还要用相同状态字符串位于引用内容、其他业务对象中的反例验证不会误触发。

## 5. 更深的数据限制：正确识别这批，也未必学会现实中的认证威胁

在允许开发池内，当前解析出的 `auth_result=failure` 共 **563 行，全部标签为 suspicious**；`auth_result=success` 共 **94,900 行，全部为 benign**。这些数由三折拟合支持重新汇总，非对所有真实认证事件的完备识别。

这说明训练器很容易形成“失败即可疑、成功即正常”的关系，却缺少该事实表示中的正常失败、恶意失败或其他反例支持。Duo 的 10 行可疑只有 9 个正文，未响应 8 行在每折拟合侧仅有 5、5、6 行。恢复这十条的正确率只能证明消除了已知回退，不能证明跨组织风险判断。

ASA 的 I 模型修复了 612 条“同输入一致标签”错误，却在“同输入相反标签”上新增 90 条；未见参数新增 12 条错误只集中在两个投影，不能当成 12 个独立场景。参数类别表能记住已见关系，无法自动获得未知参数或缺失上下文的正确含义。code 13 的 865 行仍全部错，不应再靠位数或查表项数量处理。

官方数据继续用于实验；缺少反例的能力保持未验证。不能自动改标签、凭时间串起未经确认的攻击链，或用复制/伪造日志制造独立证据。

## 6. 借鉴什么，暂不采用什么

本轮采用的是“检查目标函数、控制改动、按失败条件验证”的方法，不是寻找一个名气更大的模型替换。参数主效应/交互仍值得保留，因为 I 相对 N 的 ASA 错误净减 513，三折均改善；全局 N/I 替换继续淘汰。

DFR 等研究提示应区分“特征里有没有有效信息”和“最后决策层如何使用它”，但其方法依赖用于再训练的反相关/平衡支持；当前不能用这几十条已查看尾部样本拼一个所谓独立去偏集。研究的基准成功不等于我们的三分类数据适用。参考 [DFR 原论文](https://arxiv.org/abs/2204.02937)及 [作者项目](https://github.com/PolinaKirichenko/deep_feature_reweighting)。本轮只核查论文与项目说明，不安装或执行其重加权训练。

安全机器学习对数据偏差、实现与评价解释均需核查，不能只看排行榜总分，这与本次拆开指标和原文证据的做法一致。[USENIX Security 2022 原论文介绍](https://www.usenix.org/conference/usenixsecurity22/presentation/arp)

| 反证 | 新证据或推导 | 方案变化 |

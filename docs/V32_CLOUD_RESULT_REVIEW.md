## 3. 已观察到的三个主要问题

### P1：全局低误报掩盖来源局部失败

位置：返回每折 `report.json` 的 `risk_thresholds`，以及本次补算的 `risk.by_product`。原配置选择的是全局正常样本的分位数阈值，没有来源条件的误报合格判定。

在预设全局预算 FPR=0.001（每万正常 10 次）下，外折实际情况为：

| 范围 | 正常报警数/正常总数 | 实际正常误报率 |
|---|---:|---:|
| 全部正常 | 1,960/1,899,723 | 每万 10.317 次 |
| 非空正常 | 1,960/1,543,408 | 每万 12.699 次 |
| Duo | 223/325 | **68.62%** |
| Barracuda WAF | 1,236/4,128 | **29.94%** |
| ASA Firewall 产品桶 | 18/20 | **90.00%** |
| ManageEngine ADManager | 170/4,082 | **4.16%** |

正常样本组成发生变化时，报警负担会大幅改变。较严格的 0.0001 预算也未消除此问题：Duo 为 108/325，ASA Firewall 为 16/20；不能只选一个更低预算就宣告解决。

ASA Firewall 产品桶只有 20 条正常、10 个非空组，不能据此估计稳定的低误报率。这些正常记录也不在 `asa_like` 格式中；`asa_like` 本身没有正常反例。产品桶与格式不能互换。产品名只用于这次诊断，不能作为类别覆盖规则。

最小改进：对既有校准预测按可核实来源/格式列出正常支持、分数组成、可疑/恶意支持；来源条件阈值只能由该轮校准部分确定，不能从这些外折错误倒推阈值。支持不足的来源明确为未验证，进入人工复核或受限适用范围，不许用空正常或多数来源掩盖。全局和分来源表现同时验收；模型与校准数据一变就重新选择阈值。本次没有修改任何报警阈值。

### P1：动作正文不变，采集头变化仍改变分类

位置：ASA 准备文本的 `time: entity`、`time entity time: entity` 等前缀；返回系数中可见 `time time`、`entity time` 等高权重项。单看系数只是关联，因此本次实际进行了输入干预。

覆盖全部 **112,807 条 ASA、17,892 个规范化组**。保持从 `deny` 开始的正文逐字不变，只把前面的头部换成官方数据中已经观察到的四种表示。没有改变动作、协议、地址关系、端口、接口或 ACL 正文。下表的正确/错误沿用原记录标签作对照，不是另行取得的新环境真值。

| 统一后的日志头 | 真正改变头部的行数 | 分类翻转 | 原本正确变错误 | 原本错误变正确 |
|---|---:|---:|---:|---:|
| `time: entity ` | 105,665 | **3,894** | **2,616** | 1,278 |
| `time entity time: entity ` | 7,824 | 1,162 | 1,100 | 62 |
| `time entity entity: entity ` | 112,129 | 2,418 | 1,578 | 840 |
| `time entity: entity ` | 112,803 | 2,938 | 1,904 | 1,034 |

这是固定模型对包装信息存在实际依赖的证据；它不是新环境准确率估计，也不能证明全部域内收益都是伪收益。[反例脚本](../training/audit_v32_asa_headers.py)；[逐项结果与示例](../evidence/2026-09-12/v32_asa_header_sensitivity.json)。

最小修复应是按 ASA 字段边界统一或移除采集头，再重新拟合；不能在当前模型前简单删头后沿用原成绩，也不能全局删除 `time`、`entity` 等词而误伤正文。

**这一修改会影响分组，不能复用原划分。** 只按 ASA 动作正文重新计数，组数从 17,892 降到 17,609，其中 270 个正文组会合并旧组；183 个正文组跨当前外折，共涉及 **14,255 行**。若清洗后仍沿用旧折，就会重新出现同文跨拟合/评价区。混合标签正文组增至 75 组、4,075 行；观察到的固定正文表示最少错误数为 1,116。这是该表示在已见数据上的计数，不是模型或真实任务的误差下界。保留原标签，不用多数投票消除冲突。[重新归组影响](../evidence/2026-09-12/v32_asa_header_regroup_impact.json)。

### P2：稀少来源的分类与报警能力不能混为一谈

| 来源/格式 | 三分类目标类召回 | 全局预算 0.001 时的报警召回 | 支持边界 |
|---|---:|---:|---|
| Windows Active Directory 可疑 | 263/473，55.60% | 473/473，100% | 可疑 339 个非空组；无恶意支持 |
| Falcon 可疑 | 9/35，25.71% | 25/35，71.43% | 可疑 25 组，没有正常反例 |
| Duo 可疑 | 0/12 | 10/12，83.33% | 可疑 12 组；此阈值正常误报 68.62% |

因此，不能把 Windows 的三分类漏判都说成威胁没有报警，也不能拿高报警召回掩盖严重误报。下一轮应审查这些行的可见动作、上游信息边界及标签定义，而不是直接重采样几条记录、调大类别权重或换大模型。

## 4. 压力测试和零向量究竟证明什么

三个模型的 11 对 Falcon 上游字段变化样例均保持表示和分数不变。本地重放与返回分数在数值容差内一致。五对语义差异样例在三折中都保留不同向量，没有出现已列样例在向量化后合并。

但这五对只是 `value 0/1`、事件码、否定和命令符号等短构造，缺少可信攻击标签；它们均判正常不能单独算作错误，也不能证明模型理解了真实攻击。现有测试集遗漏了已经观察到的 ASA 采集头问题。应增加此次完整日志反例，不应要求每种语义变化都必须翻转类别。

全量零向量恰为 **356,315 条原始空消息**，非空零向量为 **0**。当前没有证据把主要失败归因于整条日志完全未见词；不能据此直接启动字符分支。部分词、组合关系和精确向量碰撞仍可能丢信息，需要按实际错误检查。

3. **仍用 N＋词文本模型完成最小对照。** 继续官方数据、每行等权、原定两个 C；不同时加字符、结构或大模型。新一轮 N 与 C1 必须同清单比较。若需要量化“清洗本身的增益”，旧/新表示须在同一新清单重新拟合；否则不把两轮总分差归因于清洗。
4. **先诊断校准支持，再测来源外推。** 根据校准部分的来源支持设计候选阈值并冻结，在外层报告总体及分来源误报/召回。稀少来源支持不足是结论边界，不是通过条件。此后优先对主要收益所在的 ASA 模板族及有正常/异常反例的来源做完整重训留出；词表、选参、拟合、阈值全部排除留出侧。

通过条件是：修复后的表示与冻结模型在可信头部变换下保持不变；不存在清洗后同文跨角色；在新同协议对照中仍有可解释的正文收益；报警结果不再用全局平均掩盖局部失败。不能预先承诺维持 0.9778，也不把降低开发分数自动当退步。

**官方数据目前足以开展上述修复、开发比较和内部留出，但不足以证明任意新环境的准确率。** 按用户要求，本阶段不寻找外部训练数据。现有数据中缺少的同来源正常/恶意反例不能靠复制样本补足；未来是否补数据取决于要覆盖的真实部署来源与剩余证据缺口。

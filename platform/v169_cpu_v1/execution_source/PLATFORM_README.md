# V169 Linux aarch64 CPU 离线执行包

这是待平台实际执行的包。最新实际训练仍为 V164，最新完整质量交付仍为 V159；三个目标均未通过。包内原 README 和 Windows/CUDA 封存属于保留的历史快照。

解压到平台有足够磁盘空间的位置，执行：

```bash
python3 -m zipfile -e SF02_V169_CPU_platform_v1.zip .
nohup python3 SF02/run_platform.py > sf02_v169_console.log 2>&1 &
```

系统需要 Linux aarch64、glibc 至少 2.28、可用 Python 3.8 或更高。包内私有 Python 3.12.14 和 26 个固定 wheel 离线安装，不修改平台已有环境。CPU 使用 4 个 Torch 线程和 24 个 BLAS 线程；实际 CPU affinity、cgroup 配额、内存和磁盘会检查。

安装完成后，实际有效可用内存须至少 8 GiB；磁盘须同时保留整轮结果、完整回传 ZIP 和 2 GiB 固定余量。启动器另计解压及安装空间。资格检查包括完整参数的 float64 CSR 前后向及重复梯度、两臂完整 64 函数 rank66 QP、三角色保存数据的完整旧能力保护。资格失败停止正式调用；资格通过后重新封存实际平台源码、数据和库，再执行原有三角色双臂有界训练。

真实 V164 零步验证在每次注册 fit 的 point0 中计入预算；预算、参数维数、目标、保护、固定 20 次接受更新及配对判据保持原科学方案。CPU 数值可能无法通过原严格容差，失败会保留证据并停止，不放宽门槛。

用 `tail -f sf02_v169_console.log` 查看阶段提示，详细日志位于 `SF02/platform_run_v1/`。运行正常返回、失败或可捕获中断后，会在 SF02 的上级目录生成两个 ZIP：优先回传 `SF02_V169_CPU_review_v1.zip`，其中包含源码、绑定、原始调用日志、完整终点逐行预测、最后提交的模型及最近五个接受状态的逐行证据；完整的 `SF02_V169_CPU_result_v1.zip` 留在平台按需取证，保留全部本次输出、资格、所有接受模型、梯度、中间结果和原始异常。紧凑包省略部分梯度及中间模型，不能单独证明全部训练过程。两个包都以原执行包和精确哈希引用旧的大型输入，平台原件不会删除。归档失败时保留整个 SF02 目录和原始日志；强制关机或 SIGKILL 无法保证 finally 执行。

禁止在同目录自动重试、覆写结果或续跑失败拟合。退出码 0 仅表示有界入口返回，分类质量须独立审核完整逐行结果，模型不会自动晋升。
